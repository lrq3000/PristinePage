# Optional model providers: contracts, assets and release gates

Specification version 1.0; authored 2026-11-14. Implements the specification boundary for FR-07, NFR-02/NFR-06/NFR-07 and T-08; no model integration is implemented by this document. [PIPELINE_CONTRACTS.md](PIPELINE_CONTRACTS.md) owns shared types, stage order, masks, OutputSpec and failures. [GEOMETRY_ALGORITHMS.md](GEOMETRY_ALGORITHMS.md) owns complete coordinate/topology/resampling mathematics. [PHOTOMETRIC_ALGORITHMS.md](PHOTOMETRIC_ALGORITHMS.md) owns final candidate quantization and the single strength/protection blend.

**Release starting state: no installed models, no model-dependent blocking path.** Capture/import, manual crop/curve correction, model-free enhancement, persistence and export must function offline without an inference runtime or checkpoint. Optional providers appear only with truthful availability explanations; a disabled card must not execute a classical method under a neural label.

## 2. Three roles, not one generic tensor callback

`DetectionProvider` returns the shared `DetectionProposal(quad,score,detected,reason)` in **oriented-source pixel-center coordinates**. It proposes geometry and never overwrites accepted user corners. `detected=false` with a full-frame suggestion remains a fallback, not successful detection. A score is an uncalibrated ranking/rejection signal, not a posterior probability.

`GeometryProvider` returns a typed inverse map or a completed rectified image. The map descriptor includes source identity, source/crop origin and size, destination target, axis layout, normalization, grid interpolation, source sampler, outside border, and integrated operations. Only a map/paired transform supports applying identical geometry to a protection mask. An already rectified image is not an illumination field and is never externally warped again.

`AppearanceProvider` returns either `RestoredImageCandidate` or `IlluminationFieldCandidate`, never an untyped three-channel array. An illumination field is defined in its input-image coordinates with explicit channel order, encoding, floor/composition and sampling rules; its adapter composes the final RGB candidate. An absolute restored image replaces the appearance candidate; it is not added to the original as a residual. The adapter then performs the common strength/protection blend once. Tensor dimensions alone cannot prove any of these semantics.

Suggested internal sealed payloads are `InverseGrid2D`, `RectifiedImage`, `RgbDivisorField` and `RestoredRgbImage`. Their descriptors are strongly typed and versioned; they are not additional public RenderResult variants. The stage adapter consumes them and records ProviderIdentity in StageRecord. Keep these types separate from the recipe: a recipe requests a provider/profile; an execution result reports the payload and stages actually used.

`GeometryRecipe.outputQuarterTurns` is a clockwise output-domain operation, not another EXIF/source transform. Map providers infer their base map from the accepted, unrotated source/crop; the renderer maps final normalized centers to base coordinates with q0:(u,v),q1:(v,1−u),q2:(1−u,1−v),q3:(1−v,u), then samples that base map and source/mask once. Do not transpose neural grid axes or rotate model input to implement this control. Appearance providers receive the already post-rotation OutputSpec raster and must not rotate it again. An opaque image-output geometry profile needs a verified integrated output-rotation/sizing contract; otherwise reject unsupported turns rather than invent a second interpolating rotation. User turns change recipe/render identity, never sourcePixelHash, original bytes or source-space controls/masks.

### 2.1 Source-reference and product-adaptation identities

Use distinct IDs for a pinned public numerical reference and a product adaptation. Reference harness profiles preserve source precision, channel order, padding, interpolation and byte casts, even where those differ from the product. They are test-only and do not accept product strength/protection controls. Product profiles obey the shared byte conversion and stage blend, and document every deviation. Never present adapted bytes as exact upstream reproduction.

Planned profile IDs: `gcdr_gc_source_v1`, `gcdr_gcdr_source_v1`, `gcdr_gc_mobile_v1`, `gcdr_gcdr_product_v1`; `docres_appearance_source_v1`, `docres_deshadow_source_v1`, `docres_appearance_product_v1`, `docres_deshadow_product_v1`; `uvdoc_grid_source_v1`, `uvdoc_grid_white_v1`; `paddle_uvdoc_image_source_v1`; `syntheticdoc_coarse_geometry_source_v1`, `syntheticdoc_coarse_geometry_white_v1`; `docquad_source_v1`, `docquad_heatmap_minimal_v1`; and `fsenet_release_product_v1`. These are specified identities, not assertions that any asset is installed, exported or supported. The minimal DocQuad product decoder is independently defined in the geometry document and is not the full upstream candidate pipeline.

There is no universal 512/1024/1600 export cap. `OutputSpec.size` and purpose remain explicit. A model's working tensor size is internal to its profile, not the export size. Map providers render the source directly at the requested admitted size. Image-output profiles either support that size with an explicit reconstruction contract or reject it; they do not silently upscale a tiny restored raster and call it source-resolution recovery.

## 3. Provider manifest and registry

The following schema is normative metadata, not a populated release allowlist. A provider descriptor can exist with absent assets and unresolved rights. A releaseable installed profile cannot contain unresolved dimensions, null checksums, unreviewed licenses or wildcard runtime versions.

```text
ProviderManifestV1 {
  schemaVersion: 1
  providerId: stable lowercase identifier
  contractVersion: positive integer
  role: DETECTION | GEOMETRY_MAP | GEOMETRY_IMAGE | APPEARANCE_FIELD | APPEARANCE_IMAGE
  variantId: exact source/product profile identifier
  profileSha256: hash of canonical effective profile including host preprocessing
  source: { repositoryUrl, commit, entrypointPaths[], snapshotDate, sourceLicenseSpdx,
            sourceLicenseUrl, notices[], architectureRevision }
  assets[]: { assetId, localRelativePath, format: ORT | ONNX | TFLITE,
              byteLength, sha256, originalCheckpointSha256?, exportRecipeSha256?,
              announcedUrl, availabilityEvidence, retrievalVerifiedOn,
              weightLicenseSpdx, weightLicenseUrl, scopeEvidence, redistributionApproved }
  provenance: { trainingDataStatements[], datasetLicenseEvidence[], sampleRightsEvidence[],
                exportToolVersions, opset, graphSha256 }
  tensors: { inputs[], outputs[] }       # names, dtype, layout, channel order, shapes/ranges
  conversion: { inputColor, normalization, resize, padding, outputSemantics,
                fieldComposition, cropRestoration, byteConversionVersion }
  geometry: { sourceSpace, cropContract, mapAxes, normalizedCoordinates,
              gridResize, sourceSampler, outsideBorder, outputAspectPolicy }?
  capabilities: { minApi, abis[], dimensionRules, supportedPurposes[],
                  protectionMask: NONE | POST_APPEARANCE_BLEND | PAIRED_GEOMETRY,
                  integratedStages[], externalFinishingPolicy }
  runtime: { name, version, precision, executionProviders[], allowedCpuPartitions,
             threadOwner, intraOpThreads, interOpThreads, maxConcurrentRuns }
  resources: { assetBytes, residentWeightsBytes, inputOutputBytesFormula,
               workspaceBoundOrMeasurement, measuredPeakEvidence[], admissionPolicyId }
  gates: { rights, integrity, sourceParity, exportCpuParity, delegateParity,
           geometryValidity, fidelity, deviceFit, offline, releaseApproval }
  validationEvidence[]: { gateId, exactArtifactHashes, environment, fixtures,
                         tolerances, result, recordedOn, evidenceLocation }
  installed: boolean
  selectableState: GATED | INSTALLED_UNVERIFIED | VALIDATED_CPU | VALIDATED_OPTIMIZED | RELEASE_APPROVED
  disabledReasonCodes[]
}
```

Input/output entries specify every tensor axis, batch1 constraint, exact or permitted dimensions, finite range, and whether an output is logit, probability, absolute image, divisor or normalized coordinate. `dimensionRules` is a typed set of rules, such as fixed H/W or required multiple32, not executable text or a user script. A manifest may not authorize arbitrary file paths or preprocessing code. SHA-256 values are lowercase64hex; only the absent-asset/GATED descriptor may leave asset hash/length unresolved. Imported manifests are data, not trusted programs.

For a publisher-supplied inference asset such as DocQuad, the locally verified publisher artifact is the numerical oracle; an unavailable earlier training checkpoint/export recipe is recorded as unknown, not fabricated and not automatically required for using that unmodified artifact. A local conversion/pruning/quantization task, by contrast, must identify the exact source artifact/checkpoint and conversion recipe. Optional checkpoint/export fields express that distinction, not a waiver of the installed inference-asset checksum or its own source-wrapper parity gate.

Recipe selection uses `ProviderAppearanceV1` from the photometric document or the domain-defined provider-backed GeometryRecipe variant, binding providerId/contractVersion/variantId/profileSha256/asset identity. No runtime provider detection by filename, model family name, tensor count or guessed channel order is allowed. Freeze effective profile parameters when saving a recipe; replacing an asset changes ProviderIdentity and cache keys, not an existing revision silently.

Registry status is derived from separate gates, not a boolean `available=true`. Suggested reason codes: `ASSET_ABSENT`, `WEIGHT_TERMS_UNVERIFIED`, `REDISTRIBUTION_NOT_APPROVED`, `HASH_MISMATCH`, `GRAPH_CONTRACT_UNVERIFIED`, `UNSUPPORTED_RUNTIME`, `UNSUPPORTED_DIMENSIONS`, `MASK_UNSUPPORTED`, `CPU_PARITY_UNVERIFIED`, `DEVICE_LIMIT`, `QUALITY_NOT_ACCEPTED`. Display these plainly. User possession of a file does not prove distribution rights or safe output.

### 3.1 Offline loading, lifecycle and threads

1. Preflight the complete recipe and installed profile before decode/inference allocation: source identity, OutputSpec, masks, stage compatibility, asset integrity, ABI/minAPI, declared runtime/precision, tensor dimensions and a checked memory admission estimate. API26/arm64 is the product baseline, not evidence that a particular runtime/delegate works.
2. Load only app-owned, hash-verified allowlisted inference-format files. Resolve local paths beneath the approved model directory; reject traversal/symlinks escaping it, unexpected external tensor files, size mismatch and zip/archive bombs. Do not deserialize PyTorch pickle checkpoints on Android. Conversion is a separately approved development operation on trusted inputs.
3. Loading must never fetch a URL, query a hub, request credentials or transmit a page. Retrieval URLs in metadata are attribution/acquisition leads, not automatic network actions. Missing files return UNAVAILABLE. Bundling a future optional asset requires an explicit release decision and does not change the no-model default requirement.
4. Run preprocessing, session creation, inference and output copying off the UI thread. Initially serialize expensive neural runs through one application-owned admission semaphore. Each session has an explicit owner/close lifecycle; retain no native tensor after its lease closes. CPU thread counts are profile-pinned; 1–2 threads are evaluation starting points, not universally optimal values.
5. Use bounded cache/lease ownership for loaded weights. Dispose session/tensors when retiring a provider or responding to memory pressure, only after active leases end. Admission includes resident sessions and copies, not just the input tensor. Avoid installing two runtimes before an actually selected profile needs them.
6. Check cancellation before/after load, prompts, inference, reconstruction and in long host loops. A noninterruptible native call may finish, but its stale output is discarded using generation/revision. Release buffers; never publish a partial image. Cancellation is not provider failure and never triggers fallback.
7. Record exact runtime/execution-provider partitions and precision. Runtime CPU partitioning under a delegate is allowed only when the profile explicitly permits it and its memory/latency are measured. It is not the same as algorithm fallback and must not be hidden. A delegate failure cannot silently create a new unverified CPU/precision combination.
8. Close output handles even on invalid shapes or nonfinite results. Hash/load/runtime/shape failures disable the affected asset with a reason until revalidated. Do not retry inference recursively or loop through every neural option. No pixels, document names, local URIs or private source paths enter ordinary logs.

Shared stage failure policy remains authoritative: FAIL by default. KEEP_STAGE_INPUT returns DEGRADED, retains the failed stage's **complete input**, records the failure and terminates the remaining graph. An appearance failure after geometry keeps that rectified page. Dewarp failure keeps the accepted rough crop; it is not relabeled as successful flattening. Invalid input, resource rejection, cancellation and storage/source failures do not invoke algorithm fallback. Export requires explicit acceptance of a degraded execution snapshot.

## 4. GCDRNet: GC field is not full GC+DR

Pinned implementation: `415c97a9a64d0a796dbbad43485ce2ab102f2a7d`; decisive source `infer.py` lines19–46, model active forward methods, and `stride_integral` [M2]. The publisher abstract supports a cascaded global-context/detail-restoration architecture; the full publisher method was unavailable. Exact runnable semantics below are code-derived, not extrapolated from the paper title.

### 4.1 Source numerical reference

- Start from oriented RGB8 and explicitly swap to OpenCV BGR. Pad **top and left** to stride32 using replication: `pt=(32−H%32)%32`, `pl=(32−W%32)%32`, bottom/right0. Keep pt/pl for every crop. Normalize BGR bytes /255 to NCHW float32 batch1. The source wrapper calls CUDA; this is not a requirement or Android capability.
- A line resizing to512² is overwritten immediately by the padded original. Constructor `img_size=512` also does not prove fixed512 inference: active forwards have no fixed-size input resize. The reference evaluates both networks at the native padded image size.
- GC constructor is `UNext_full_resolution_padding`, three input/output channels. Output S has a sigmoid head. Source `F.interpolate(S,(Hp,Wp))` omits mode and therefore uses **nearest**; normally this is a same-size operation. Do not replace it with bilinear while claiming parity.
- `C01=clamp(I01/S,0,1)` is per-channel division of encoded BGR01. The wrapper supplies no epsilon floor. Validate positive finite S and finite division; for pathological zero/underflow return a structured failure instead of accepting NaN or inventing a source epsilon. A sigmoid's nominal range is not a numerical proof of positive finite outputs on every backend.
- GC-only means composing C01 from GC; it is a deliberately isolated experiment, not the wrapper's final saved image. GC+DR concatenates `[original_BGR01, corrected_BGR01]` in that order to six channels and calls `UNext_full_resolution_padding_L_py_L`. Its first output is an **absolute sigmoid image**; three auxiliary lower-resolution heads are unused by the inference wrapper. Do not add it as a residual or divide by it.
- Source image byte casts are truncating `(float*255).astype(uint8)` after their stated clamping/range; crop `[pt:pt+H,pl:pl+W]`, then interpret BGR and swap explicitly back to shared RGB. Source parity compares raw floats before image encoding as well as the public byte path. PNG/JPEG encoding is not part of neural parity.

### 4.2 Explicit mobile field adaptation `gcdr_gc_mobile_v1`

This product variant uses **only GC**, at a bounded working raster, and composes source-resolution pixels. It is an experiment, not verified low-memory equivalence to native GC+DR. Fixed profile fields are `workingLongEdge=512`, `minDivisor=1/255`, `maxGain=3`, `fieldResize=HALF_PIXEL_BILINEAR`, `fieldSmoothing=NONE`, `inputPadding=TOP_LEFT_REPLICATE_32`, `inputPrecision=FP32`, `byteConversion=ROUND_BYTE_V1`. These fields are included in profileSha256; changing any creates a different profile/version.

For current appearance stage input W×H, set `s=min(1,512/max(W,H))`, `Ww=max(1,floor(W*s))`, `Hw=max(1,floor(H*s))`. Resize encoded RGB8 using the shared half-pixel bilinear/roundByte rule, swap to BGR, pad as above, normalize and predict GC. Require the expected finite three-channel output in [0,1]; out-of-sigmoid-range values reject rather than being repaired by the divisor floor. Restore to padded input shape using the source nearest rule if that graph genuinely has a lower output resolution. Remove pt/pl in **working** coordinates. Swap field channels BGR→RGB, then bilinearly lift the field to W×H; never interpolate gains under this ID.

For each full-size channel `g=clamp(1/max(minDivisor,S_lifted),1,maxGain)`, `candidate=roundByte(input*g)`. Clip/quantize before the single adapter-owned strength/protection blend. The max gain/floor are deliberate safety changes from source division. No GC target245 scaling is implied, and no detail restoration runs. A zero predicted divisor is finite but floor-clamped in this product variant; NaN/Inf remains a failure. The strict positive-divisor reference and this safe composition must not share an ID.

`gcdr_gcdr_product_v1` instead uses native padded GC+DR at an admitted size, source float composition internally, then `roundByte(255*clamp(DR_main,0,1))` and one public blend. It does not claim fixed512 speed or native-resolution fit. External denoise/detail are forbidden by its initial finishing policy to avoid undisclosed restoration stacking; this is a conservative product policy, not a claim that its learned DR equals the classical detail algorithm.

### 4.3 Arithmetic and conversion fixtures

- GC-01: W=33,H=65 gives pl31,pt31, padded64×96; crop removal restores exactly33×65. With workingLongEdge512, W=1000,H=500 gives working512×256, not512².
- GC-02: shared RGB (10,20,30) becomes tensor channel order **[30/255,20/255,10/255]**. A synthetic identity image-output tensor must return RGB (10,20,30), not (30,20,10).
- GC-03: product field S=.5, input100 gives gain2 and candidate200; S=0,input100 uses cap3 and candidate255; input0 remains0. S=NaN fails. Input200,S=.5,strength.5 yields **228**, not a double-blended result.
- GC-04: supplied DR main=.25 with original=.80 must produce product candidate **64**, not 255 from residual addition. Source truncation produces63. These different expected bytes are deliberate profile differences.
- GC-05: a lifted field [1,.5] sampled at its midpoint is .75 and reciprocal gain4/3, not the midpoint of gains1 and2 (1.5). Check field-versus-gain interpolation explicitly.

Code is MIT with a separate nested UNeXt MIT notice. README announces GC and DR checkpoints in an external OneDrive folder, but retrieval/content/checksums and weight-specific terms were not verified. A root software MIT license is not a statement that every externally hosted checkpoint has MIT redistribution rights. Export risks include roll/chunk shifts, slicing, reshape/transpose, reflection padding, normalization, depthwise convolution and sigmoid. Pruning unused DR heads requires raw-main-output parity, not just a smaller file. No verified parameter-count/FLOP/mobile-time claim is made [M2].

## 5. DocRes: exact prompts, 1600 branch and ratio reconstruction

Pinned implementation: `d3e3a18c7c7ad10e4615ca2eb6a10f83128d8560`, `inference.py` prompt functions and appearance/deshadowing functions [M3]. The six-channel Restormer is configured with dim48, blocks[2,3,3,4], refinement4, heads[1,2,4,8], expansion2.66, WithBias LayerNorm and dual_pixel_task=true. Do not infer another released architecture from a generic Restormer exporter.

### 5.1 Task prompt contracts

Both tasks begin with OpenCV-style **BGR** image bytes. Resize the full current appearance input to1024×1024, anisotropically, with linear interpolation. For each B,G,R plane separately: dilate with a7×7 all-ones square; then median-filter with side21. Dilation uses the maximum over valid support (equivalent to the default noncontributing exterior for byte maxima); median uses replicated borders. Merge the three background planes as B.

For **deshadow**, the returned prompt is B resized linearly back to the original stage size. The function also calculates a variable named shadow_map, but its active return is the background image. Do not reimplement the unused variable as the prompt. For **appearance**, form `D=255−abs(original1024plane−backgroundPlane)`; min-max normalize each D plane independently to0..255, merge, then linearly resize back. A constant plane normalizes to zero, not255 and not a divide-by-zero NaN.

Reference profiles use the pinned OpenCV prompt operations and preserve their integer outputs. Product profiles specify byte endpoints with shared roundByte: min-max is `roundByte(255*(D−minD)/(maxD−minD))` when maxD>minD, else0; byte resizes use the shared linear/roundByte rule. Prompt median/max are exact byte statistics. This independently fixed host arithmetic may differ from source integer kernels by a byte; test it as a **product** profile rather than obscuring the difference. Morphological/median prompt processing is not learned illumination recovery.

### 5.2 Branching and tensors

Construct six channels `[BGR image, BGR task prompt]` at the current appearance-input size W×H. **If max(W,H)<1600**, pad all six channels at top/left with replication to stride8, then normalize/transpose to batch1 NCHW. **If max(W,H)≥1600**, resize the six-channel byte raster to exactly1600×1600, not aspect-preserving1600-long-edge. There is no stride padding in that branch. The source uses `.half()` on both tensor and model for appearance/deshadowing; source-reference precision is FP16. A product CPU FP32 graph is a separate precision profile and must be compared against the FP16 reference and its own FP32 export oracle.

The network predicts a three-channel restored image P01. Clamp to[0,1]. The source quantizes **before** the high-resolution ratio stage by truncating255*P01 to uint8. In the small branch, crop top/left padding and return that image. In the large branch, for each channel:

```text
P8 = quantize_255_times_clamped_prediction(P01)
P8[P8==0] = 1
I1600 = byte_linear_resize(original_BGR, 1600, 1600)
S1600 = float64(I1600) / float64(P8)
Sfull = linear_resize_float_field(S1600, W, H)
Sfull[Sfull==0] = 0.00001
Cfull = clamp(float64(original_BGR) / Sfull, 0, 255)
```

Source final byte conversion truncates Cfull. Product profiles use **roundByte at both neural P8 quantization and final Cfull conversion**, and shared byte resize for I1600, with float32 stored S1600/Sfull and float64 scalar division/statistics. Zero handling is exactly equality-to-zero, not a second arbitrary positive epsilon; any nonfinite/negative ratio or invalid shape rejects. These differences must be included in profile identity and parity accounting. Preserve source-order operations; forming a float ratio before P8 quantization is another algorithm.

The lifted field is `resized_input/restored_prediction`, not the neural output itself. Final division by that field retains high-resolution photographed structure differently from simply resizing the restored1600 image. It can amplify quantization/color errors and preserve artifacts from tiny text in the ratio. It is not a physically established illumination estimate or a drop-in divisor for unrelated networks. Product adapters swap BGR candidate→shared RGB, then apply strength/protection once after candidate clipping. Full task output is an appearance replacement; do not chain deshadow then appearance by default. External denoise/detail are initially forbidden by the profile's finishing policy.

A preview below1600 and an export at/above1600 execute different branches. A detail crop must therefore use full-target context/branch and then crop; directly feeding the small crop to the network is not an equivalent zoom. No universal1600 export cap follows from the square inference branch. The full-resolution ratio application still needs admitted source/output buffers.

### 5.3 Deterministic host fixtures

- DR-01: 1599×100 uses the small branch, pl1,pt4, padded1600×104. 1600×100 uses a1600×1600 neural tensor and high-resolution ratio reconstruction. Do not decide the branch from tensor shape after padding.
- DR-02: constant128 per-plane prompt input has background128; deshadow prompt is128, appearance prompt is0. This tests the actual returned background versus an unused shadow_map.
- DR-03: large-branch source pixel I1600=100, product P8=200 gives divisor.5; matching original pixel150 yields candidate**255** after clipping300. If P8=0 it is replaced with1 before division. I1600=0 yields divisor0, then full-size exact-zero guard1e−5; an original0 pixel still gives0.
- DR-04: network output.5 gives source P8=127 and product P8=**128**. A source/native output mismatch caused by this intentional rule is not evidence of neural conversion failure; compare like profiles and retain both results.
- DR-05: supplied final unbounded candidate300, original200 and strength.5 yields**228**, not250. If the product P8 or final conversion uses truncation, its profile fixture fails.
- DR-06: six-channel identity inspection confirms prompt concatenation after all image channels; input is `[B,G,R,P_B,P_G,P_R]`, not interleaved image/prompt pairs. Reference small-branch top/left padding is removed from both axes exactly once. For a1599×100 base page with clockwise output turn1, appearance instead receives100×1599 and uses pl4,pt1, padded104×1600; it does not rotate that input or reuse base-axis padding metadata.

Prompt1024 work, neural tensor allocation, activations, ratio/resampling and full-resolution RGB output all count toward cost. LayerNorm reductions, GELU, attention normalization/matmul/softmax, depthwise convolutions, PixelShuffle/PixelUnshuffle and reshapes require export/delegate inspection. Do not load the separate MBD segmentation checkpoint for appearance/deshadow: it belongs to the source's dewarp-prompt path, not these forwards. The source end-to-end script has sequential tasks with intermediate JPEGs; it is not the required product architecture. MIT code and announced `docres.pkl`/`mbd.pkl` links do not establish external checkpoint license or retrieval. The paper's15.2M/183GFLOPs figure lacks a sufficiently established shape for a handset-cost promise [M3].

## 6. Original UVDoc map versus Paddle image-output distribution

### 6.1 Original map contract

Pinned UVDoc `4c9b82b537057aff2526e6dd118a847cdd072e82`: orient/decode once, use shared RGB bytes→float32/255, resize anisotropically with the reference OpenCV linear path to **W488,H712**, then batch NCHW `[1,3,712,488]`. No letterbox, ImageNet normalization or external page mask is in that demo. The network returns a2D map plus an auxiliary3D map; use only the first for resampling [M4].

The coarse tensor is `[1,2,45,31]`, axes `[batch,xy,row,column]`, channel0=x and channel1=y. Values are normalized input sampling coordinates, not displacement and not output-pixel positions. Upsample the map with bilinear **align_corners=true**; sample original RGB01 bilinearly with align_corners=true. The source demo outputs the original input width/height. Map aspect45×31 and network input aspect488:712 are not measurements of physical page aspect.

At output turn0, for destination centers x=0..Wo−1,y=0..Ho−1, map lookup uses `(x*(31−1)/(Wo−1),y*(45−1)/(Ho−1))`. For nonzero turns first obtain base `(ub,vb)` through the shared quarter-turn composition, then use `(ub*30,vb*44)` without transposing the45×31 tensor or rotating the source/model input. Convert sampled normalized coordinates to source centers `xs=(gx+1)*(Ws−1)/2`, `ys=(gy+1)*(Hs−1)/2`; with an accepted source crop add its origin once and enforce crop-local support. All relevant dimensions must be≥2. Full topology, bounds/support, overlap and output-aspect validation are in the geometry document. Nonfinite outputs reject **before** a sampler could reinterpret NaN as a valid boundary coordinate; do not clamp a bad map to conceal out-of-bounds predictions.

`uvdoc_grid_source_v1` preserves source zero padding, therefore outside RGB01 is black. `uvdoc_grid_white_v1` returns the same validated coarse map but uses the product's constant-white geometry sampler and shared roundByte. It supports the paired float protection mask using the identical map with outside1. Source-black versus product-white is a visible deliberate adaptation, not a backend bug. ## 10. Export, numerical parity, fidelity and device gates

These are future acceptance gates, not checks already passed. Freeze fixture identities and tolerances **before** running a comparison; a failure is not resolved by widening tolerances until it disappears. Keep software graph parity, adapter arithmetic, visual quality and handset fit separate.

1. **Rights/integrity:** identify exact source commit, architecture, all notices, checkpoint bytes/hash, explicit weight-license scope and redistribution decision; bind converted graph hash to original checkpoint hash and exporter environment. An announced URL, HEAD200, publisher checksum or model-card tag is recorded at its actual evidence level, never as a local successful retrieval. No asset with unresolved product rights enters the release allowlist.
2. **Reference oracle:** execute the pinned public wrapper on controlled permission-cleared fixtures in a separately authorized environment. Save raw network inputs/outputs before color conversion, fields, maps, prompt rasters, padding/crop metadata and reference final bytes. No private documents in public evidence. Source quirks remain visible, including FP16, truncation and border differences.
3. **FP32 CPU export parity:** for a locally converted graph, isolate the neural graph from host OpenCV/Pillow operations and use the same identified source artifact/checkpoint, input tensor, layout, shape and eval state. An unmodified publisher inference asset instead uses its supported reference-runtime raw outputs as the oracle; do not fabricate an unavailable training-checkpoint comparison. Initial proposed image/field raw-float tolerances: max absolute2e−4 and mean absolute1e−5 on[0,1] outputs; reject any new nonfinite values, shape/range mismatch or discrete branch difference. Map tolerance additionally requires max converted source-coordinate error≤.1pixel at the actual source size and no validity/topology status change. These are design starting gates requiring review, not universal guarantees of perceptual equivalence.
4. **Host adapter parity:** source-reference profile must reproduce its named resize, pad/crop, prompt, sampler, zero guard and quantization path; deterministic synthetic adapter fixtures in this document require exact bytes. Product variants are compared against their own specified reference, never source truncation by accident. For non-tie real CPU candidate bytes initially require every channel difference≤1 and report the exact histogram/max/error locations; investigate larger differences even when a global mean is tiny. For exact threshold/geometry decisions require identical classification, not a tolerance excuse.
5. **Optimized backend/precision:** FP16, quantization, delegates, graph fusions, head pruning, alternative working sizes or tiling create new identities and rerun raw-output and final-content checks. A proposed FP16 raw image tolerance of max1e−3/mean1e−4 is not authorization to accept erased faint marks or moved boundaries. Integer quantization has no automatic approval from generic PSNR. Inspect unsupported nodes/CPU partitions, repeatability, load/run failures and memory peaks.
6. **Geometry safety:** run identity/affine/crop/rotation/letterbox, nonsquare checkerboards, one-pixel lines, labeled corners, outside-border and paired-mask tests. Require finite grid values, noncollapsed consistently oriented bilinear cells checked at all corners, bounded stretch, non-self-intersecting boundary and no nonlocal overlap under the geometry document's rules. A smooth plausible screenshot is insufficient. Sampling the source once is preferred to compounding warps; a learned image-output provider cannot manufacture this evidence without its actual map.
7. **Fidelity:** paired originals and full-size outputs on faint strokes/pencil, punctuation, dense/small text, colored paper/ink/stamps/highlights, embedded photos, dark fills, hard/soft shadows and grain. Evaluate clipping, lost/new strokes, duplicated/omitted content, color shifts, halos and margin retention. PSNR/SSIM, OCR or whiteness alone cannot validate documentary fidelity. Reference labels/permission-cleared real pages are required beyond synthetic fixtures.
8. **Physical device/resource fit:** nominate actual API26+arm64 handset/build/runtime/delegate, memory class and page sizes/purposes; record cold load, warm end-to-end latency including prompts/copies/sampling, peak Java/native/accelerator memory, repeated-use thermal behavior, cancellation and stale-result handling. A declared tensor buffer formula does not bound activations. Measure after warm-up and cold start separately. Missing measurements keep the option experimental/gated, not “fast”.
9. **Offline/failure/release:** airplane-mode launch and every selected provider with installed assets; no network fallback; absent/corrupt asset, bad hash, unsupported shape/mask, native failure, resource rejection, process restart and cancellation tests. Check structured shared statuses and the last accepted source/recipe. Selectability requires the exact shipped ABI/runtime/profile/device support envelope and explicit release approval, not just successful model loading.

Memory planning counts source/crop/geometry raster and RGB output (3N each), protection4N where supported, tensors (12N for float32 RGB,24N for six channels), optional full-grid8N, prompt/ratio fields and resident weights/activations/scratch. Avoid full-resolution float RGB/grid materialization when the verified map/field profile permits streaming. Do not assume activations scale linearly: attention, padding and conversion scratch can change the curve. Whole-image context makes naive independent tiles a new algorithm; no silent tiling or lower-resolution export on memory failure.
