# Atelier neural evaluation — acquisition decision and acceptance

This is the next proposed U-01/AT-07 experiment, not an approval or a passed test. It intentionally excludes downloads, dependency changes, external uploads and production packaging until the applicable permission and rights checks are recorded. The default classical app must continue to work without models. A detector is not a dewarper, and an installed runtime is not a working method.

## First pair

- **Geometry:** evaluate the exact PaddlePaddle `UVDoc_onnx` revision `3bcf535371727d11e783101f79a504c68848aae3`, whose [pinned model card](https://huggingface.co/PaddlePaddle/UVDoc_onnx/raw/3bcf535371727d11e783101f79a504c68848aae3/README.md) declares Apache-2.0. The [pinned tree metadata](https://huggingface.co/api/models/PaddlePaddle/UVDoc_onnx/tree/3bcf535371727d11e783101f79a504c68848aae3) reports `inference.onnx`, 31,684,150 bytes, LFS SHA-256 `54cab30dc2cf347b4f3d6971c833b1c3d84f5ef17280f1f6d15796bff20e63d6` (metadata rechecked 2026-11-20; binary not verified). This is an image-output candidate, not a claim that it exposes an original-source inverse grid or a paired mask transform. Keep it separate from the original UVDoc grid recipe. Reject protection or geometry/rotation/size combinations until the actual graph and exact image-output contract support them; do not silently apply a second corrective warp.
- **Appearance:** evaluate `GCDRNet` global-context illumination first, pinned to source revision `415c97a9a64d0a796dbbad43485ce2ab102f2a7d`; only then test its distinct GC+DR output if a measured need remains. The [upstream README](https://raw.githubusercontent.com/ZZZHANG-jx/GCDRNet/415c97a9a64d0a796dbbad43485ce2ab102f2a7d/README.md) links an external checkpoint but does not specify weight rights (rechecked 2026-11-20). Obtain the applicable terms for that bundle or choose a weight-cleared replacement. Do not infer rights from the source-code license. Keep FSENet as a conditional offline comparator rather than an assumed mobile fallback. See [provider specifications](MODEL_PROVIDERS.md) for exact tensor and postprocessing contracts.

Prefer one approved CPU inference runtime for both candidates if their exported graphs and supported Android ABIs permit it. ONNX Runtime Android is a candidate, not an added dependency. Maven Central [lists `com.microsoft.onnxruntime:onnxruntime-android`](https://repo.maven.apache.org/maven2/com/microsoft/onnxruntime/onnxruntime-android/maven-metadata.xml); the checked `1.32.0` AAR `.sha256` URL did not resolve. Do not infer actual binary hashes, Android API/ABI coverage, or supported graph ops from the version listing. Record the exact artifact and hashes, repository, ABI/native footprint, verified dependencies and notice files before adoption. Raw tensor fixtures precede Kotlin/Android integration. Require an offline initialization path with no automatic acquisition, silent model substitution, broad grants or network access.

## Same-input experiment

1. For each locally cleared page, bind the byte/pixel identities, EXIF-normalized source dimensions, fixed rotation, test target and selection. Include flat skew, bound book curvature, hard shadows, cast, faint pencil, colored markings and photographs. Synthetic ramps and grids diagnose alignment and rounding; they do not replace the representative-page set. Keep private originals/outputs/identifiers outside Git and do not send them to a service.
2. Compare perspective, true Bézier (or reviewed manual curve) and learned dewarp against the same normalized source. Report image destination and any required size change. Mark protected, hidden or clipped areas and grid/line residuals; inspect printed margins, folds, direction, aliasing and lost marks. Do not silently resize a failed candidate to obtain a comparison.
3. Separately hold one admitted geometry and identical output size for every appearance method on each page. Compare No enhancement, White paper, Natural light and the learned candidate. Inspect shadows, casts, color retention, faint text, texture, new edges/halos and clipping. Record failed cases as failures, not absent rows or classical output attributed to the model.
4. Prove source-versus-exported CPU parity on fixed synthetic tensor inputs before Android acceptance. Report asset/profile/backend identities, cold/warm timing, peak memory, CPU/ABI and failure category independently of visual scores. Repeat on the authorized emulator for functional offline validation; record physical-device latency, thermal and fidelity as separate gates.

## Reentry

Start the first two acquisitions only after explicit approval of their exact assets and the agreed CPU runtime, evidence of checkpoint rights for each intended use, and access to a locally cleared representative set. No model asset was fetched or installed and no inference or quality comparison was performed by this specification.
