# Atelier — Android product and interaction contract

Version 1.0.0. **Atelier (C) is the selected direction** in the [interactive reference](../superpowers/mockups/first-major-redesign.html). This document defines the real Android behavior; the HTML defines the visual impression and click sequence, not the processing, sample data, platform pickers, persistence or failure handling. Use the [versioned design kit](../design/atelier/v1/README.md). Atelier supersedes the earlier screen hierarchy in [UX_SPECIFICATION](UX_SPECIFICATION.md), not the requirements for privacy, quality, exports or batch editing. The following is a target contract, not a claim about the current APK.

**Language:** All PristinePage-controlled labels, accessibility descriptions, dates with month names and messages are in idiomatic English. French labels in the historical reference (including citations to that reference below) identify the corresponding elements, not strings to ship. Android permission prompts and native/provider pickers use the device/provider language. User-entered titles and source metadata are not translated. Use the user's locale to collate their titles and their time zone for the clock.

Use **My scans**, **Settings**, **Sort albums**, **Add pages**, **From gallery**, **From files**, **Finish importing**, **Perspective**, **Rotation**, **Correction**, **Save album**, **Frame**, **Original**, **Page info**, and **Apply** as the respective English UI labels. A compact control may use **Import**, **Review pages** or **Next** when the surrounding context makes the target clear.

## Goal and approach

Make the shortest real journeys easy: open the camera from Home, build and finish one album from several sources, reopen a page and adjust it, and compare corrections without losing the original. Keep the page visibly larger than its controls. Emphasize the current action, not a row of competing primary buttons. The stored original and the accepted recipe must remain usable when editing, analysis or saving fails.

Use native Compose over the existing CameraX, picker, app-owned storage, editor state and renderer. Restyling the old destinations alone would preserve their immediate append behavior and miss the mixed staging/finish journey. Replacing the scanner or embedding the mockup would discard working decode, persistence and lifecycle guards or substitute demo behavior. Add the smallest new capabilities the journey actually needs; do not replace the accepted [implementation plan](IMPLEMENTATION_PLAN.md). Keep API and package identity unchanged.

## Destinations and entry points

- **Mes scans → Prendre une photo:** bottom-center `+` goes directly to the camera destination for a new album. No create form, onboarding or picker intervenes. Bottom-right gear opens **Paramètres**; the header sort button opens **Trier les albums**. A card opens the album directly.
- **Album → page:** show the ordered grid immediately, without requiring the user to select a page in a list first. A tap on the title opens rename; a tap on a thumbnail opens that page's large preview. **Ajouter des pages** starts the same acquisition destination, bound to this album. Preserve the grid's scroll and focused page on return when that page still exists. Use album/page overflow or selection actions for reorder (`Move earlier/later` also available without dragging), duplicate, remove, and export review once implemented; none substitutes a placeholder action for a missing capability.
- **Capture → review → wizard:** the shutter, gallery and files all feed the same ordered acquisition draft. The review offers **Prendre une autre photo**, **Ajouter depuis la galerie ou les fichiers**, and **Terminer l’import**. Only the last starts the wizard: **Perspective → Rotation → Correction → Enregistrer l’album**. On success, open the saved album grid.
- **Reopened page → ribbon:** header Back and **Appliquer**; image first, one active tool panel at most, then **Cadre · Rotation · Correction · Original · Infos**. Cadre opens the same geometry controls as Perspective. Correction opens the same carousel as in the wizard. Tapping an active tool collapses its panel without resetting changes. Original toggles comparison independently; entering a geometry tool restores the editable source viewport.

## Home, dates, titles and settings

Render the album title, page count, up to three thumbnails in persisted page order, and a labeled date and time (`Créé` / `Modifié`). Use clean loading or unavailable placeholders **per tile**, not fabricated page images; never make remaining pages wait for one thumbnail. Prefer latest accepted result thumbnails; if an edited rendition cannot be shown, label any substitute as an original preview, or show unavailable. A blank new library contains a short prompt and the same camera shortcut, not a fake sample album. Existing empty albums and albums whose pages fail to load remain visible; invalid catalog metadata receives a safe error, not unverified title/date values or silent removal.

Default sort: latest modification first. Creation and modification orders are both descending, with immutable album ID as stable ascending tie-breaker. A–Z and Z–A use locale-aware, case-insensitive title collation, with ID ascending for ties in both directions. Expose guarded stored timestamps at the catalog boundary and preserve the global order across catalog pages, not a per-page Compose sort. Changing sort/locale or mutating a key invalidates the prior cursor/result. Store timestamps as UTC epoch milliseconds; display the local date **and** time in English using the device's current time zone. Creation timestamp is the stored album creation; touches, previews and canceled drafts do not update modification. A successful rename, page membership/order change or saved recipe changes modification time. Use the persisted values, never the file mtime or current clock as a substitute. With date sorts, the card shows the sort's timestamp; with name sorts, it shows the timestamp selected in Settings. Album overview shows last modification as in the reference.

The title is normal text with a small edit affordance, not a permanently open field. Rename pre-fills the current title, trims outer whitespace, rejects blank titles and enforces the existing repository limit of 160 UTF-16 code units of well-formed text, not the demo input's stricter limit. Save using the exact album ID and expected revision. Cancel/no-op does not update time. On conflict or storage failure, retain the typed text and offer refresh/retry rather than overwriting a newer revision. Only new albums use the saved name template, which defaults to `pristinepage_%date_%time`; identical names do not identify albums.

The square-cornered album title area wraps rather than animating. The pinned overview title uses at most five lines so page actions remain reachable; the scrollable Home card and Rename show the full title.

Settings persist the selected Home sort, the preferred timestamp for name sorts (modified by default), and the camera viewfinder grid (on by default). The two visible switches are **Afficher la grille de visée** and **Afficher la date de création**; use helper text explaining the date-sort precedence. The grid is an overlay only, never burned into the still. No reset of real data, tutorial fixtures, account, network, theme selector or model install is implied by the prototype's reset button.

The Home gear opens a standalone **Settings** destination, not a bottom sheet over Home. Group settings under **Home and albums**, **Camera**, and **Text recognition (OCR)**, with individual subpages for the album name template and OCR languages. Keep the Home header sort shortcut and use the same persisted preference in both routes. Back returns from a subpage to its parent, then to the previous Home state. Do not reset existing preferences, change saved albums, or add networking as part of this move.

## Mixed acquisition and its ownership

Keep **Caméra**, **Depuis la galerie** and **Depuis un fichier** distinct. In the camera's bottom-left slot the nine-square **Importer** button opens an in-app source sheet with the two separate picker choices. The center shutter is manual. The bottom-right **Terminer** opens review if there are accepted items. Show the pending count and ordered thumbnail queue; review shows the accepted still/item thumbnails, not a live frame frozen and passed off as a capture. Use the existing supported flash controls when available and the grid preference. When permission is denied/revoked, the camera is missing, or Preview fails, keep the two picker routes usable without requiring another camera permission grant. Explain the cause and how to retry the camera.

Gallery uses the image Photo Picker or its existing distinct gallery fallback. Files uses the image-filtered system document picker. No silent switching between them, no broad storage grants. Accept ordered, bounded JPEG/PNG/WebP inputs under [CAPTURE_IMPORT_EXPORT](CAPTURE_IMPORT_EXPORT.md) and the installed codec's proven capabilities. Validate actual content; consume only the granted URI. Do not retain external URI strings or temporary pixels in saved UI state. Picker cancellation is neither success nor an error requiring deletion; existing accepted entries remain. Failed items do not increment the count. Explain individual failures, allow retry/reselection and preserve successful items' order. Preserve the compatible camera JPEG's entire original bytes.

The **Atelier draft** spans repeated shutter/picker operations to one target; a single picker request/ingest batch is not the draft. Reserve identities before capture/launch and correlate callbacks to the operation and draft. Serialized admission rejects duplicates/stale callbacks and enforces the target's capacity across the entire draft. Retain successful inputs as privately owned immutable sources; new draft pages do not appear as saved pages until commit. Do not implement this by eagerly editing an existing album and hoping to undo it on Back. Wait for unsettled capture/copy operations or explicitly cancel those operations before enabling **Terminer l’import**; it freezes the ordered successful item IDs for this wizard pass. Returning to acquisition may add new items; a new Finish validates and freezes membership again without losing edits to retained IDs. The storage slice must establish an explicit recoverable draft owner before exposing the journey, with source pins, ordered successful pages, and one final revision/membership commit. Reuse existing ingestion and journal operations wherever they preserve this boundary.

See [acquisition staging and publication](ATELIER_ACQUISITION_STORAGE.md) for the proposed reuse boundary and the journal/replay constraint that rules out moving a committed staging page to a different document.

Back with no accepted or pending items returns to Home or the target album. Otherwise show **Continuer l’import** / **Abandonner cet import** with the scope named. Abandon releases only draft-owned claims; existing albums, accepted pages, recipe history and prior originals are untouched. After configuration change restore the bound draft and next action without double-launching. After process death use durable opaque IDs to offer Resume/Discard for the last privately checkpointed recipes, step and selected page, as well as recoverable sources. Checkpoint completed edits and step transitions, not every pointer sample. Explain any uncheckpointed in-flight action or unavailable item; do not reacquire a stale external grant. Final save is idempotent, checks current target membership and revision, preserves old pages and appends draft pages in order, and reports success only after guarded commit. A conflict or storage failure keeps the draft available and avoids a partially published album; never create a lookalike album as a fallback for a missing target.

## Wizard and per-page editor

The wizard shows one step at a time with the step name and position. A numbered scrollable page strip is present for more than one page; switching pages preserves all drafts and never applies edits to the new selection. Only newly acquired pages are wizard members, even when appending. Each page has its own seeded geometry, turns and appearance. **Continuer** changes step, not persistent storage; Back moves one step backwards or returns to acquisition on the first step without losing prior work. **Passer** on Perspective proceeds with whole-image geometry for the new pages, asking before replacing any user-edited frame. It does not touch old album pages or change rotation or appearance. A page whose automatic placement failed may instead keep the whole image, or be framed by hand. A retained invalid proposal cannot be marked complete by moving to a different page. After Correction **Enregistrer l’album** saves all new pages with their accepted individual recipes, not just the page on screen. Block duplicate acknowledgments/launches while storing; offer clear retry or conflict recovery.

The large Fit viewport preserves aspect and does not crop the actual page; thumbnails may crop decoratively. Rotation uses real output quarter-turns left/right, updates the angle and rendered preview, and composes after geometry and before appearance. Do not rotate the original bytes or double-apply EXIF. The geometry overlay always edits the oriented source; rotation affects final preview rather than relabeling those source controls. **Infos** reports real dimensions, page order, source/preview distinction and requested versus actually executed method and status, without paths, digests, off-device metadata or synthetic sample text in the primary view.

Reopened pages use accepted versus working recipe state, with revision-checked **Apply**. The Carnet operator's retest updates header Apply: after a confirmed save stay on the same page and close only the active tool; with an open tool and no changes, close it without a write. Dirty Back still offers Continue editing, Discard or Apply and leave. Retain the draft and open tool on save failure and never label stale content current. In the crop tool, labeled Undo, Redo and Discard icons remain under the result preview and above the independently scrollable edits; preserve the source magnifier and its automatic side choice. Keep full-bypass viewing semantics and advanced Detail controls discoverable. [BATCH_EDITING](BATCH_EDITING.md) is a separate album action: show **Sélectionner** in the album header/actions and switch to selection controls including **Terminé**. All effectively edited pages save atomically even if deselected; the wizard page strip is not batch selection and cannot satisfy FR-17.

## Perspective and true Bézier

**4 points** shows draggable, consistently labeled TL, TR, BR, BL corners and a single outlined quadrilateral, with an outside scrim that leaves the interior visible. Use the oriented original, actual fitted-image bounds, and inverse display transforms for input, not screen percentage. Magnify/zoom or nudge controls without moving the underlying source coordinates. Reject crossed, degenerate or non-admissible shapes and retain the last valid state. Center labels in semantic actions rather than covering the image.

Seed valid detected corners on first wizard entry for untouched pages. **Proposition de contour** separates candidates from application: selecting a detector does not replace manual edits, **Replacer** explicitly requests and applies a current valid proposal for this page. **Auto · Bords** starts with a bounded classical luminance-edge detector: identify line candidates at preview scale, score convex four-line proposals by boundary support, and verify native coordinates through the map-admission path. An unsupported or low-support case returns no proposal; neural assets are not a prerequisite. **Auto · Zone de texte** is a distinct optional, actual content-driven proposal and must be identified as an estimate that may exclude margins/illustrations. Do not advertise it if it has no working provider; explicitly report its status if a build cannot produce it. **Image entière** is a deterministic full-frame reset, not a detector success. If detection fails or a newer gesture supersedes it, keep the existing controls; on first failure show whole image with a clear fallback notice. When applying a proposal would replace a customized Bézier path, confirm before resetting it to four straight edges, and keep its prior controls undoable. Never commit detection merely because it ran or replace a saved crop on reopen.

The [regional detector](../../validation/geometry/atelier-regional-edge-detection.md) adds sustained luminance support beside each of the four lines to recover some low-contrast or blurred page boundaries and reject thin distracting lines. This is a perspective proposal for visible flat sheets, not automatic reconstruction of a curved or partly missing page.

**Suggest a curve** is an explicit action on a current four-corner Result. The [classical proposal](../../validation/geometry/atelier-curved-page-proposal.md) needs consistent visible boundaries and improvement on interior lines. The resulting editable midpoint shape uses the ordinary preview/Undo and save path. A weak, superseded, canceled or resource-limited proposal keeps the existing frame and does not alter a saved recipe. Manual curve remains available.

**Bézier** is a real four-sided cubic path, initialized from the current four source corners with straight segments. Keep those four identified corner anchors so each boundary has a defined destination edge; permit insertable/removable intermediate nodes on all four sides. Node and tangent controls are distinct. Moving a node translates its attached handles; moving a handle changes the adjacent cubic in the actual render. Smooth interior nodes may keep opposing tangent directions while retaining separate arm lengths; corners permit independent handles. Insert from the explicit **+ Point** action at the nearest eligible segment, including a focusable segment choice without dragging. Split that cubic at its parameter without changing the curve when inserted; moving the new node can then reshape it. **Retirer** applies only to a selected intermediate node; non-exact merges are visible and undoable. Preserve geometry on gesture cancel; one completed gesture is one undoable edit. Clamp source coordinates and set reviewed caps for node count, map preparation, sampling, proof work and memory before enabling this mode. Keep the existing midpoint **Courbure** algorithm and its historical recipe readable; it is not Bézier.

Bézier acceptance requires a typed, versioned source-bound recipe, an actual backward map from the four cubic edge chains to a rectangular output, and the same admitted map in preview and full-target rendering, including paired masks when supported. Validate the true cubic boundary for simplicity and reject maps with folds, reversed orientation, unsupported samples or budget exhaustion; a sampled drawing alone is not map admission. Pin coordinate spaces, sizing, serialization, validity/proof and renderer budget in [GEOMETRY_ALGORITHMS](GEOMETRY_ALGORITHMS.md) and [PIPELINE_CONTRACTS](PIPELINE_CONTRACTS.md) before enabling saves. Original, straight perspective and old manual-curve recipes keep their existing semantics and fingerprints. Proposed controls that fail proof are not silently approximated by the old midpoint recipe. Leaving Bézier for a plain quadrilateral requires explicit application of the four-corner-only result; Undo can restore the previous complete curve.

See [cubic contour mapping](ATELIER_BEZIER.md) for the directional segment conventions, certified projective departures, host evidence, and open native checks.

## Correction and comparison

Open a horizontal carousel with text plus imagery, a check/selected state, swipe and discrete previous/next controls. Use the existing genuine classical methods: **Sans amélioration**, **Papier blanc**, **Lumière naturelle**, **Gris**, **Noir et blanc**. The first is the full photometric bypass; the palette and short labels never conceal which stages actually changed. Distinguish labeled bundled sample cards from live page previews. Selecting a method schedules the current page and shows pending/ready/error, while comparison remains one tap away. A failure may keep the last same-page result labeled **Aperçu précédent** but never show another method under the failed name. No fake HTML filters or placeholder output in production.

**Document color** is a separate, opt-in [classical method](../../validation/appearance/atelier-document-color.md) for uneven or tinted paper lighting. The card describes the method and the live page shows its actual result. Reopening or reselecting an active Document color look keeps its saved strength, including values set in album batch edit. Selecting it from another appearance method uses its own default and clears grayscale or black-and-white conversion.

**Paper shadow** is an opt-in [classical method](../../validation/appearance/atelier-paper-shadow.md) for a straight shadow across light paper. It is a separate individual and batch Look, not a second pass over Document color. It preserves the lit region, keeps the previous frame and stored original, and makes no correction when the lighting model is unsupported. The live result, not a substitute sample image, is the comparison.

**Original** displays the normalized uncropped photograph, no user rotation or processing; **Entrée après géométrie** preserves crop and user rotation and bypasses photometric stages; **Résultat** runs the current recipe. Make all three reachable from view choices within Correction while keeping the one-tap Original toggle. Viewing or switching comparisons does not change the draft. **Courbure** remains an advanced choice within Cadre and is the selected mode when opening a saved midpoint recipe. Learned dewarping belongs in geometry; learned appearance belongs in Correction. They are real mandatory product capabilities under [U‑01 and FR‑07](PRD.md), not synonyms for detection or paper whitening; no provider appears as working without authorized assets/runtime, numerical parity, actual local inference and device evidence. Compare dewarp methods on the same oriented originals and appearance methods at fixed admitted geometry and raster size. Measure geometry/margins, hard shadows, color casts, faint or colored marks, artifacts, latency and peak resource use on representative authorized pages, not only bundled examples. Do not add optional export polish to unblock that comparison.

Correction magnifies the fitted preview from 1× to 5× with pinch in or out and bounded pan. Result, geometry input and Original within Correction share the display transform, while Zoom in and Fit provide non-gesture controls. Reset when changing pages or leaving Correction. Magnification does not edit the recipe, schedule a new raster, imply full-resolution detail or change the crop canvas or the outside-tool gallery gestures.

## State, accessibility and acceptance

Use the states and components in the [design kit](../design/atelier/v1/components.md). Reflow at large font scales and with keyboard/insets; a bottom sheet/ribbon cannot hide its final action or capture TalkBack focus behind it. Icons have labels, touch targets are at least 48dp (including expanded geometry handles), choice status is not color-only, and no required action is swipe-only. Provide directional actions for corners, controls and handles; support keyboard, Switch Access and reduced-motion behavior. Preserve visibility of the currently focused handle or action.

## Delivery order

1. **T-10 independent catalog prerequisite / AT-01:** Theme, launcher asset, Home, preferences and real album catalog (dates, order, titles and thumbnails), then the immediate album grid. This sub-slice can precede the ongoing T-09 editor completion; it neither removes T-10's dependency on T-09 nor closes AT-01 without its native camera witness.
2. **T-05 / AT-02–03:** Mixed staging and guarded final album save, CameraX and system-picker journey, then the stateful three-step wizard. Keep baseline ingress/codec behavior intact.
3. **T-09 / AT-03–05:** Full-page ribbon, common rotation and correction controls, comparison and saved reopen; use the same editor session/renderer. Add real four-corner detection and, as a separately reviewed T-06 contract, versioned cubic contour rendering.
4. **T-10 / AT-05 and T-08/T-12 / AT-06–07:** Complete the retained cumulative batch and neural gates as their prerequisites clear. Re-rank after meaningful evidence, not after each UI unit test. Record a blocked gate with a concrete reentry condition. Preserve existing APKs, data and evidence.
