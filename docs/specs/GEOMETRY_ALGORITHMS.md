# Geometry algorithms and numerical rendering contract

Version 1.0, 2026-11-14. Scope: FR-03 page rotation, FR-04/05, NFR-01/02/06 and implementation tasks T-02/T-06/T-08. This is an independent implementation specification, not a reconstruction of another application's behavior. Read [PIPELINE_CONTRACTS.md](PIPELINE_CONTRACTS.md) for shared types, [MODEL_PROVIDERS.md](MODEL_PROVIDERS.md) for assets/runtime admission, and [VALIDATION_PLAN.md](VALIDATION_PLAN.md)/[TEST_FIXTURES.md](TEST_FIXTURES.md) for application acceptance. All equations and mandatory classical recipes needed to implement geometry are supplied here; public references establish particular upstream contracts, not an external local-workspace dependency.

Evidence labels: **SOURCE** means behavior inspected in the pinned public implementation; **DESIGN** means the specified product behavior; **PROPOSED GATE** means a concrete initial numerical acceptance policy that must be validated against fixtures and permission-cleared real pages before release. No handset measurement, model conversion, inference, image-quality acceptance or application implementation is claimed by this document. Tolerances may change only through a versioned contract and recorded regression evidence, not per-image hidden tuning.

## 1. Scope, order and minimum useful implementation

Geometry runs once, including user page rotation after the base geometry and before appearance, denoising, sharpening and final grayscale/binary conversion. The mandatory useful baseline is `NONE`, labeled four-corner `PERSPECTIVE`, and `MANUAL_CURVE`; unavailable learned providers never disable those paths. `ROUGH_CROP_DEWARP` is optional and gated. Detection proposes controls; it is not an additional rendering mode and never replaces accepted user controls without confirmation.

The baseline reuses a tested linear-algebra/SVD implementation and image-buffer primitives rather than inventing a tensor runtime or general workflow engine. A platform homography/remap implementation may accelerate rendering only after passing this reference sampler's border, rounding and coordinate tests. A manual four-corner crop is preferable to accepting a detector's invalid outline; retaining the photograph is preferable to accepting a folded dewarp.

These algorithms estimate where to sample existing photographed content. They cannot reveal text hidden behind a fold, recover an occluded margin, infer a physically correct paper aspect from four arbitrary image points, or guarantee content fidelity merely because the resulting page looks rectangular. UVDoc explicitly assumes an entirely visible document without occlusion/foldover [U3]. Coordinate prediction followed by source sampling is distinct from generating replacement RGB content; learned coordinates can nevertheless stretch, omit or duplicate real content.

## 2. Recipe family, spaces and identity

DESIGN: implement a sealed `GeometryRecipe` family with `schemaVersion`, a source binding `(sourcePixelHash, sourceSize, orientationColorConversionVersion)`, algorithm ID/version, every effective parameter, the declared target rule, and `outputQuarterTurns:Int` in `0..3`, default 0. Its four variants are `None`, `Perspective`, `ManualCurve`, and `RoughCropDewarp`, matching `GeometryMode`; every variant supports this clockwise output rotation. Reject an out-of-range serialized turn count rather than reducing it modulo four; a UI rotation action explicitly computes its new valid count. Reject unknown fields/versions for rendering while preserving stored documents. Reject a mismatched source hash or dimensions; never adapt a recipe to an unrelated image by opportunistic scaling.

- `None`: no geometric controls; base target is the oriented-source size/aspect, swapped for odd output turns. At source-sized base resolution, rotation is an exact pixel permutation; turn zero is a byte-identical source copy, with no color roundtrip. Smaller output uses an explicit half-pixel, clamp-border source-resize map composed with the output rotation, not a corner-aligned dewarp or a twice-resampled intermediate.
- `Perspective`: `QuadPx` labels stored as normalized source-center controls; target rule `EDGE_EXTENTS` or `FIXED_RATIO(widthOverHeight)`; default `EDGE_EXTENTS`; sampler ID `bilinear_white_v1`.
- `ManualCurve`: the same labeled quad, two on-curve midpoint handles, finite `depth` in `[-0.95,0.95]`, the same target rules, `arcSegments=128`, and `manual_ruled_v1`. Defaults are chord midpoints, depth zero, no inset and no edge profiles. Store the requested mode even when its exact straight-control branch executes perspective; record that dispatch.
- `RoughCropDewarp`: accepted integer `RectPx`, immutable provider/asset/contract identity, `geometryOnly=true`, target rule `CROP_ASPECT` by default, and optional explicit fixed ratio. Persist the accepted crop and target decision; do not rerun detection to choose them during export. No implicit perspective preprocessing is included.

Source `S` is immutable, orientation/color-normalized encoded sRGB RGB8, size `Ws×Hs`. Pixel centers are `(0,0)` through `(Ws−1,Hs−1)`, x right and y down. A source control is serialized as `(x/(Ws−1),y/(Hs−1))`; geometry requiring these divisions rejects a source or destination axis smaller than two. `NONE` alone may resize to a one-pixel axis under the shared resize contract.

At render, denormalize user controls once to float64 source pixels. Crop `C=(x0,y0,Wc,Hc)` has local centers `(0,0)..(Wc−1,Hc−1)` and translation `S=C_local+(x0,y0)`. Extraction is integer half-open `[x0,x0+Wc)×[y0,y0+Hc)`. Final destination `D` has explicit `Wo×Ho` centers, with `u=xo/(Wo−1)`, `v=yo/(Ho−1)`. The unrotated base-geometry raster has size `(Wg,Hg)=(Ho,Wo)` for odd output turns, otherwise `(Wo,Ho)`. Display, preview, base geometry, final destination, detector tensor, detector heatmap, model input and model grid are separate named spaces; retain their transforms rather than multiplying normalized coordinates from different spaces.

`OutputSpec.size` is the already-resolved final, post-rotation destination, not a long-edge cap or a request to guess page dimensions. Persist target-rule parameters and output turns in the recipe; carry the resolved base/final target dimensions and requested raster size in the render/execution identity. A detail view uses full-target algorithm context or an explicitly equivalent region renderer, not a new geometry fit to a viewport. A changed output size, source binding, target rule, output turn count, sampler or model hash invalidates cached rendering.

EXIF orientation is applied exactly once before these controls exist. Its clockwise 90° source-normalization example is `(x',y')=(Hs−1−y,x)`, new size `(Hs,Ws)`, inverse `(x,y)=(y',Hs−1−x')`; that belongs to decode, not the user page-rotation operation. User rotation changes only `GeometryRecipe.outputQuarterTurns` and the page's recipe/revision, not source pixels, source binding, normalized crop/curve controls, source masks, another duplicated page's recipe, or EXIF state. Display-transform controls for interaction, but inverse-transform edits back to the original oriented-source coordinates. Do not persist a second conflicting page/source rotation.

Compose user rotation into backward sampling. For final normalized `(u,v)`, obtain base normalized `(ub,vb)` as `q0:(u,v)`, `q1:(v,1−u)`, `q2:(1−u,1−v)`, `q3:(1−v,u)` for clockwise counts 0,1,2,3. Then apply the selected base inverse map at `(ub,vb)`; its pixel-coordinate form uses `xg=ub*(Wg−1)`, `yg=vb*(Hg−1)`. This is one composed source-to-final resampling, not a rendered base bitmap followed by another interpolating rotation. Apply precisely the same composition to protection and coverage, retaining their own outside values. Geometry validation remains in the base domain: a quarter-turn is an orientation-preserving bijection and does not excuse a folded base map.

For `NONE`, the equivalent final-to-base integer-center formulas are q0:`(xo,yo)`, q1:`(yo,Hg−1−xo)`, q2:`(Wg−1−xo,Hg−1−yo)`, q3:`(Wg−1−yo,xo)`. Compose these with the half-pixel resize `xs=(xg+0.5)*Ws/Wg−0.5`, `ys=(yg+0.5)*Hs/Hg−0.5`, using the declared resize clamp border. These index formulas also handle a singleton resized axis without dividing by `Wo−1` or `Ho−1`; non-NONE geometry retains its axes-at-least-two requirement. When base and source sizes match, use exact index permutation instead of floating-point interpolation.

## 3. Quad validation and target dimensions

DESIGN: `validateQuad(q, sourceSize)` runs before any solve/allocation. Require all eight coordinates finite and within the source center rectangle; require distinct consecutive corners and each edge length at least one source pixel; require polygon area strictly greater than one square source pixel. Do not repair a serialized invalid quad by clamping, sorting or swapping labels. UI dragging may prevent invalid movement and show a reason.

Use the declared cycle `p0=TL,p1=TR,p2=BR,p3=BL`. For `e_i=p_(i+1)−p_i`, require every `cross(e_i,e_(i+1))` strictly positive in the x-right/y-down convention; require positive signed shoelace area `A=0.5*sum cross(p_i,p_(i+1))`. Reject crossings/touches between nonadjacent edges with a robust orientation/on-segment predicate. “Clockwise” here means this explicit positive sign, not a library's y-up convention. Labels remain attached to their corners when a user rotates a page; independent min-x/min-y selection is not a labeling algorithm.

PROPOSED GATE: float64 comparisons use `D=max(1,hypot(Ws−1,Hs−1))`, length uncertainty `1e−10*D`, and cross-product uncertainty `1e−12*D²`; a result within predicate uncertainty is rejected as degenerate. The one-pixel edge/area conditions are separate product minimums, not replacements for convexity, conditioning or robust predicates. Full-frame reset is an explicit user selection; a detector failure must not label it detected.

Natural perspective/manual target dimensions are `Wn=ceil(max(|TR−TL|,|BR−BL|))+1`, `Hn=ceil(max(|BL−TL|,|BR−TR|))+1`. The `+1` converts a center-to-center extent into a number of centers: a full-frame quad of a `401×301` source must yield `401×301`, not `400×300`. Manual mode deliberately uses this same chord-based sizing; arc lengths control parameterization, not an undocumented change of page aspect.

For `FIXED_RATIO(r)`, require finite `r>0` and explicit width/height orientation; no unannounced portrait swap. Use base `(Wb,Hb)=(Wn,Hn)` for perspective/manual, `(Wc,Hc)` for rough-crop dewarp. Fit inside that base without upscaling: if `Wb/Hb>=r`, choose `(floor(r*Hb),Hb)`, otherwise `(Wb,floor(Wb/r))`. Reject either dimension below two or outside admission limits. `CROP_ASPECT` uses `(Wc,Hc)`; `NONE` uses `(Ws,Hs)`. Record integer rounding and the achieved raster aspect; a familiar paper preset is a user assumption, not a geometric measurement.

After choosing the unrotated base target `(Wt0,Ht0)`, set final target `(Wt,Ht)=(Ht0,Wt0)` for odd `outputQuarterTurns`, otherwise `(Wt0,Ht0)`. Thus a fixed ratio is specified in base-page orientation and is inverted in the final displayed aspect for odd turns. Only then apply a purpose long-edge limit `L`: `s=min(1,L/max(Wt,Ht))`, `(Wo,Ho)=(max(1,floor(s*Wt)),max(1,floor(s*Ht)))`, subject to dimensions at least two for geometric sampling. Export uses its selected explicit final target, never an inflated tensor size to manufacture detail. An arbitrary caller-supplied aspect inconsistent with the resolved target/turn/purpose policy is `INVALID_INPUT`; do not silently stretch. A preview may differ photometrically from a downsampled full export because downstream algorithms receive different dimensions.

## 4. Perspective: solve once, sample backward

Associate source `TL,TR,BR,BL` with base destination `(0,0),(Wg−1,0),(Wg−1,Hg−1),(0,Hg−1)`. The forward homography satisfies `[a,b,1]^T ~ H*[x,y,1]^T`; output sampling uses `G=H⁻¹`. After applying the final-to-base quarter-turn, evaluate `z=G20*xg+G21*yg+G22`, `xs=(G00*xg+G01*yg+G02)/z`, `ys=(G10*xg+G11*yg+G12)/z`. Sample the original oriented source, not an enlarged detector image or an intermediate unrotated page.

DESIGN numerical solve: independently Hartley-normalize source and destination point sets by translating their centroids to zero and scaling mean Euclidean distance to `sqrt(2)`. For each normalized correspondence `(x,y)→(a,b)`, add rows `[-x,-y,-1,0,0,0,a*x,a*y,a]` and `[0,0,0,-x,-y,-1,b*x,b*y,b]` to an `8×9` DLT matrix. Use SVD with its full right-null vector, reshape it to `Hn`, then denormalize `H=Tdestination⁻¹*Hn*Tsource`. A thin decomposition omitting the ninth right-vector is insufficient. Do not solve normal equations or divide by an arbitrarily tiny `H22` to force a preferred scale.

Use float64 through the solve/inverse and coordinate generation. PROPOSED GATES: require DLT rank eight and `sigmaMax/sigmaMinNonzero<=1e10`; require the normalized `Hn` invertible with 2-norm condition number at most `1e10`; reject nonfinite results. Check forward and backward corner reprojection error against `max(1e−6,1e−9*sourceDiagonal)` source pixels and the analogous destination tolerance. Do not apply a condition-number threshold to an unnormalized pixel matrix, whose units/translations can inflate that number harmlessly.

Normalize `G` by a nonzero scale and evaluate its denominator at all four destination corners. Require one common nonzero sign and `min(abs(zCorner)) > 1e−10*max(abs(zCorner))`. Because `z` is affine in destination coordinates, this excludes a pole anywhere in the rectangle. A failed inverse, pole or reprojection test returns `INVALID_MAP`, not a plausible-looking affine substitution. A valid projective map has the expected positive orientation; do not accept a reflection by taking an absolute determinant.

If the source quad is exactly the source-center rectangle and base dimensions equal source dimensions, bypass the matrix solve: turn zero dispatches to byte-identical copy; nonzero turns dispatch to the exact index permutation, including matching float32 masks. A 180° turn must not accidentally take the unchanged-copy branch merely because final dimensions equal source dimensions. Exact identity/quarter-turns do not need a lossy matrix/color roundtrip. A bilinear interpolation of four source corners is generally not the same map as a homography; use the projective denominator even for a visually mild trapezoid.

## 5. Manual curve: an explicit direct inverse ruled surface

DESIGN `manual_ruled_v1` adopts the inexpensive two-edge concept, but not the upstream mesh/inset renderer [M3]. It models two curved horizontal boundaries joined by straight rulings. It is not arbitrary 3D sheet reconstruction and it cannot model every crease, varying interior bend or occlusion. User-facing handles are points on the top/bottom curves at Bézier parameter `t=0.5`, not the quadratic control points themselves.

Preflight requires both serialized normalized midpoint coordinates finite and in `[0,1]`, the source binding valid, and the quad valid under section 3. Nonfinite/out-of-range handles or depth are `INVALID_INPUT`, not processing fallback candidates. Derived Bézier control points may lie outside the photograph; validity is decided by the actual curve/map bounds, not by clamping those derived controls.

For top endpoints `(P0,P2)=(TL,TR)` and on-curve midpoint `Mtop`, compute `Ctop=2*Mtop−0.5*(P0+P2)`. For bottom endpoints `(BL,BR)`, use the same equation with `Mbottom`. Evaluate `Q(t)=(1−t)²*P0+2*t*(1−t)*C+t²*P2`. This guarantees `Q(0.5)=M`; using `M` directly as `C` halves the intended sagitta. Side edges are the straight segments TL→BL and TR→BR.

For derivatives use `Q'(t)=2*((1−t)*(C−P0)+t*(P2−C))`. A coordinate component's interior extremum is at `t=(P0−C)/(P0−2*C+P2)` when that denominator is nonzero and `0<t<1`; otherwise its endpoints suffice. Inside inverse-LUT interval k, `dt/du=1/(128*(l_(k+1)−l_k))`; use the chain rule for `T'(u),B'(u)`. These equations fix both true-boundary bounds and direct-map derivative units.

Build a separate float64 arc-length LUT for each boundary: `t_k=k/128`, `q_k=Q(t_k)`, `l_0=0`, `l_k=l_(k−1)+|q_k−q_(k−1)|`, then divide all `l_k` by total length. Reject total length at most one source pixel, a nonfinite term, or any segment increment at most `max(1e−12,1e−12*totalLength)`; do not replace a degenerate curve with a uniform LUT. The source implementation's permissive fallback is not this product's error policy.

To invert normalized arc length `u`, return exactly 0/1 at its endpoints; otherwise find consecutive knots `l_k<=u<l_(k+1)` by upper-bound search, and return `t(u)=(k+(u−l_k)/(l_(k+1)−l_k))/128`. At an internal knot either side has the same position; validate both one-sided derivatives. Define `T(u)=Qtop(tTop(u))`, `B(u)=Qbottom(tBottom(u))`. These are arc-length approximations using 128 chords, not analytic equal-arc-length claims.

For unrotated base normalized coordinates `(ub,vb)`, set `w(vb)=vb+d*vb*(1−vb)` and `F(ub,vb)=(1−w(vb))*T(ub)+w(vb)*B(ub)`. Obtain `(ub,vb)` from the final-destination quarter-turn before evaluating this formula; later derivations use `(u,v)` as shorthand for this base domain. `F` already maps base destination to source; there is no root-solving “inverse” and no additional homography of its output. Require serialized `d` finite and in `[-0.95,0.95]`; do not silently clamp invalid stored parameters. Here `w(0)=0`, `w(1)=1` and `w'(v)=1+d*(1−2v)>=0.05`. The bounded depth avoids endpoint collapse but does not by itself prevent crossing boundaries or folded rulings.

No hidden inset: evaluate the full `[0,1]²` domain, including exact user-selected edges. Do not replace `u,v` with `.012+.976*u,.012+.976*v`. SOURCE: the inspected manual implementation builds a 33² grid with a 1.2% inset on each side, then renders through a 129² triangle mesh and clamped bitmap shader; it also uses a 1.5-source-pixel straightness heuristic [M3]. Those choices crop margins and use different interpolation from this direct inverse map. They are not required to reuse the underlying idea and are not inherited by `manual_ruled_v1`.

Exact straight dispatch: when depth is exactly zero and each serialized normalized handle equals the arithmetic midpoint of its normalized chord endpoints, execute the perspective homography with identical target dimensions. Construct default/reset handles by that exact normalized arithmetic so the branch survives persistence without a pixel-denormalization comparison. This is an explicit algorithm branch, not a claim that a straight ruled bilinear surface equals projective rectification. Do not use the upstream 1.5px heuristic: subtle real curvature must not disappear with image resolution. A future tolerant snap requires an explicit UI action or separately versioned parameter; near-straight controls otherwise use the ruled-surface branch.

Validation evaluates the actual curved boundaries, including quadratic coordinate extrema in `(0,1)`, not just the corner quad. The curve endpoints, derivatives, source bounds and topology must pass section 10. In particular top/bottom handles can each be inside a valid quad while causing their curves to cross; reject that recipe rather than clipping the handles or straightening it silently.

Automatic edge profiles are deferred. SOURCE: the reference estimates brightness crossings from an expanded rectified page band, bins them and fits a profile [M3]. Visibility assumptions, exact fit/regularization, saturation policy and interaction with handles would all need an independently specified/versioned contract and fixtures. No “automatic manual correction” toggle is shipped on the strength of this outline; manual handles remain the complete deterministic fallback. Do not copy an approximate profile algorithm and report source parity.

## 6. Canonical bilinear sampler and one-pixel boundaries

DESIGN `bilinear_white_v1`: given finite source coordinates `(xs,ys)`, let `i=floor(xs)`, `j=floor(ys)`, `a=xs−i`, `b=ys−j`; use weights `w00=(1−a)*(1−b)`, `w10=a*(1−b)`, `w01=(1−a)*b`, `w11=a*b`. For each RGB channel, sum the four weighted neighbors in float64, left-associated in order 00,10,01,11 without fused multiply-add in the byte-reference oracle, and apply `roundByte(z)=clamp(floor(z+0.5),0,255)` exactly once. Arithmetic is on encoded sRGB samples, not linear radiance. Reject nonfinite coordinates before `floor` or integer conversion.

Each neighbor independently returns its source sample if `0<=x<Ws` and `0<=y<Hs`, otherwise constant `255`. Do not clamp the coordinate to an edge, zero the entire sample because one neighbor is outside, or make an in-bounds integer-edge pixel white because its zero-weight neighbor lies outside. For extreme finite coordinates outside `[-1,Ws]×[-1,Hs]`, return the outside constant without a potentially overflowing integer conversion; the same shortcut follows the declared constants for masks and source-parity samplers.

“One-pixel border” means bilinear support spans one center interval: at `xs=−0.25,ys=0`, 25% of support is outside; at `xs=−1,ys=0`, the result is entirely outside. It does not mean adding an artificial white frame, erasing the first/last source row, or rounding coordinates before sampling. With an exact last-center sample `(Ws−1,Hs−1)`, the output is that source pixel.

Protection uses the identical `(xs,ys)` and weights, original float32 samples in `[0,1]`, and neighbor outside value **1**, producing a clamped float32 result without byte quantization. Page coverage is separate: soft coverage can use the same sampler with outside **0**; a hard semantic label map uses nearest-neighbor index `floor(x+0.5),floor(y+0.5)` with outside label zero, never an RGB sampler by accident. No page-coverage threshold is applied to whiten RGB in the baseline geometry path.

Define geometric source support `V(xs,ys)=sum(w_ab*inBounds(i+a,j+b))`, independent of whether source RGB is black/white or a learned page mask is confident. A warped page mask measures estimated document coverage, `V` measures source availability, and protection measures restrictions on later photometric modification. None is a substitute for the others. An outside protection value of 1 preserves the white geometry result from subsequent appearance changes; it does not preserve nonexistent source content or prevent resampling.

The white-border product sampler differs from upstream numeric parity: UVDoc samples source `[0,1]` with zero padding, therefore black outside [U2]; SyntheticDoc samples source `[-1,1]` with zero padding and then denormalizes, therefore `0.5` gray outside [S2]. At fractional boundaries the outside contribution is black or gray per neighbor, not a post-render paint operation. SyntheticDoc's gray is 127.5 before quantization; product byte rounding yields 128, whereas its Python `astype(uint8)` truncation yields 127. Preserve upstream float/truncation behavior in a source-parity oracle and use a distinct product variant ID for white/roundByte rendering.

There is no extra photometric strength blend in geometry. Protection is transformed first and used once by later supported photometric stages. A coordinate-generating model is not allowed to consume an appearance-protected mask as if it were a document boundary mask. All mode-off and exact-identity paths preserve source pixels without enhancement.

## 7. Rough crop, crop-origin composition and masks

`ROUGH_CROP_DEWARP` begins with a confirmed axis-aligned source extraction, not a forced perspective flattening. If deriving a proposal from a valid quad, use `x0=max(0,floor(min cornerX))`, `y0=max(0,floor(min cornerY))`, `x1=min(Ws,ceil(max cornerX)+1)`, `y1=min(Hs,ceil(max cornerY)+1)`, then `Wc=x1−x0`, `Hc=y1−y0`; any user expansion is an explicit integer margin, default zero. Validate `Wc,Hc>=2` and bounds before extraction. Accept and persist the final integer rectangle, rather than regenerating it from a changed detector/preview.

If the grid addresses crop centers, map `xc=(gx+1)*(Wc−1)/2`, `yc=(gy+1)*(Hc−1)/2`; source centers are `xs=x0+xc`, `ys=y0+yc`. Crop origin is added after denormalization, not multiplied by grid normalization. A model input resize does not change the fact that the grid's normalized values address the original crop. Reusing `(Ws−1,Hs−1)` here incorrectly expands the selected page back over the full photograph.

The crop is an intentional content boundary. When sampling a crop-local map, each neighbor must first lie in the accepted crop; neighbors outside it use the sampler's outside value even if a corresponding pixel exists elsewhere in the full source. Direct original-buffer sampling may avoid an intermediate crop allocation, but it must enforce this crop support domain and then translate allowed indices by `(x0,y0)`. The same support domain applies to RGB, protection and coverage; otherwise border pixels can leak unwanted adjacent pages or photographic background back into a confirmed crop.

Transform source protection through that exact crop-local inverse map with outside 1. A detector-derived page mask requires its own detector-to-source transform before the final warp; it is never directly stretched to the photograph or passed as protection. A grid can be reused for RGB and every aligned scalar plane, but interpolation/outside values remain typed metadata. A neural image-only output without the identical paired-mask transform cannot satisfy geometry-first protection and must be disabled for protected recipes at preflight.

The default dewarp target has the accepted crop's raster aspect. Neither the original photograph's aspect, the neural input tensor aspect, nor coarse-grid row/column counts establish physical paper shape. A user-selected fixed ratio is permitted as an explicit assumption. Perspective-before-dewarp is a different preprocessing/provider variant requiring its own quality/parity evaluation; it is not implied by selecting `ROUGH_CROP_DEWARP` and is not the inspected SyntheticDoc recommendation [S1].

## 8. `detectDocQuad`: complete proposal extraction and validation

DESIGN API: `detectDocQuad(orientedSource, providerIdentity)` returns `DetectionProposal(quad:QuadPx?,score:Double?,detected:Boolean,reason:String?)` in original oriented-source pixel centers. The mandatory no-model/manual path returns `(null,null,false,"DETECTOR_UNAVAILABLE")`, while the editor independently offers full-frame reset. Inference/output/map errors, low score and invalid geometry have distinct reason codes; no failure returns a fabricated successful full-frame detection.

The optional `docquad_heatmap_minimal_v1` is an independent minimal decoder for the pinned DocQuad contract [M1,M2], not a port of every upstream heuristic. Preflight requires verified asset identity, tensor names, float32 type, exact output shapes and installed/validated status. Its source-parity preprocessing is RGB `/255`, channel-first `input:[1,3,256,256]`, black centered aspect-preserving letterbox; named outputs are `corner_heatmaps:[1,4,64,64]` in TL/TR/BR/BL order and `mask_logits:[1,1,64,64]`. Read outputs by name, not tuple position. Reject every nonfinite input/output logit.

For the full oriented source, `s=min(256/Ws,256/Hs)`, `ox=(256−s*Ws)/2`, `oy=(256−s*Hs)/2`; do not round these to integer resized dimensions. Reproduce the pinned Android `Canvas.drawBitmap` float destination rectangle `(ox,oy,ox+s*Ws,oy+s*Hs)` with its filter/dither/antialias policy for source parity [M2]. A portable deterministic bilinear preprocessing variant must declare how it replaces those platform details and pass paired input-tensor tests; it is not automatically identical because its letterbox dimensions match.

For the portable raster reference, destination tensor index `(i,j)` has an edge-frame center `(i+0.5,j+0.5)` and samples source center `((i+0.5−ox)/s−0.5,(j+0.5−oy)/s−0.5)`; source-neighbor interpolation is clamp-to-source at the resized-image edge, black outside the destination image rectangle. Choose rectangle membership by the destination center, then sample. This explicitly fixes raster behavior; do not silently use a geometry white-border sampler to construct detector input. It is a versioned preprocessing adaptation, not a bitwise Canvas parity claim.

The head's decoded coordinate is a nominal model coordinate `m`, with heatmap cell `(ix,iy)` located at `((ix+0.5)*4,(iy+0.5)*4)`. The pinned coordinate decoder uses `m=s*q+offset`, inverse `q=((mx−ox)/s,(my−oy)/s)` [M2]. Retain that trained/head convention in this minimal decoder; do not add or subtract a half pixel by analogy with the raster resize formula above. Nominal head coordinates, raster sample centers and normalized user controls are explicitly different interfaces. If changing the decoder to an edge-aligned label convention, give it a new ID and measure the changed corner bias; neither convention is an undocumented universal correction.

For each channel, scan row-major, selecting the first strict maximum logit (`>` keeps the earliest tie). At an interior peak, compute x-offset `deltaX=0.5*(L−R)/(L−2*C+R)` only if `L−2*C+R<−1e−12`, clamp it to `[-0.5,0.5]`; otherwise mark that axis invalid with offset zero. Repeat for y with top/center/bottom values. SOURCE: an upstream comment gives the denominator sign incorrectly; the executable negative-concavity condition is authoritative [M2].

If either axis has a valid parabolic fit, use `(ix+0.5+deltaX,iy+0.5+deltaY)`. If both are invalid, use the clipped 5×5 window around the peak, weights `exp(logit−windowMax)`, and weighted mean of `(x+0.5,y+0.5)`; fall back to the peak center only if the reduction is nonfinite or has zero weight. Multiply by four, invert the recorded letterbox, and validate the resulting labeled source quad using section 3. Border peaks are not specially snapped into a plausible page.

Compute stable sigmoid with `1/(1+exp(−z))` for `z>=0`, otherwise `exp(z)/(1+exp(z))`. Let `pmin` be the minimum sigmoid of the four peak logits. At each heatmap cell center `(i+0.5,j+0.5)`, compare the mask foreground `maskLogit>0` against point-in-convex-quad inclusion using the decoded nominal quad divided by four; include polygon-edge points. Let `IoU=intersection/union`, zero if union is empty. Return the uncalibrated ranking score `pmin*IoU`.

PROPOSED GATES: require `pmin>=0.5`, `IoU>=0.5` and `score>=0.35`, in addition to all quad-validity checks. A failed proposal returns `detected=false,quad=null` and its specific reason; an optional debug overlay is not accepted geometry. These starting thresholds are not calibrated probabilities or a demonstrated optimum. Do not reuse the upstream commented-out suspicious-result block as if it were enforced. This minimal decoder deliberately omits PCA mask rectangles, rotation retries, temporal smoothing and full-resolution edge snapping; adding any is a separately specified decoder variant, not a hidden fallback.

If a provider first downsizes or rotates analysis input, persist its additional exact transform and compose its inverse before returning source controls. Reversing the detector letterbox is not reversing a dewarper's preprocessing. Similarly, to inspect a source point in the heatmap mask use its declared nominal head transform and `h=m/4−0.5`; never resize 64² mask logits anisotropically to the full photograph and call that the same transformation. Detection is O(256²+4*64²) outside model cost and does not require a full-resolution float map.

## 9. Learned map extraction: common equations, provider-specific contracts

A `GeometryProvider` map result declares source binding/crop domain, grid shape and layout, component order, normalized-coordinate convention, destination-domain convention, interpolation, padding, integrated stages and asset identity. A tensor that happens to have two channels is not sufficient evidence. Extract → verify shapes/finiteness → convert into this declared map → validate topology/support → generate coordinates → sample RGB/masks. Do not clamp an invalid normalized grid into `[-1,1]` before validation.

For a channel-first normalized backward grid `G:[1,2,Gh,Gw]`, component 0 is x and component 1 is y. Apply the final-to-base quarter-turn to obtain `(ub,vb)`, compute `fx=ub*(Gw−1)`, `fy=vb*(Gh−1)`, and bilinearly interpolate grid nodes at `(fx,fy)` to obtain `(gx,gy)`. At turn zero this is `fx=xo*(Gw−1)/(Wo−1)`, `fy=yo*(Gh−1)/(Ho−1)`. This is corner-aligned upsampling in the base page, composed with output rotation; rotation neither transposes the model's tensor contract nor rotates the model input. For active source/crop size `(Wa,Ha)`, denormalize `xa=(gx+1)*(Wa−1)/2`, `ya=(gy+1)*(Ha−1)/2`; then translate its crop origin when applicable. Both upsampling and source sampling correspond to `align_corners=True` [G1].

Do not substitute half-pixel map interpolation or `align_corners=False` source normalization `xa=((gx+1)*Wa−1)/2`. The latter maps −1 to −0.5 instead of 0 and alters boundary support/text positions. A normalized identity grid has `Gx[j,i]=2*i/(Gw−1)−1`, `Gy[j,i]=2*j/(Gh−1)−1`; it must map every destination center to the corresponding corner-aligned active-source center, regardless of output resolution.

SOURCE UVDoc original [U1,U2]: oriented RGB converted to float `[0,1]`, anisotropic OpenCV linear resize to width 488, height 712, tensor `[1,3,712,488]`, no letterbox or ImageNet normalization. Use first output `point_positions2D:[1,2,45,31]`; ignore the auxiliary 3D head for rendering. The map refers to the original input source, not the 488×712 raster. The demo renders at original source dimensions and truncates float output to uint8. Product `uvdoc_grid_white_v1` retains the map equations but uses explicit product target dimensions, validation and white/roundByte sampling, and is not pixel-for-pixel demo parity.

SOURCE SyntheticDoc original coarse [S1,S2]: first accept a rough crop; use checkpoint `image_size=[720,512]` as height,width and `bm_out_size=[31,45]` as rows,columns. The expected map is **`[1,2,31,45]`**, not UVDoc's `[1,2,45,31]`. Its RGB preprocessing is Pillow/torchvision `Resize`, `ToTensor`, then `(I/255−0.5)/0.5`; pin resize/antialias library behavior for parity, not an assumed OpenCV equivalent. Check actual checkpoint metadata/exported shapes instead of inferring axes from its filename.

Extract `bm_map`, ignore `shadow_map` in geometry-only execution, use corner-aligned map upsampling and source sampling, then the crop-origin formula in section 7. The reference outputs the original crop dimensions. Its shadow correction is a separate photometric division path; do not enable it inside geometry-first execution or treat it as protection/coverage. Turning shadow application off does not establish that the unused decoder stops computing. Pruning that head is an export/parity task, not a measured optimization.

SOURCE wrapper differences [P1]: the inspected PaddleX UVDoc runner is an image-output contract with its own channel handling and internal resizing, not a drop-in external coarse-grid provider. Never apply a second dewarp sampler to an already rectified image. An image-only wrapper is unavailable for protected geometry unless it returns the exact paired transform or paired mask result. A different detector, segmentation head or map provider must supply its own spaces/normalization/cropping/outputs; UVDoc assumptions do not generalize merely because its paper is cited.

Maintain two separate oracles: upstream float/source-parity behavior for conversion checks, and the product map/sampler contract for application results. Establish exported CPU float map parity before delegate/quantization work, then assess coordinate drift and document content separately. Neither successful loading nor reported desktop inference times establishes target-device speed, memory, thermal stability or geometric quality. Exact asset rights, hashes and runtime gates remain in [MODEL_PROVIDERS.md](MODEL_PROVIDERS.md).

## 10. Topology, local stretch and visibility acceptance

Never return an image from a NaN/Inf grid, collapsed cell, reflected/folded patch, nonlocal overlap or self-intersecting boundary. An attractive output or high detector score cannot override these checks. Validate before image sampling/publication; validate the map actually used by the renderer, including crop normalization and any composition. Expected orientation is fixed positive by the identity in x-right/y-down coordinates, not chosen from the map's majority sign.

For a bilinear cell, let `p00,p10,p01,p11` be source positions and `F(r,s)=p00+r*a+s*b+r*s*c`, where `a=p10−p00`, `b=p01−p00`, `c=p11−p10−p01+p00`. Derivatives are `Fr=a+s*c`, `Fs=b+r*c`; `J(r,s)=cross(a,b)+r*cross(a,c)+s*cross(c,b)`. Check **all four cell corners**. J is affine, so its corner extrema bound the whole cell; two triangle areas or the center determinant alone do not. Reject any nonpositive/uncertain corner before computing positive-scale statistics.

For comparable tolerances, first divide source coordinates by `(Wa−1,Ha−1)` in the active source/crop frame, and multiply `Fr` by `Gw−1`, `Fs` by `Gh−1` to express derivatives against the whole unit destination domain. PROPOSED GATES: let `Jref` be the median of all positive corner determinants; require every corner `J>max(1e−10,1e−4*Jref)`. This is scale-relative collapse rejection, not an empirical quality score. Reject unreasonable dimensions separately before normalizing.

For each cell in the same units, let `M` be the maximum Frobenius norm of its derivative matrix at the four corners and `mJ` its minimum determinant. The norm is convex in cell parameters, so `M` bounds the whole cell; singular values satisfy `sigmaMax<=M`, `sigmaMin>=mJ/M`, and anisotropy is at most `M²/mJ`. PROPOSED GATES: `M<=100`, `mJ/M>=1e−4`, `M²/mJ<=1000`. These conservative sufficient tests can reject a usable extreme view; report rejection and offer manual correction/recapture rather than changing the limits silently. Test exact threshold behavior and record distributions before tightening or relaxing them.

Positive local Jacobians alone do not replace global checks. Build the ordered outer polyline of grid nodes, test every nonadjacent boundary segment for crossing, overlap or non-endpoint touch, and reject any self-intersection. A positive-J bilinear cell maps onto its convex corner quadrilateral. Use a spatial AABB index to enumerate candidate cell pairs, then robust convex-polygon intersection/separating-axis tests: distinct cells must have disjoint interiors; adjacent cells may share only their prescribed edge/vertex, and nonadjacent cells must not touch. Reject uncertain predicates instead of accepting nearly coincident sheets. Do not test only pairs that are far apart in a row; a wrap can overlap cells in another row.

Manual direct-map validation must not pretend that sampling a 33² grid proves its actual nonlinear map safe. On the union of top/bottom arc-LUT breakpoints, each `T(u),B(u)` is a quadratic polynomial in u; let `D(u)=B(u)−T(u)`. Since `Fv=w'(v)*D` and `Fu=(1−w)*T'+w*B'`, `det(Fu,Fv)/w'=(1−w)*cross(T',D)+w*cross(B',D)`. Each endpoint-in-w expression is cubic in u. Evaluate each cubic at interval endpoints and every real root of its quadratic derivative inside the interval, with both one-sided values at LUT breaks. Require the same positive scale-relative determinant margin; this certifies orientation over all v because `0<=w<=1` and `w'>=0.05`.

More precisely for manual admission, compute `Jref` as the median of positive actual normalized Jacobians on the fixed 129×129 domain lattice; a nonpositive sampled derivative already rejects the map. On each joint LUT interval let `qmin` be the minimum of both cubic expressions above; `mJ=(1−abs(d))*qmin` is a conservative full-interval lower bound. Require `mJ>max(1e−10,1e−4*Jref)`, then use this mJ in the stretch gates. For a cubic `c0+c1*u+c2*u²+c3*u³`, stationary roots solve `3*c3*u²+2*c2*u+c1=0`; handle linear/constant degeneracies, use a cancellation-resistant quadratic solver, and conservatively reject unresolved multiple-root/predicate uncertainty. Evaluate polynomials with interval bounds when deciding a near-threshold sign.

For manual stretch gates, bound derivative components over each u-interval/v-domain by outward-rounded polynomial interval arithmetic; use determinant lower bounds and Frobenius upper bounds as above. Subdivide inconclusive intervals up to depth 20; an unresolved gate is `INVALID_MAP`, not a pass. Check the four true boundary curves for simplicity with endpoint-aware quadratic-Bézier/line intersection predicates; de Casteljau convex-hull subdivision may certify separation, but a depth-32 or normalized-box-width `1e−9` unresolved intersection must reject. Only the known common endpoints of adjacent boundaries are allowed. Positive interior Jacobian plus an injective oriented boundary supplies the global one-to-one condition for this continuous piecewise-smooth disk map; additionally run a sampled-grid overlap diagnostic for implementation regressions, without representing that diagnostic as the proof.

For perspective, a valid convex quad and pole-free invertible homography establish injectivity without approximating the map by bilinear cells. To apply the same stretch policy, express G in unit destination/normalized active-source coordinates. With numerators nx,ny and denominator z, `Fx=((G00*z−nx*G20)/z²,(G10*z−ny*G20)/z²)` and `Fy=((G01*z−nx*G21)/z²,(G11*z−ny*G21)/z²)`; `J=det(G)/z³`. Bound z and derivative numerators over the rectangle, use conservative positive determinant/Frobenius bounds and the same gates, subdividing inconclusive rectangles to depth 20. Define Jref by the same 129×129 analytic-Jacobian sample median as manual mode; unresolved bounds reject. Actual perspective extent extrema occur at the four corners because a linear-fractional coordinate has no interior extremum on a pole-free convex rectangle.

PROPOSED VISIBILITY POLICY `geometry_visibility_v1`: first reject any actual map extent more than 0.25 active-source pixels outside the valid center rectangle; use exact node extrema for bilinear maps and quadratic-edge extrema for the manual surface, whose convex ruling weights cannot exceed those edge extrema. Then evaluate geometric support V on a fixed 129×129 corner-aligned destination-domain lattice, requiring mean V at least 0.995 and minimum V at least 0.75. No coordinate clamping is allowed to make this pass. Record min/mean support and the grid/boundary/stretch diagnostics. The lattice support score is an operational sampling gate, not a proof that all visible content is retained.

An optional page-coverage mask can identify uncertain photographic background for the editor, but does not override a valid user selection or automatically whiten missing/low-confidence regions. Default manual and perspective paths do not require a learned mask. A visible curved page with valid geometry can be resampled; hidden content remains hidden. If required visible boundaries extend outside the photograph, reject faithful full-page flattening or let the user explicitly select a smaller crop; do not label synthetic white padding as recovered paper.

## 11. Failures, admission, cancellation and complexity

Preflight checks source identity, dimensions, strides, rectangle bounds, mask alignment/range, output size, serialized controls, provider/mask capability and checked Long allocation sizes. Reject invalid inputs as `INVALID_INPUT`; reject unavailable/gated providers as `UNAVAILABLE`; rejected geometric solutions are `INVALID_MAP`. Cancellation, invalid input, source/storage failure and admission/resource rejection never invoke fallback or publish newly generated pixels.

For processing/map/provider failure, default `FallbackPolicy.FAIL` returns no new image. Explicit `KEEP_STAGE_INPUT` returns `DEGRADED`, the exact complete failed-stage input, warning/provenance, and terminates downstream stages. A dewarp failure retains the accepted integer rough crop because crop and dewarp are recorded separate stages; a manual or perspective failure retains that geometry stage's source input. Do not resize the fallback merely to disguise its aspect/dimension difference from requested output. Keep its matching mask if retained; no downstream appearance executes. Export rejects degraded results until the user explicitly accepts an execution snapshot naming the omitted stages.

For that exception, persist a verified lossless EXPORT-purpose fallback raster and execution record under a retained RenderId before review. Freeze both requested and actual dimensions, KEEP_STAGE_INPUT, acceptedRenderId/execution hash and all omissions. A source/crop fallback that omitted user rotation must be reviewed unrotated; differing actual dimensions require renewed size/physical-PDF/resource review, not an implicit fit to OutputSpec. The snapshot pins and reuses those exact pixels without rerender/resizing/rotation. Missing/changed accepted pixels fail. See DATA_MODEL_AND_STORAGE for schema/lifetime; this exception never approves an invalid serialized recipe, cancellation or a resource/storage failure.

Never switch a failed manual curve to perspective, a failed neural map to another model, or a failed detection to detected-full-frame under the original success label. The exact straight-control branch is a documented requested algorithm dispatch, not a failure fallback. A failed base geometry does not execute its requested output rotation over the retained stage input; record that omission in the degraded execution snapshot. Record requested/executed IDs, source/crop/base/final-destination spaces, target rule, outputQuarterTurns, resolved dimensions, provider hash/backend/precision, sampler, gate version, warnings, and generation/revision. A successful old render cannot replace a newer editor selection.

For `N=Wo*Ho`, RGB rendering is O(N) time and output storage `3N` bytes; a float32 protection plane adds `4N` only when present. Do not allocate a dense two-channel float map costing `8N` bytes: at 12,000,000 pixels it is 96,000,000 bytes before images/activations; a float RGB source adds another `12N`. Keep a learned coarse grid, produce coordinates per row or bounded strip, and sample original RGB8 directly. Source-buffer tiling must account for nonlocal map reads; a destination strip does not imply its corresponding source pixels are local.

Perspective setup is constant-sized SVD; coordinate generation is O(N). Manual LUT setup is O(128); precomputing `T(ub),B(ub)` at Wg base-column positions costs O(Wg*log 128) and O(Wg) storage; w at Hg base-row positions costs O(Hg). Each final pixel then uses O(1) evaluation with those axes permuted/reversed by outputQuarterTurns; do not assume a constant w along a final row for odd turns. Learned setup uses O(Gh*Gw) storage; four-node lookup per destination pixel and the quarter-turn composition are O(1). Exact cell-pair topology checking with spatial indexing is typically O(K log K+P), K cells and P candidate pairs, but worst-case O(K²); enforce a deterministic `P<=1,000,000` product admission limit and return `RESOURCE_LIMIT` if exceeded, never skip checks. Manual/perspective adaptive interval and boundary validation additionally share a limit of 100,000 processed subdivision boxes per render, checked before enqueuing more work, and retain the stated depth bounds. Exceeding this work budget is `RESOURCE_LIMIT`; unresolved numerical validity at a depth limit is `INVALID_MAP`. Use bounded depth-first storage, not a materialized full subdivision tree.

Run inference/geometry off the UI thread. Check cancellation at stage boundaries, at least each output row, and during long topology loops. Parallel row computation must preserve per-pixel operation order/rounding and exclusive buffer ownership; never publish a partial output. GPU/native acceleration, lower precision and antialiasing beyond this bilinear reference each require their own equivalence/quality gates. Bilinear minification can alias one-pixel features; this specification does not assert that source resampling alone guarantees legibility.

## 12. Deterministic fixtures and acceptance vectors

These fixtures are requirements for future tests, not tests already run in an application. Store generators and expected coordinates/bytes independently of the implementation under test. Float64 math-unit tolerance defaults to `1e−9` in normalized coordinates or `1e−6` source pixels; byte output is exact for the specified scalar/identity fixtures. Exported-model tolerances must be chosen from measured paired errors before admission, never invented from a screenshot.

1. **Scalar sampling and typed masks.** Source scalar image `[[0,100],[200,255]]` sampled at `(0.25,0.5)` is `119.375`, roundByte 119; at `(−0.25,0)` it is `63.75`, byte 64 with white border; at `(1.25,0)` it is `138.75`, byte 139; at `(−1,0)` it is 255. Protection `[[0.2,0.6],[1,0]]` gives 0.525 at `(0.25,0.5)` and 0.4 at `(−0.25,0)`; geometric support there is respectively 1 and 0.75. This catches whole-sample rejection, edge clamping, unsigned/floor errors and coverage/protection confusion.
2. **Identity and edge extent.** A `3×2` RGB8 image containing packed row-major bytes `00 01 ... 11` hexadecimal is copied byte-for-byte by NONE; full-frame perspective has corner area 2px², natural target `3×2`, and is also exact identity. SHA-256 of the 18 raw packed pixel bytes is `7a096cc12702bcfa647ee070d4f3ba4c2d1d715b484b55b825d0edba6545803b`. This is a raw-fixture digest, not a replacement for source identity including dimensions/conversion metadata. A `401×301` full-frame quad resolves to `401×301`.
3. **Projective oracle and non-equivalence.** In a `160×120` source, backward matrix `G=[[12,1,20],[0.5,9,10],[0.01,0.02,1]]` over an `11×11` destination gives TL `(20,10)`, TR `(127.27272727272727,13.636363636363635)`, BR `(115.38461538461539,80.76923076923076)`, BL `(25,83.33333333333334)`, and center `(73.91304347826087,50)`. Those source corners have natural target `109×75`; declared fixed ratio 1 gives `75×75`, purpose L=11 gives the test `11×11`. Solving their homography must reproduce G up to scale. Bilinear interpolation of just the four source corners instead yields center `(71.91433566433567,46.934731934731936)` and must fail this oracle.
4. **Quad failures and denominator pole.** Reject NaN/Inf, duplicates, a bow tie `[(0,0),(4,4),(4,0),(0,4)]`, clockwise-label reversal, any area at most 1px², an out-of-source corner and nearly collinear normalized correspondences beyond the conditioning gate. A synthetic backward denominator `z=1−0.2*xo` on `0<=xo<=10` changes sign and is rejected before sampling. A noisy/near-degenerate fixture must not be reported as noiseless identity.
5. **Bézier handles, LUT and depth.** Source `101×101`, corners `(0,0),(100,0),(100,100),(0,100)`, top M `(50,10)`, bottom M `(50,90)` give Ctop `(50,20)`, Cbottom `(50,80)`. Symmetry makes inverse-LUT u=0.5 give t=0.5 on both edges. At `(u,v)=(0.5,0.5)`, d=0 gives `(50,50)`, d=0.4 gives `(50,58)`, d=−0.4 gives `(50,42)`, and d=0.95 gives `(50,69)`. Exact corners/edge handles remain in the rendered domain; there is no 1.2% inward movement.
6. **Manual folds and straight branch.** The same corners with top M `(50,90)` and bottom M `(50,10)` fold despite valid corners; reject. Reject d=1, d=NaN, zero-length LUT segments and a boundary self-intersection. Default midpoint handles/d=0 on a trapezoid must execute the homography, not the four-corner bilinear map. A small nonzero sagitta remains a manual map; scaling the photograph must not silently cross a 1.5px straightness threshold.
7. **All-corner Jacobian test.** Cell `p00=(0,0),p10=(1,0),p01=(0,1),p11=(−0.2,1)` has `J=1−1.2*s`: center J=0.4, bottom-corner J=−0.2. Center-only validation falsely passes; the required test rejects. Also reject a collapsed cell and an entire mirrored identity grid rather than accepting their arbitrary dominant sign.
8. **Nonlocal overlap.** Primitive grid with `i=0..16,j=0..2`, `theta_i=4*pi*i/16`, `r_j=2−j/2`, `p_ij=(3+r_j*cos(theta_i),3+r_j*sin(theta_i))` wraps twice. Its small bilinear cells have positive local orientation, but repeated boundary/cell regions must fail global checks. Test pairs across rows and distant columns, not only immediate neighbors.
9. **Crop translation and support boundary.** Crop `(10,20,5,3)` maps normalized `(−1,−1),(0,0),(1,1)` to source `(10,20),(12,21),(14,22)`. At local x=−0.25, outside support is white/protection 1 even when full-source column 9 exists. Proposal corners `(10.2,20.2)..(13.2,21.2)` produce half-open bounds `[10,15)×[20,23)` and this exact crop size; verify all four extrema and integer-max cases.
10. **EXIF normalization/asymmetric pixels.** At decode, a `3×2` source requiring clockwise normalization maps `(0,0)→(1,0)`, `(2,1)→(0,2)` and changes oriented dimensions to `2×3`. Use different channel values at every center, a non-symmetric quad and a sparse float protection plane; apply the inverse transform and compare exact coordinates/pixel identities. This establishes the oriented-source binding before geometry. It does not authorize applying EXIF again when a user subsequently rotates the page; that separate operation is fixture 16.
11. **Detector letterbox/head coordinates.** Source `400×200` gives s=0.64, offsets `(0,64)`. A decoded heatmap center `(ix,iy)=(16,24)`, zero deltas, gives nominal `(66,98)` and source `(103.125,53.125)` under the pinned head inverse; roundtrip is exact within tolerance. Portable tensor raster sample `(i,j)=(65,97)` instead addresses source `(101.84375,51.84375)`, demonstrating why raster half-pixel arithmetic must not be substituted into the trained head inverse. For a parabolic peak `L=1,C=4,R=3`, deltaX=0.25; flat/border/tied peaks exercise deterministic centroid/tie branches. A failed detector returns detected=false, never detected-full-frame.
12. **Learned grid axes/alignment.** For both grid shapes `[1,2,45,31]` and `[1,2,31,45]`, synthesize normalized identity, render active source `5×3` to `3×3`, and expect x centers `0,2,4`, y centers `0,1,2`. Corner normalized −1 maps to center 0; using align_corners=False gives −0.5 and fails. Use an x/y-asymmetric ramp to catch transpose/channel swaps. Test grid upsampling and source denormalization independently before a composed image check.
13. **Reference padding and product adaptation.** At a completely outside coordinate, UVDoc float reference is RGB zero, SyntheticDoc normalized-zero reference denormalizes to RGB01 0.5, and product RGB is white 255. At a partially outside coordinate compare weighted contributions, not just full-outside values. Reject NaN before a runtime can reinterpret it as −1. Protect a single edge pixel and prove it is warped identically rather than independently resized.
14. **Visibility, dimensions and failure snapshots.** Exercise each support/stretch/candidate-pair threshold just above/below the limit, singleton-axis rejection, checked dimension overflow, nonfinite masks, unsupported paired masks, cancellation mid-row, and provider absence. FAIL publishes nothing; KEEP_STAGE_INPUT returns exact source/crop input and DEGRADED, skips appearance, and cannot be exported without explicit snapshot acceptance. An old generation cannot overwrite the newest accepted preview.
15. **Reproducibility and real-page gates.** Hash fixture source bytes, oriented packed RGB, recipe canonical serialization, provider/exported asset, raw coarse map and final product RGB separately; include dimensions/conversion/backend/precision in the render key. Exact byte hashes apply only to a pinned deterministic variant; cross-backend neural/grid comparisons use declared measured coordinate tolerances. Add permission-cleared faint ink, colored annotations, one-pixel strokes, curved boundaries, checkerboards, partial occlusion and background-text cases. No geometry or OCR metric alone establishes preserved meaning; inspect margin/stroke retention and retain the original.
16. **User page quarter-turns — GEO-07.** With base identity geometry on a `3×2` source labeled rows `[A,B,C]`, `[D,E,F]`, `outputQuarterTurns=1` produces final `2×3` rows `[D,A]`, `[E,B]`, `[F,C]` by one source sampling/permutation. Final center `(0,0)` maps to source `(0,1)`; `(1,2)` maps to `(2,0)`; normalized final `(0.25,0.75)` maps through q1 to base `(0.75,0.75)`, source `(1.5,0.75)`. Protection rows `[0,0.25,0.5]`, `[0.75,1,0.125]` become `[0.75,0]`, `[1,0.25]`, `[0.125,0.5]`, with no byte quantization. For the raw `3×2` RGB fixture in vector 2, expect rotated byte-triplet order indices `[3,0,4,1,5,2]`; q2 yields `[F,E,D]`, `[C,B,A]`, q3 yields `[C,F]`, `[B,E]`, `[A,D]`, and four UI turns return to q0. A `401×301` base target becomes final `301×401` for q1/q3 before purpose sizing. Assert source bytes/hash/binding and source-space controls/masks unchanged, recipe/render identity changed, and another duplicated page unaffected. Repeat q1 with nontrivial perspective/manual/grid base maps using `Fbase(q1(u,v))` as the coordinate oracle, not a resampled intermediate bitmap; reject stored counts −1/4 as INVALID_INPUT.
