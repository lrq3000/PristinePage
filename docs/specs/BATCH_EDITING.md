## Intent, scope and approach

Correct different pictures efficiently when automatic orientation is wrong, and apply supported appearance/color/shadow-correction settings without opening/saving every page separately. A batch covers the currently open album/document only. Select all active pages or any subset, and change selection repeatedly during one session.

Selected approach: per-page draft recipes plus one Done commit. Immediate save per click contradicts the requested final Done and safe Cancel. Copying one complete recipe to every page loses independent turns/crops/settings. Reuse existing immutable recipes, quarter-turn geometry, revision checks, Undo and bounded renderer; no generic workflow engine or new Gradle module.

The user specified cumulative rotation, mutable selection, one Done, batch correction settings and current-album scope. Preview, Undo/Redo, Cancel, field-scoped changes, immutable originals and all-or-nothing recipe save were safeguards explicitly included in the approved design. Layout/icons and supporting interface names below are implementation-owner choices, not user-selected artwork. Crop/corner/curve editing stays per-page; batch crop/control-point copying and cross-album saves are excluded. No new automatic-orientation algorithm, color slider or model is promised by this amendment.

## Selection and per-page drafts

1. Enter from document overview, capturing stable DocumentId/documentRevision, active PageIds, source bindings, per-page recipe revisions and accepted recipes. Page identity is never a list index. Provide Select all, clear selection and accessible individual toggles. “All” means that captured page set; membership changes invalidate commit rather than silently including new imports.
2. Keep selection separate from per-page drafts/history. Every edit command captures its then-current selected PageIds. Deselecting a page retains its earlier edits; newly selecting a page does not replay past commands. Disable edit actions for an empty selection.
3. Rotate90° adds one clockwise quarter-turn to each selected draft's current valid q: `(q+1) mod4`, not “set every page to90°”. Existing nonzero orientations accumulate independently. Four turns restore q. Serialized values outside0..3 still reject; the command rule does not relax the codec. Appearance changes and automatic suggestions never silently overwrite manual turns.
4. Show effective per-page rotations/settings and thumbnail preview/pending/error states. Mixed selected values show Mixed, never a guessed shared value. Exact draft/generation keys reject stale previews. Queue/admit rendering under existing memory limits and one expensive neural session; no concurrent full-resolution decode of every page or fake successful preview.
5. Session Undo/Redo affects the previous command's original PageIds even if selection now differs; selection remains independent. Cancel discards all pending session edits, not just selected pages, without modifying accepted recipes/originals. Dirty navigation offers Keep editing, Discard or Done. Existing activity-recreation draft retention applies to the batch.
6. Done saves all pages whose final canonical recipe differs from entry, including deselected pages. Unchanged/net-unchanged pages get no revision. With no effective changes, Done closes without a repository call, documentRevision increment or Undo entry. Four turns alone therefore do not create a change or repeated pixel resampling.

Canonical example, initial q=0: select A,B,C → Rotate90° → select B,C → Rotate90° → Done. Save A:q1 (+90°), B/C:q2 (+180°), D:q0 unchanged. A still saves although deselected. The same relative rule applies to initially nonzero q.

## Appearance/color/shadow settings

Apply supported, actually implemented appearance methods and typed parameters to the current selection through the same session. A later command replaces its named setting on those pages; strengths do not add repeatedly, and no whole source-page recipe is copied. Different subsets can finish with different methods/values.

Preserve each page's turns, base geometry, crop/curve controls, masks and unrelated settings. Existing Looks presets retain the exact [UX_SPECIFICATION](UX_SPECIFICATION.md) mappings, including required binary/detail changes; show all affected fields/pages before confirmation. No enhancement remains the full photometric bypass. A single parameter edit preserves all other fields. Missing/incompatible selected controls are explained instead of guessing a cross-method conversion.

Prevalidate a selection-wide command before changing drafts: invalid/unsupported commands change none of those drafts and identify affected pages/reasons so selection/settings can be revised. Revalidate all changed final recipes at Done. Missing providers, unsupported masks, integrated-stage conflicts or output/resource incompatibilities never silently skip pages, remove masks, substitute another method or save only a valid subset. Retain drafts for correction. U-01 neural implementation/rights/runtime gates still apply; batch controls cannot turn gated methods into implemented features.

## Persistence and rendering contract

Use only existing `geometry.outputQuarterTurns` per page. Original bytes/SourceId/SourceBlobId/byte-pixel hashes, decode/EXIF provenance, source-space controls and source-aligned masks do not change. Compose the quarter-turn into the inverse map once for RGB/protection/coverage; odd turns swap target aspect before sizing. No destructive JPEG rewrite or rotated preview becomes the original. Reuse [PIPELINE_CONTRACTS](PIPELINE_CONTRACTS.md).

Add data-owned `BatchRecipeChange(pageId:PageId, expectedRecipeRevision:Long, recipe:Recipe)` and suspend `DocumentRepository.applyBatchRecipes(documentId:DocumentId, expectedDocumentRevision:Long, changes:List<BatchRecipeChange>):DocumentMutationResult` in the existing data model/repository package. Input is nonempty, unique by PageId and contains final complete per-page recipes, not pixels/arbitrary maps/a shared orientation. App applies named-field draft changes; data validates complete final recipes/source bindings. Reuse `Applied(documentRevision,affectedPageIds,undoId)`, `Conflict(actualRevision)` and `Rejected(error)`; Conflict means actual document revision for this aggregate method.

Perform bounded recipe/capability preflight outside the write transaction. In one short Room transaction recheck document lifecycle/revision, active membership/source bindings and every expected page recipe revision; insert all changed immutable revisions, move current pointers/update pins, increment documentRevision once and add one UndoEntry with action BATCH_RECIPE_EDIT and bounded before/after references. Applied includes all changed PageIds and non-null undoId. App filters no-op drafts before the nonempty call. Duplicate/foreign/removed PageIds or invalid recipes reject the whole mutation; conflict/storage failure commits none. Existing metadata/history concepts suffice; actual DDL/recovery still require review, not an assumption of DB/filesystem joint atomicity.

Done reports saved edits only after the metadata commit. Derived previews/renders may finish later with truthful pending/error state; render failure does not imply partial recipe persistence, change originals or permit silent substitutes. Retain saved recipes and retry/edit options. Frozen exports never acquire later batch edits. Saved-batch document Undo restores every affected page as new monotonic revisions, not by overwriting history or undoing only the current selection. While Done is pending or its result uncertain, serialize/disable further edits, Undo/Redo, Cancel and duplicate Done so no later drafts are lost or a committed save is described as canceled. Revision fencing prevents repeated commits. Reconcile/read accepted state after uncertain interruption rather than blindly issuing another save. A conflict preserves the complete draft and requires a reviewed refresh/retry decision, never automatic overwrite. Session Redo reuses its original command PageIds, and a new edit after Undo invalidates the abandoned redo branch.
