### Region finding

The new branch builds candidate regions at three bounded global luminance splits (Otsu, and up to 12 code values to either side), with both polarities and four-neighbor connectivity. It constructs the convex hull from row endpoints and reduces it to four vertices only if the original hull stays within two detector pixels of all four edges. The 7% minimum extent, fill test, in-frame margins, directional labeling and existing regional support reject weak hypotheses. A second distinct supported contour is an explicit refusal. Prospective size ceilings: the existing 384-pixel analysis edge and one integer component queue plus one visited plane; no full-source working raster.

The first JUnit baseline reproduced two missed positive outlines. The first implementation recovered the oblique sheet but exposed the prior clipped-receipt shadow control as a false cap. A lower-contrast continuation of both fitted sides beyond a cap must veto the proposal even if the newly quantized component does not contain those pixels. A one-pixel gap in a supported measurement band is allowed only for region-supported candidates so isolated print strokes cannot make every other near-boundary probe fail; retain the older line-fit thresholds unchanged.

### Color boundaries

The Android adapter supplies preview RGB, averaged over disjoint integer cells before color subtraction rather than sampling only one phase of a high-frequency pattern. Keep established luminance line fits first. When they do not give an answer, compare region candidates in luminance, `(R−G+256)/2` and `(B−G+256)/2` (integer floor). These simple opponent planes retain some strong chromatic boundaries lost in the weighted luma sum; they are not perceptual color differences. Flat channels are skipped. Chromatic candidates use the region proof, not repeated legacy line fits. An explicit luminance ambiguity does not enter color fallback. Two supported candidates in different planes must agree at all four corners within four detector pixels, or the result is a refusal. Curved-page estimation continues to use its separate source-aligned luminance sampler.

### Review and publication boundary

Independent review found that a cast shadow reversing contrast could still supply a false cap on a clipped sheet, and a single newly found luminance region could mask a different color-only sheet. Both proposed regressions failed at JUnit. A second review reproduced another clipped-sheet false cap with a two-tone background; the two continued sides then had opposite contrast signs. The cap veto now checks sustained continuation of both sides, requiring each side to keep its own sign. Before accepting a new luminance region, the color planes can veto it with a different valid contour. Existing supported line proposals are retained unchanged; there is no claim of general multi-document disambiguation.

Frame detection now uses a short-lived editor ticket registered before work yields. An intervening drag, history action, save/navigation or lifecycle stop invalidates the ticket even if the user later restores identical corner coordinates. Detection borrows under the existing image allowance: charge the preview retain and a conservative 4 MiB scratch reservation, and reuse region queue/visited storage across channels. The 4 MiB is application-ledger accounting rather than measured whole-process memory. An unavailable permit or obsolete result leaves the frame unchanged. In the guided view, setting the completed flag before analysis would remove the very canvas that owns the coroutine. A paused wizard retains its preview without starting detection; the analysis effect restarts when that preview is eligible and records a completed attempt only after a current result or failure. The Android sources include a bitmap/minification witness and a guided-screen/source/preview witness; pure detector tests alone are not native evidence.
