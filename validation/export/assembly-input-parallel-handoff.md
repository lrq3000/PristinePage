## Contract and reconstruction

- The prior producer's private `assemblyInput` wrote a 32-byte tag: UTF-8 `pristinepage-export-assembly-v1` followed by an actual NUL. Next came a four-byte big-endian byte length `36` and the canonical snapshot UUID, then length `64` and the lowercase hexadecimal snapshot digest, then a four-byte big-endian page count, then length `36` and a canonical render-job UUID per page, in frozen ordinal order. Valid input size is `144 + 40 * count`, or 184–4,144 bytes for 1–100 pages. The stored job input digest is lowercase SHA-256 of these exact bytes; the separate row key is `export-assembly-v1/<snapshot UUID>`.
- The existing freeze loop uses the frozen rows in order, with distinct original page IDs. `ExportSnapshotIdentity` checks contiguous ordinals against the reviewed page list; `RenderJobIdentity` includes that original page ID in its canonical bytes, and the unique-key lookup then checks exact canonical input before reuse. Therefore valid reuse across different snapshots does not put a duplicate render ID in one assembly intent. Reject duplicate IDs, do not deduplicate or sort; retain typed `ExportSnapshotId` and `JobId`, with their existing canonical UUID checks.
- An internal object shares v1 encoding, key and digest with `RoomExportSnapshots`. `verify(expectedJobId, snapshot, row)` takes a separately authenticated immutable `ExportSnapshot` and an **already materialized** `JobRow`. Check `jobId`, exact `EXPORT_ASSEMBLY` kind/key/snapshot column and null `pageOrdinal`, then bound the BLOB before copying or hashing. Hash and parse the same copy; check the tag, exact fixed lengths, typed payload snapshot ID, canonical snapshot hash matching the expected one, ordered count equal to `snapshot.pages.size` within 1–100, exact whole extent and unique canonical render IDs. Fixed-size arrays and the proved total extent do not depend on claimed lengths. A malformed UTF-8 or other non-ASCII field cannot pass the canonical UUID or digest checks. Return a detached unmodifiable ordered list of `JobId` references. Corruption gives nonretryable `RepositoryFailure(OperationError(INTEGRITY_FAILED, false, "export_assembly_input_invalid", expectedJobId.value))`, not a status, retry, admission or cancellation result. There is no new verifier call in a job runner.
- Reuse existing types and JVM byte-buffer primitives, not a general serializer or a second wire version. `RoomExportSnapshots` still inserts the same `JobRow` inside the same transaction with the same state, ownership, order and domain identity; no new metadata write, query, schema, public API or dependency. The helper does not bound Room's original BLOB/TEXT materialization or authenticate a row against a hostile party able to replace both fields and digests. It does not prove the referenced rows exist, have the correct render kind or match the corresponding frozen pages. Even a canonical swapped list with a recomputed digest would need the later render-to-page binding check. No lease authority, state or readiness is inferred.
