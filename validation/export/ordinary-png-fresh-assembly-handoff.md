## Motivation and design

The freeze producer already persists an immutable snapshot and the v1 `EXPORT_ASSEMBLY` intent. The previous by-key reader authenticates an assembly envelope against an already-authenticated snapshot and returns ordered references, not live job authority. The public generic lease path can take over eligible jobs and does not raw-bound the full row before extraction. This new internal route combines the existing proofs without extending that public path, adding a queue, or substituting a test lease.

- **Prepare:** Begin with a snapshot ID only as a lookup key. The same database's bounded snapshot reader checks the raw header, supported lifecycle/retention, raw page rows, and immutable canonical hash and settings. Preparation refuses nonordinary profiles (not PNG, degraded fallback, masks, or nonempty asset identity), then calls `RoomExportAssemblyReads.loadForSnapshot` for the exact indexed assembly key and immutable ordinal references. The existing v1 encoder rebuilds the complete BLOB and digest outside writer transactions. There is no API accepting caller-supplied snapshot values, job IDs or arbitrary lists as authority.
- **Admit:** Accept only an opaque preparation from the same snapshot/catalog participants. The explicit suspend preflight has no implicit success default and runs outside the writer. In the transaction, compare the exact detached frozen header/page content, not current document/page/order/recipe rows. Check retention against the audit clock (`retainedUntil == now` is expired). Check the indexed key and exact snapshot/job/input BLOB/digest relationship, existing generic lease storage guard, and virgin `PENDING` profile before opening the full job. The exact admission CAS changes just job state and audit timestamp; recheck scalar guards and full `ADMITTED` row including audit data before returning the receipt. An affected-row count alone is not authority.
- **Acquire:** Accept only the same-store admission, never a bare `JobLease`. Repeat exact snapshot/job checks; require the exact admitted owner-free, deadline-free, error-free, checkpoint-free row with zero counters. Use the existing `RoomJobLeases` same-transaction writer, its currently `ALIVE` requester check, generation CAS and monotonic elapsed deadline. The post-CAS guard and full `RUNNING` row must agree with the expected owner/deadline, attempt/generation 1, audit fields and immutable input. Refused postconditions roll back; the result wraps the original admission and the exact lease returned by this guarded transaction.
- **Lifecycle ruling:** First claim requires a retained `FROZEN` snapshot, the state written by the existing freeze producer. Both phases leave the snapshot `FROZEN`; only the job moves `PENDING → ADMITTED → RUNNING`. Known canceled/failed/expired and bounded unknown states retain their distinct errors; other retained states are conflicts, including read-only `PRIVATE_READY`. No recovery, interrupted/expired-owner takeover, scheduler, or release of stored ownership is added. This route does not start a retry when a prior claim exists. If a later writer or recovery protocol needs a new state edge, it requires separate review rather than being inferred from a lease.

The envelope is unchanged. Returned references are the ordinal list persisted at preparation. This slice detects a replacement relative to that list, not a coherently substituted envelope already on disk before the first read. Exact render-job-to-page and terminal-target checks are separate. The metadata claim gives no stable render-target lifetime, synthesized pin, permission to open a file, actual PNG proof, artifact-set authority, readiness or external publication.
