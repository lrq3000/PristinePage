## Behavior and rationale

- **Host gate:** `OrdinaryPngContainer(budget).read(borrowedInput, observedLength, maxBytes, expectedPixelSize, checkpoint)` reserves its 64 KiB reusable block and 64 KiB provisional overhead before reading. It hashes every admitted byte while walking chunk headers, payload and CRC. A single physical EOF probe rejects trailing growth, not part of the byte receipt. All extents are checked in `Long` against the declared remaining bytes before payload reads. Leading unique 13-byte IHDR must match positive expected axes exactly; RGB8 or RGBA8, methods `0/0/0` only. At most 4096 chunks, including IHDR/IEND; IDAT may have empty pieces but its one contiguous run must have nonempty aggregate payload; IEND is empty and ends at physical EOF. No IDAT inflation or claim that valid CRC means valid pixels. I/O is storage failure, structural/CRC/shape mismatch is integrity failure, actual non-PNG and unsupported methods/fields are unsupported format, cap/allowance are resource limits. Cancellation is not encoded as a refusal.
- **Encoded privacy allowlist:** before IDAT, at most one of each: `sRGB` byte 0–3, `gAMA` exactly 45455, `cHRM` exactly the sRGB white point and primaries (these three also precede `PLTE`); `pHYs` exactly nine bytes with unit 0 or 1; direct-color suggested `PLTE` with 1–256 RGB triples; `eXIf` exactly a 26-byte big- or little-endian TIFF with only inline SHORT Orientation=1, zero pad and zero next IFD. Orientation absence is allowed. No text, private or unknown chunks, richer EXIF, animation, ICC/HDR or transparency chunks. Import has different format, metadata and normalization rules (including ignored ancillary chunks); calling the import filter as the proof would admit out-of-profile files. This is an output allowlist, not a claim of steganography detection, general PNG parsing or what an Android writer emits.
- **Writer:** `OrdinaryPngWriter(budget).write(image, alreadyBoundedSink, checkpoint)` borrows the complete retained `RgbImage` and the file owner's synchronous capped sink. It repeats the shared preview converter's active-row packing pattern without allocating a second packed RGB or borrowing any UI bitmap. Private opaque sRGB `ARGB_8888`, density none, exact dimensions; no resize/source metadata. It uses `Bitmap.compress(PNG, 100, ...)` (quality is ignored for PNG); `false` without a recorded sink failure is an encode refusal. The stream adapter forwards writes only, latches the original exception and rethrows it even if native compression translates it into `false` or throws something else. Wrapping sink `IOException` here would hide data-owned cap and storage distinctions. The codec does not close, flush or retain the sink; the data owner authenticates/syncs it. Private bitmap and reservations release on all exits. Cancellation is checked before packing, at each row, before and after compression; the actual bounded sink also checks its own cancellation during writes.
- **Verifier:** `OrdinaryPngVerifier(budget).verifyClosed(file, expected, cap, checkpoint)` requires stable private ownership of the closed file plus the complete expected raster until return. Opens a regular file read-only, checks encoded shape, metadata and bytes, reuses strict API28+ `ImageDecoder` (software, straight alpha, explicit sRGB, no resize/sampling, no partial acceptance). Actual MIME/animation/size, resulting size/config/color and every alpha/RGB sample are checked, excluding stride padding. Header `ImageInfo.colorSpace` is not used as encoded profile evidence. `DecodeException.SOURCE_EXCEPTION` is storage, malformed/incomplete is integrity with a distinction for whether strict header configuration finished, and no successful decode stands in for content comparison. After releasing native resources, scans the closed bytes again and requires identical byte count and SHA-256. This detects changed valid identities at the boundaries, not concurrent mutation/replacement between opens, long-term durability, or publication. API ≤27 refuses; no fallback decoder. Both codec paths share one injected `ImageAllocationBudget`; native phase estimates are `8N + 4W + 1 MiB`, plus actual encoded length for readback (`N=W×H`); checked arithmetic, ARGB byte extent and budget admission precede allocation. The caller's retained RGB still occupies its separate reservation in the same budget. Estimates are not measured upper bounds on JNI memory/PSS or cancellation latency inside uninterruptible platform calls.
- **Next join, not done:** Retain the accepted `RenderResult` and current lease/target ownership continuously around the two synchronous callbacks. `EncodedPngIdentity` is *compressed* byte length/SHA-256. It can be checked against data-owned `StagedDerived`/seal identity; the existing `DerivedFiles.readStaged` checks the staged bytes before the callback and `seal` reopens/checks them again. The current `RoomRenderFileExecution` callback returns *canonical raster* SHA-256. After exact RGB proof use the existing retained execution's raster identity (or the existing data-owned grammar when appropriate); do not return `receipt.sha256` there or duplicate the grammar in image. Preserve current `DerivedByteLimitExceeded`/cancellation routing, recovery and data-owned final proof. This worker did not change those contracts or mint `READY`.
