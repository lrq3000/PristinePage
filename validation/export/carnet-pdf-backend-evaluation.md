# Carnet PDF: reuse assessment and bounded continuation

Scope: image-only PDF of the saved album or exact selected pages, in the existing freeze → render → journal → verify → Save as / Share flow. No OCR, document editing, PDF parsing of user-supplied files, release enablement, or new dependency acquisition. Public sources were inspected on 2026-11-21.

## What the existing options actually provide

- [Android PdfDocument](https://developer.android.com/reference/android/graphics/pdf/PdfDocument) already writes mixed-aspect pages directly to a stream. The project's inspected [AOSP implementation](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/libs/hwui/jni/pdf/PdfDocument.cpp) retains finished page recordings through writing; one open page does not mean one page of retained memory. No additional dependency. Keep this for the first measured envelope, rather than replacing working writing and readback to get Kotlin syntax.
- [PdfKmp](https://github.com/ConaMobileDev/PdfKmp) is Apache-2.0 and written in Kotlin. Its [Android driver](https://github.com/ConaMobileDev/PdfKmp/blob/master/pdfkmp/src/androidMain/kotlin/com/conamobile/pdfkmp/render/AndroidPdfDriver.kt) uses the same Android `PdfDocument`; `finish()` also writes to a `ByteArrayOutputStream` and returns bytes. Not a fix for this app's retained page recordings or direct-to-journal end-to-end memory requirement.
- [PdfBox-Android 2.0.27.0](https://github.com/TomRoush/PdfBox-Android/releases/tag/v2.0.27.0) is the leading alternative for larger albums, not selected for product use yet. Apache-2.0 source and mobile-specific port, with the latest tagged release reported by GitHub published in January 2023. The exact tag's [PDDocument constructor](https://github.com/TomRoush/PdfBox-Android/blob/v2.0.27.0/library/src/main/java/com/tom_roush/pdfbox/pdmodel/PDDocument.java) silently falls back to in-memory scratch when initialization fails; never adopt that fallback. A possible spike is an explicit `ScratchFile` + `COSDocument` + `PDDocument(COSDocument)` that refuses on scratch failure, and the [encoded-stream `PDImageXObject` constructor](https://github.com/TomRoush/PdfBox-Android/blob/v2.0.27.0/library/src/main/java/com/tom_roush/pdfbox/pdmodel/graphics/image/PDImageXObject.java) on already verified, metadata-stripped JPEGs. Do not use [`JPEGFactory.createFromStream`](https://github.com/TomRoush/PdfBox-Android/blob/master/library/src/main/java/com/tom_roush/pdfbox/pdmodel/graphics/image/JPEGFactory.java) as a streaming proof; the inspected source reads its argument into a byte array. The [published POM](https://repo.maven.apache.org/maven2/com/tom-roush/pdfbox-android/2.0.27.0/pdfbox-android-2.0.27.0.pom) declares three Bouncy Castle 1.72 transitives; review footprint, version/security and notices before acquisition. A source copy loop and a scratch cap do not bound all Java/native objects.
- [PdfBox-Android-3](https://github.com/ainceborn/PdfBox-Android-3) is a newer fork, but its documented coordinate adds JitPack. Do not add a repository or claim security/Android compatibility from the fork's name. [OpenPDF](https://github.com/LibrePDF/OpenPDF) uses MPL/LGPL and its current line advertises Java 21; Android compatibility of a pinned version and its image-writing path are not established here. [iText](https://github.com/itext/itext-java) offers PDF generation but its AGPL/commercial license is not an approved integration choice.

## Ruling and next evidence

Keep the existing native writer for the first supported profile. Do not write a PDF syntax engine. Retain compact per-page expected raster samples; after the journal's write, close the native document, recycle the retained bitmaps, and release their allowance before starting `PdfRenderer`. Continue reserving a separate current-page readback allowance and evidence lifetime. This reduces simultaneous ownership, not the maximum writer retention before write; no new memory coefficient is claimed as a measured bound.

The Android probe is designed for three mixed-aspect write/readback cycles near the provisional 2,097,152-pixel aggregate ceiling. Reuse the existing approved signer/package and guarded runner for the named LDPlayer instance, but require exact authorization for this worktree and probe. The focused codec test is in the image module's self-target test APK; do not install it alongside the differently targeted app instrumentation under the same test package. Verify the exact input APK and the installed bytes/runner, preserve existing guest data, and stop/release the instance after the test or a readiness failure. No phone, settings change, replacement instance, external provider or recipient is needed.

Record process-lifetime high-water RSS separately from stage RSS, PSS and native heap snapshots, and retain dimensions, file size, elapsed time and reported allocation reservations. Report baseline and later stage samples rather than treating the reservations as physical measurements. The three cycles are diagnostic, not a release qualification. Follow with explicit refusal/cancellation and representative paragraph/stroke detail at reviewed pixel dimensions, not only synthetic color/noise; also measure the integrated frozen-source renderer alongside its real retained state. Only register a profile after matched OS/backend/minimum-device evidence with justified headroom. Keep unsafe-map, JPEG and ZIP regressions and do not silently lower the chosen resolution.

If the native envelope fails to deliver the required multi-page use case, request approval for one isolated read-only acquisition and host/native comparison of the exact PDFBox candidate and pinned transitives, before wiring any new backend. Reuse the existing JPEG, snapshot, journal and independent readback; require that a scratch failure does not fall back to RAM and compare target peak memory, byte growth, text legibility and latency. Do not change the already delivered APK or use a personal phone.

## Boundary review

- The original reviewer identified that the reordered-page witness attempted to verify before a successful write. The corrected witness first writes and independently verifies an ordered control, then reads the separate swapped PDF through the same verification state. This remains a native assertion to execute, not a passed test from compilation.
- Allocate the comparison array before creating its temporary Android bitmap, so there is no intervening allocation outside the bitmap's `finally`. On native document-close failure, refuse readback and drop owners without forcing bitmap recycling while native references could still exist. No such platform close failure or eventual memory reclamation was reproduced; the host test exercises the failed-close contract with a stand-in only.
