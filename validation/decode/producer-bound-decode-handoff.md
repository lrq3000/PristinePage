## Why this boundary

An ordinary render job can reuse normalized-equivalent inputs from a different source than the frozen consumer page. The [admission receipt](../storage/ordinary-admitted-render-proof-handoff.md) retains the exact admitted JOB producer binding; later normalized equality does not authorize replacing that producer. At this base, `OrdinaryFrozenPageRequest.build` constructs and checks an ordinary FAIL/EXPORT request but does not open a file, and `DefaultRenderCoordinator` calls `SourceDecoder.decode(request.sourceId, request.output)`. `FrozenPageRenderer` separately preloads the frozen consumer source, not the actual binding subsequently loaded by that coordinator. An outer preload and a renderer reload are not a producer proof, even when both run under the same dispatcher. A result or provenance record cannot claim producer A if its actual decode consumed B.

The proposed narrow seam is `suspend SourceDecoder.decodeForProducer(sourceId: String, output: OutputSpec, expected: ExportSourceBinding): DecodedSource`. Use the same decode implementation, preflight the opaque ID and destination bounds, and bind the actual loaded SourceId, BlobId, byte SHA-256, byte count and full `SourceInspection` to the admitted producer before `SourceFileDecoder.decodeFile`. Consume the checked load's file and digest, not an `expected` path, an ordinary second lookup, or a normalized-pixel-only substitute. Keep the same post-codec validation, full-source budget, cancellation checks and whole-owner lifetime. A distinct source can be valid if it is the exact admitted producer; frozen consumer equivalence and exact producer consumption are different checks. This is a test proposal, not a change to the shared contract or export wiring.

## Expected RED and later behavior

Nine original JUnit methods are unchanged; the shared fixture uses its existing real `SourceDecoder`/`DecodedSource` with typed calls now that those classes exist. Reflection is retained only for the new suspend entry point (it also accepts Kotlin internal JVM name mangling); resolution is outside the negative expectation, and invocation unwraps target failures. On this base expect **six explicit JUnit assertion failures**, all with `SourceDecoder.decodeForProducer(String, OutputSpec, ExportSourceBinding) is absent`, plus nine expected existing controls. These are predictions, not observed JUnit counts. An absent method must not turn a negative witness green or cause a compile-time missing-symbol failure.

- `producerDecodeChecksAndConsumesOneExactLoadWithoutReopening`: the port would return B on a second lookup. Accept A with exactly one lookup and one codec call, use A's file and digest, retain the full 3×2 raster for a 2×1 destination, and close the borrowed RGB and reservation together.
- `producerDecodeRejectsSameLengthNormalizedEquivalentDifferentBytesBeforeCodec`: A and B are synthetic four-byte files with different independently pinned SHA-256 values and the same IDs, RGB and complete normalized inspection. With A expected and B returned, require nonretryable `INTEGRITY_FAILED` with the requested opaque ID, one load, zero codec calls and zero tracked bytes. Matching B as a separate control must consume it; this does not legitimize same-ID mutation after admission.
- `producerDecodeRejectsIndependentSourceBlobCountAndInspectionDriftBeforeCodec`: ten table vectors cover returned SourceId, BlobId, length, MIME, encoded/normalized extent, swapped encoded extent with unchanged normalized extent, EXIF, profile, conversion and pixel digest. The size/EXIF vectors move coupled fields where required to keep `SourceInspection` well formed. The count-only vector deliberately injects stale recorded count at the port while holding the digest/file fixed; it is a comparison witness, not a claim that `RoomCommittedSources` would issue that inconsistent result.
- `producerDecodePreflightsOpaqueScopeAndDestinationWithoutLookupOrCodec`: malformed/path-shaped request ID, a valid but foreign ID, and an over-limit destination must fail with the typed input/integrity/resource distinctions and no side effects.
- `producerDecodeStillChecksTheActualCodecResultAndClosesItsWholeOwner`: matching loaded binding is not enough to deliver pixels after the codec reports changed inspection; verify one codec invocation and release both the undelivered RGB and permit.
- `producerDecodeCannotBypassSharedFullSourceBudgetForASmallDestination`: run the existing full-source admission through the codec port under a competing reservation, retaining the unrelated reservation unchanged until its holder closes. There is no claim about native memory or platform codec call count beyond the `SourceFileDecoder` seam.

## Data read and integration limits

`CommittedSource` is a projection, not full `SourceRow`/`SourceBlobRow`: it does not carry the ingest transaction ID, row creation timestamps, or a comparable relative path/state. `RoomCommittedSources.load` already raw-bounds both typed reads in one transaction, reconstructs `SourceInspection` and verifies the private original's byte count and hash outside Room, but ordinary `load` does not compare those rows with the receipt. For full immutable-row coverage, add a separate data-owned witness through the **actual bound read** with the existing `CommittedSourceReadTest` real `SourceFiles`/transaction-aware fixture: vary an immutable row-only field while visible projection stays equal, refuse before byte proof for that drift, and retain a positive control for legitimate changes to reference counts under the existing positive-liveness policy. The data owner can reuse its guard/projection/closed-file proof in one lookup rather than performing a guard-only preload and reread. These image tests are agnostic about which internal layer performs that check and do not substitute for it.

Then verify the consuming coordinator actually routes the admitted JOB binding into the bound decode (rather than the frozen consumer source, ordinary unbound decode, or a second lookup) and prevents failure publication/checkpointing. These host witnesses do not exercise actual Room/SQLite, normalized-equivalent real PNGs, native decoder validation, file proof, lease ownership transfer or durable export. They exclude adversarial same-UID filesystem replacement; the existing cooperative immutable root and retained owner still apply. See [T-04 read evidence](t04-source-read-receipt.md), [pipeline contract](../../docs/specs/PIPELINE_CONTRACTS.md) and [export composition boundaries](../export/ordinary-terminal-export-compose-handoff.md) for distinct evidence and gates.
