## Boundary and witnesses

The [admission receipt](../storage/ordinary-admitted-render-proof-handoff.md) retains the exact admitted **JOB** Source/Blob, not the consumer's normalized-equivalent source. `CommittedSource` omits `ingestTransactionId` and both `createdAt` fields; equality of everything the decoder sees is insufficient. Complement the separate producer-bound decoder draft with one data-owned read of the requested source: same-database scalar guard and typed Source/Blob projection in one transaction, exact admitted-row equality except `Source.refCount` and `SourceBlob.sourceCount` (live counters must each be positive), and real `SourceFiles` proof of the checked path/length/hash only after metadata admission and outside the transaction. Do not compare after an ordinary `load`, which would already touch the file, or perform a guard-only preload followed by a second lookup.

- `boundLoadRejectsRowOnlyDriftBeforePrivatePathResolution`: independently change the valid ingest UUID, Blob creation time, or Source creation time in the same catalog. Both ordinary loads succeed and match on all six `CommittedSource` fields, including inspection and the same real original. The admitted binding must nevertheless fail nonretryable `INTEGRITY_FAILED` for the requested opaque source, before even entering private path resolution, without metadata changes.
- `boundLoadAllowsBothPositiveCounterChangesAndReturnsTheVerifiedOriginal`: increment both still-positive counters without changing immutable metadata. Require a successful read, one bounded metadata lookup, real path resolution outside the transaction, the same projection and exact closed bytes, with no read-side writes. These synthetic counter mutations isolate binding policy; they do not test reference accounting.
- `boundLoadRejectsEachNonpositiveLiveCounterBeforePrivatePathResolution`: independently set each live count to `0` or `-1` while leaving the other count and the admitted binding unchanged. A deliberately permissive scalar double exposes the typed positive-liveness check even for a negative count normally refused by the real guard. Expect the same typed refusal before file work.
- `boundLoadStillHashesClosedBytesWhenTheRowsMatch`: make the live and expected rows agree on a different valid-looking SHA-256 while leaving the four closed bytes and their length untouched. The real file path must be reached outside the transaction but the bound load must refuse; returning a file after comparing only the metadata cannot pass.

The existing `CommittedSourceReadTest` fixture still runs the real `RoomCommittedSources` and `SourceFiles` with complete real row types. As in the eight existing cases, the host substitutes for Android Room; both guard and typed queries share one transaction-aware metadata fixture, not a new source port. The root is canonicalized normally; a test-only `File` wrapper observes `toPath()` before forwarding to the real path, before `PrivateStorePaths` can probe it. For the rejection cases the observer count must not change during the bound call, so an identical public error from a later file failure cannot satisfy the ordering oracle. All synthetic files are retained; no file deletion, permission tricks or fake byte verifier.
