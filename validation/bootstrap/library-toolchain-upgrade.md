## Permission regression

Before adding the removals, `:app:checkDebugAarMetadata :app:processDebugMainManifest :app:processReleaseMainManifest` with strict verification and lock refresh succeeded. Structural inspection of both real merged manifests found exactly `READ_EXTERNAL_STORAGE` and `WRITE_EXTERNAL_STORAGE` from the forbidden permission set. Their SHA-256 values before removal were `07189916d12cb84c9ec31eca13aa41f533a9c62e06f78649a6bfba0c05d474c3` (debug) and `657e8b56876a89b7ebfb8106291d1dd03c4e0f2468125b2de7848d479c4027f6` (release). Both already showed API 26/36. The same compiled `ManifestPolicyTest` subsequently failed exactly its two permission assertions against the retained red artifacts and passed all five cases against the rebuilt ones. Earlier dependency-verification refusals are not permission failures. Regression coverage includes the two legacy permissions, all-files and broad image access, network/backup policy, package identity and the runtime SDK limits.

Do not use SimpleStorage's stock folder contract for this app. Its [result handling](https://github.com/anggrayudi/SimpleStorage/blob/b3fce1d2479d57fe738e7bb82cc03ef856cd474f/storage/src/main/java/com/anggrayudi/storage/contract/SimpleStorageResultContracts.kt) can require legacy access before launching on Android 9 or earlier and can trigger cleanup of narrower persisted grants after selecting a broader folder. Use Android's exact tree result and manage persistable modes deliberately; use a narrow SimpleStorage tree-backed resolution after admission. This upgrade does not add the Settings UI, a live selected graph, filesystem durability, deletion authority or any Android runtime evidence.
