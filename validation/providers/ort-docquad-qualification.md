## Observed local inference

The [DocQuad](probe_docquad_cpu.py) and [Paddle UVDoc](probe_uvdoc_cpu.py) probes use the already installed desktop ONNX Runtime 1.26.0 CPU provider with one intra-op and one inter-op thread. They do not fetch files or consume real pages. DocQuad returned zero foreground cells on the black tensor. The broad synthetic marked page had 1,034 foreground cells but a negative weakest peak; its approximate crop should be refused by the minimal decoder. On a narrow marked rectangle, all four peaks were positive and within two heatmap cells of the expected landmarks, and the mask had 1,493 foreground cells. Two synthetic Paddle UVDoc inputs at 128×96 and 89×145 returned finite output, at the respective original shapes, with mean absolute input/output tensor differences of about 0.059 and 0.052. These checks show the downloaded graphs execute and respond to synthetic inputs. They do not validate representative-page corner quality, dewarping quality, exact Paddle color order, Android runtime parity, handset footprint, or saved-output behavior.

A separate Paddle UVDoc constant-plane control `(0.8, 0.4, 0.2)` at 131×97 preserved both 2:1 channel ratios exactly in this run, consistent with one spatial transform shared by the three color planes. This rules out an output channel permutation on that control; it cannot identify the intended semantic input channel order for the learned predictor or qualify the BGR wrapper without an exact reference.

## Core DocQuad adapter

The portable input maps destination pixel centers through the exact floating letterbox, uses clamped bilinear sampling inside the rectangle and black outside it, and normalizes to planar RGB FLOAT32 without intermediate byte rounding. This is not a bitwise port of Android Canvas. The minimal decoder uses labeled channels, a row-major maximum, bounded negative-concavity interpolation or clipped weighted centroid, source-coordinate backprojection through the model's nominal head convention, the existing `QuadValidation`, and mask/logit agreement. It never proposes a full-frame fallback as model success. This code is not connected to capture or the editor.

The detector wrapper borrows a verified asset from the model store, serializes its detector calls, checks a qualified peak estimate against the shared image budget before creating tensors, and checks cancellation before returning any result. The adapter's raw heads are named and typed by the runtime bridge. The [isolated Java CPU bridge](ort-android/OrtDocQuadCpu.java) compiled against `classes.jar` from the exact AAR. It uses one intra-op and one inter-op thread, CPU only, explicitly disables telemetry, opens the ORT-format file from an already verified lease, validates the named metadata and actual tensor extents before copying, and closes options, session, tensor and outputs. Compile-only; none of the Android runtime code or library is a dependency of the app in this increment.

Independent source review identified two Important gaps in the first wrapper: cancellation could lose to an error returned by a blocked runtime, and detached mutable tensors could still alias runtime scratch. Focused host tests reproduced both. The wrapper now checks cancellation before mapping failures and owns bounded snapshots of the exact-sized float heads before an adapter can reuse buffers. The qualification estimate must cover the snapshot copies as well as native buffers and runtime workspace. Broader tied/edge peak behavior, fractional portrait padding and confidence boundary fixtures remain coverage follow-ups.

Post-review strict offline Gradle verification ran `:core:test :test-fixtures:test :data:testDebugUnitTest :image-android:testDebugUnitTest :app:testDebugUnitTest :app:lintDebug` with the existing dependency verification and SDK-download guard. The reports contain 1,474 JVM cases with zero failures, errors, or skips, including all 11 DocQuad cases and both reproduced regressions. Lint reported zero errors and 21 warnings. No APK was assembled or signed, and no Android test was executed.

For the desktop end-to-end geometry witness, pass `--heads-dir` pointing to an empty local directory to `probe_docquad_cpu.py`, then run [DocQuadHostProposal.java](ort-android/DocQuadHostProposal.java) in Java source mode with the current `core/build/classes/kotlin/main`, pinned Kotlin stdlib and `kotlinx-serialization-core-jvm` on the classpath, passing the same directory. The current decoder refused the blank tensor (`LOW_CONFIDENCE`) and broad marked page (`INVALID_GEOMETRY`). It accepted the narrow marked page at score 0.8957, with all four corners within two source pixels on each axis of the synthetic rectangle. This combines real desktop inference with actual Kotlin proposal extraction; it bypasses Android CameraX, input display, and native runner invocation.

## Android reentry

Recover an authenticated copy of the exact Android release provenance and native notices, or qualify a separately scoped source-verifiable Android runtime of the same format family. The next candidate must preserve API 26 and ARM64, no startup network access, CPU-only baseline inference and the untouched classical path. For an app integration, assert the runtime's provider is absent in the actual merged debug/release manifests and separately check the instrumentation variant; leave both Internet permission removals intact and disable native telemetry before creating the first model session. Verify the actual artifact's installed size, load/raw-output parity, one-session budget and process cleanup on the authorized LDPlayer target. Keep custom models, appearance assets, saved learned recipes, and public releases gated until their own requirements pass.
