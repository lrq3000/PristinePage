It was obtained from the [pinned JitPack coordinate](https://jitpack.io/cz/adaptech/tesseract4android/tesseract4android/4.9.0/tesseract4android-4.9.0.aar); the digest identifies the observed bytes, not an independently published signature. The POM lists only `androidx.annotation:annotation:1.3.0` at runtime. There is no Gradle repository or dependency change in this qualification.

All 20 files match the pinned [publisher tree](https://api.github.com/repos/tesseract-ocr/tessdata_fast/git/trees/65727574dfcd264acbb0c3e07860e4e9e9b22185?recursive=1) in both exact length and Git blob SHA-1. Their [SHA-256 values and lengths](tessdata-fast-4.1.0-pins.tsv) were calculated and independently rechecked on the retained files for future app identity checks. The packs sum to 50,008,092 bytes; the AAR plus those packs is 62,856,546 bytes. No extra layout/script model was acquired. The provider bytes and raw request evidence stay outside Git.

The AAR's own text manifest declares `minSdkVersion=21`, no permissions or components. It contains JPEG, Leptonica, PNG and Tesseract libraries for four ABIs. All four ARM64 ELF libraries have 16 KiB-aligned load segments with congruent file and virtual offsets. Their `DT_NEEDED` inventory points to the other packaged libraries or Android system libraries (`libc`, `libdl`, `libm`, `liblog`, `libjnigraphics`, `libz`), with no shared C++ runtime entry. This does not determine static runtime or notice obligations. The exact JVM class exposes `init`, `setPageSegMode`, `setImage(Bitmap)`, `getUTF8Text`, `stop` and `recycle`; this is static inspection, not JNI execution. Inspect the eventual app's merged manifest, APK ZIP alignment and native loading before Android use.

There are no notice files inside the AAR's ZIP. The [wrapper tag tree](https://api.github.com/repos/adaptech-cz/Tesseract4Android/git/trees/15c534717b1cb58261b58d4e4c1200c7f81f668c?recursive=1) contains the vendored Tesseract `LICENSE`, Leptonica `leptonica-license.txt`, IJG JPEG `README` and libpng `LICENSE`. Each exact file was retrieved and checked against that tree. Keep the wrapper and trained-data Apache-2.0 texts as separate source evidence. Matching vendored source licenses is not proof of AAR build reproducibility or final notice closure.

The [synthetic multilingual probe](probe_ocr_language_packs.py) returned nonempty recognition on all 20 single-language samples using the acquired packs with the already installed **desktop Tesseract 5.3.3**, and all 20 matched after NFC, case and whitespace normalization. These high-contrast generated lines do not establish Android 5.5.1 recognition, real-page accuracy, mixed-script bidi fidelity, OCR-to-FTS search, latency or RAM. The nonexact RTL mixed result remains an acceptance case, not a waiver.
