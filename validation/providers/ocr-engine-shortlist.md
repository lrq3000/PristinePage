# Offline OCR engine shortlist

Metadata inspection only, November 2026. No engine or model was acquired for OCR. Package size, language coverage, runtime memory, exact transcription and release rights are independent; vendor metrics on other tasks do not settle these.

- [Bundled ML Kit Text Recognition v2](https://developers.google.com/ml-kit/vision/text-recognition/v2/android) is a size comparator: Google advertises about 4 MB per script per architecture for the bundled option, which avoids relying on a separately downloaded Play-services model. Its [language list](https://developers.google.com/ml-kit/vision/text-recognition/v2/languages) includes English and French under Latin. Google's [terms and privacy](https://developers.google.com/ml-kit/terms) state that ML Kit APIs may contact Google and send metrics. Do not adopt by default unless the exact dependency/configuration can be shown to meet PristinePage's no-network/no-telemetry policy without a Play-services prerequisite. Do not substitute the smaller unbundled package, whose model availability is conditional.
- [Tesseract4Android 4.9.0](https://github.com/adaptech-cz/Tesseract4Android/releases/tag/4.9.0) reports Tesseract 5.5.1; its [pinned README](https://github.com/adaptech-cz/Tesseract4Android/blob/4.9.0/README.md) points to the standard `cz.adaptech.tesseract4android:tesseract4android:4.9.0` JitPack variant and declares API 21+. Qualify the standard variant first; no new repository is enabled by this record. [English](https://api.github.com/repos/tesseract-ocr/tessdata_fast/contents/eng.traineddata?ref=4.1.0) and [French](https://api.github.com/repos/tesseract-ocr/tessdata_fast/contents/fra.traineddata?ref=4.1.0) fast-language files total 5,243,453 bytes at the pinned tag, before native runtime or any optional orientation data. The [data guide](https://tesseract-ocr.github.io/tessdoc/Data-Files.html) distinguishes fast integer LSTM weights from the slower alternatives. Compare as the configurable baseline for sparse text, single block, and different language packs. Review exact AAR, dependencies, ABI/JNI load and all notices before packaging.
- [PP-OCRv5 mobile](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/OCR.html) lists a 4.7 MB detector plus a 7.5 MB English recognizer or 14 MB Latin recognizer, before orientation, runtime and integration costs. Its division into detection and recognition is compatible with a dedicated OCR engine, but published component sizes and desktop timings do not qualify an Android package.
- [LFM3-Omni-2B](https://docs.liquid.ai/lfm/models/lfm3-omni-2b) understands images, but is a generalist with an additional audio/video use case, not a verified literal OCR backend. The closely matched [vision-only LFM3-VL-2B GGUF inventory](https://huggingface.co/api/models/LiquidAI/LFM3-VL-2B-GGUF?blobs=true) already lists 1,099,627,808 bytes for Q4_K_M plus 203,031,872 bytes for its Q8_0 visual projector (about 1.21 GiB together, before runtime). These are exact listed files for that vision variant, not Omni size or measured RAM. Do not default to an image-to-text generator that may silently omit, paraphrase or invent text. Evaluate it separately only if a compact specialist leaves a meaningful quality gap and the actual model/license/runtime is approved.

Qualify Tesseract4Android with fast language data first for the strictly local default. Compare same-page transcription and Home query recall on permission-cleared printed pages, receipts, multi-column and rotated scans, mixed languages, faded text and blank pages. Measure character and word error, missing lines and invented words, plus APK delta, peak memory, energy and end-to-end CPU latency. Bring in bundled Latin ML Kit as a comparison only if its privacy boundary can first be proven; do not silently fall back to a generative engine.

The [synthetic desktop control](probe_ocr_tesseract.py) used the already installed Windows Tesseract 5.3.3 and existing English data. Automatic page segmentation (3), single block (6) and sparse text (11) all returned the nine expected normalized tokens on one generated receipt, at roughly 150 ms per fresh CLI process on this host. No Android performance, scan-quality, or comparative conclusion follows from this positive control.

For a separately approved ML Kit qualification, the documented root is [`com.google.mlkit:text-recognition:16.0.1`](https://dl.google.com/dl/android/maven2/com/google/mlkit/text-recognition/16.0.1/text-recognition-16.0.1.pom). Its POM names `text-recognition-bundled-common:17.0.0`, `common:18.11.0` and Google Play-services library coordinates. Inventory and review their full transitive closure without enabling app networking or a cloud fallback. Maven availability and the word “bundled” do not pass the no-services, no-network, actual manifest or third-party notice checks. Do not acquire weights/binaries or modify dependency pins from this note alone.

**Proposed acquisition scope, not approved:** The [standard 4.9.0 AAR](https://jitpack.io/cz/adaptech/tesseract4android/tesseract4android/4.9.0/tesseract4android-4.9.0.aar) advertised 12,848,454 bytes in a metadata probe. Its [POM](https://jitpack.io/cz/adaptech/tesseract4android/tesseract4android/4.9.0/tesseract4android-4.9.0.pom) names AndroidX annotation 1.3.0; no dependency resolution or version change is implied. With the two pinned English/French `tessdata_fast` files above, that is 18,091,907 advertised binary bytes, excluding metadata and notices. The wrapper identifies its source under the [Apache-2.0 license](https://github.com/adaptech-cz/Tesseract4Android/blob/4.9.0/LICENSE); native dependencies and weight terms require separate checks. If authorized, retrieve only those three binaries and matching provenance/notice metadata into private scratch storage, verify lengths and identities, inspect packaged API/ABI, native contents and notices, and report missing evidence. This retrieval would not include enabling JitPack in Gradle, wiring the runtime, operating a device or publishing anything.

## Multilingual footprint

Metadata measured on 2026-11-22 from the complete [publisher tree for `tessdata_fast` 4.1.0](https://api.github.com/repos/tesseract-ocr/tessdata_fast/git/trees/4.1.0?recursive=1), tree `65727574dfcd264acbb0c3e07860e4e9e9b22185`, and the same JitPack AAR length probe. Proposed 20-language cross-script starter set (Tesseract codes): `eng`, `fra`, `spa`, `deu`, `ita`, `por`, `nld`, `pol`, `tur`, `rus`, `ukr`, `ell`, `ara`, `heb`, `hin`, `chi_sim`, `jpn`, `kor`, `vie`, `ind`.

- Starter models alone: 50,008,092 bytes; with the standard AAR: 62,856,546 bytes; with the AAR and optional orientation/script detection `osd.traineddata`: 73,419,273 bytes (73.42 MB / 70.02 MiB).
- All 119 nonvertical root recognition files: 334,691,048 bytes. With the AAR and `osd`: 358,102,229 bytes (358.10 MB / 341.51 MiB). These filenames include language varieties and historical models; the count is not a claim to support 119 distinct languages or all human languages.
- The 125-file root catalog includes four vertical models (7,903,853 bytes) and two auxiliary files (`osd` 10,562,727; `equ` 2,251,950). Including the AAR: 368,258,032 bytes (368.26 MB / 351.20 MiB). This excludes the separate 37-file `script/` family, whose 344,943,595 bytes largely overlap the language coverage rather than adding 37 independent languages.

These are published artifact bytes, not installed APK delta, RAM or latency. Qualify the 20-language set first and keep wider catalog packs optional and local once installed; do not load all engines/languages into every OCR job. Separate automatic script/language choice, user override and mixed-page tests from pack storage. The earlier two-language qualification proposal is not the multilingual product configuration. No broader acquisition or app networking is authorized by this calculation.
