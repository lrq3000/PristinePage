# OCR release readiness checklist

**Goal:** Decide whether one exact PristinePage build is ready to distribute with standard offline OCR, without turning qualification into an open-ended OCR benchmark. This supplements the [accepted implementation plan](../../docs/specs/IMPLEMENTATION_PLAN.md); it does not replace it, waive the [OCR contract](../../docs/specs/OCR_SEARCH.md), or declare the rest of the scanner ready.

**Approach:** Publish the already verified work as a source-only development checkpoint. For distribution, retain Tesseract 5.5.1, Tesseract4Android 4.9.0 and the same 20 language packs. Prefer a scoped source fix with the installed toolchain over changing recognizers, adding a fallback, or redirecting the whole application's logs. Do not call a rebuilt library identical to the upstream AAR.

## Source checkpoint — separate from release

- [ ] Verify the exact sanitized branch and live `main`; review all outgoing history with the installed public-history guard. Use a classic two-parent merge with the standalone intention and complete incoming commit records, a separate development version commit, and push only `refs/heads/main`. Source publication contains neither private runtime inputs nor APKs. No tag, signing, store upload, or release claim.

## Release gates

- [ ] **Native privacy and notices.** Use the exact upstream wrapper tree at `15c534717b1cb58261b58d4e4c1200c7f81f668c` and its vendored sources, with the installed NDK `28.2.13676358` first. Install no additional toolchain under this scope. Record source hashes, build inputs, linked objects/static archives and required notices, including toolchain runtime material and IJG attribution. Use the [existing native-sink witness](ocr-tesseract-qualification.md#native-diagnostic-admission-remains-open) to reproduce the known missing-pack path and qualify the fix. Check descriptor 2 and Android logs for synthetic path and text markers on normal recognition, rejected input and native initialization failure. Require no marker disclosure, no process-wide production redirection, and scanning usable on a handled refusal. A source license alone does not establish exact redistribution rights; require independent review of the produced inventory.
- [ ] **Exact build, clean install and upgrade.** In the existing strict-offline stage, verify final manifests, signatures as applicable, required ABI/16 KiB alignment, complete pinned asset/native inventory, and no network permissions or private fixture payload. On an exclusively claimed clean LDPlayer guest, prove package absence and radio isolation before first launch; run Files → correct → save → automatic OCR → exact Home page. Run an in-place update separately against a retained synthetic installation with known data and verify saved pages and previous valid results still open; prove background backfill for unqueued pages and stale-revision refusal. Restore radios and verify guest shutdown and release. A new guest needs at least 16 GiB free on the VM volume and 4 GiB live RAM; never erase a retained guest to get a nominally fresh install.
- [ ] **Bounded OCR regressions on the final runtime.** Reuse the [20-scan smoke set](ocr-smoke.md) unchanged: five each in English, French, Japanese and Simplified Chinese, every required anchor and identifier, and at most 15% normalized character edits per page. Because native bytes change, rerun the existing single-language, mixed and blank recognition/search controls once to confirm all advertised languages still work; add no fixtures or stress campaign. Reuse the existing foreground-refusal, capped interruption, explicit rerun and exact-page tests. Cover production local DocumentsUI text Save as with verbatim and zero-byte output and a controlled in-write interruption: require an honest unverified outcome, no automatic replay, and no silent overwrite. No claim that distinct provider URIs cannot alias. If no safe way exists to simulate this boundary without altering a real provider, document verified coverage and keep the remaining provider behavior explicitly unverified.
- [ ] **Bounded real-scan and device qualification.** Use at most five permission-cleared printed examples: an ordinary page, a small-print receipt, a two-column or table page, a faint page, and a mixed-script page. Declare reference keywords and numeric anchors in advance. Require exact-page retrieval for every selected readable anchor and no invented or changed identifiers in the checked lines; record other mistakes and layout limitations rather than tuning to these five pages. On one authorized non-personal representative arm64 handset, run three repetitions of the supported workflow, including scanning/editing while OCR is pending. Record latency, peak process memory, and failures; no app crashes, ANRs, data loss, or material loss of scan responsiveness. Agree the device and any numeric resource thresholds before the run; if access is unavailable, report emulator-qualified development status only. No physical device, private document, or external upload is authorized by this checklist.
- [ ] **Release decision.** Independently review the exact artifact, provenance/notices, acceptance results and remaining findings. Stop ship for a private-data leak, rights gap, wrong-page result or export, silent corruption, uncontrolled retry, ordinary crash/ANR, or unresolved mandatory evidence. Document known nonblocking quality limits. Production signing and distribution are a separate operator action; the rest of PristinePage's release gates still apply.

## Cutoff

One native candidate and at most one correction justified by a specific failed gate; rerun only the affected checks after that correction, plus one final exact-artifact end-to-end pass. Run the fixed synthetic sets once per changed native candidate, at most five held-out pages and three handset repetitions. No additional engine, layout tuning, corpus expansion, multi-hour run, or unrelated scanning/export work. Reassess after each gate and at least every 30 minutes of active work. Stop as **OCR release-ready** once all applicable gates pass, or as **blocked** after the correction limit or when required rights, authority, disk, data, or device access are unavailable. In either case record the exact build, evidence, omissions and next decision.
