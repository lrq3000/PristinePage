# Basic OCR smoke test

This is a small regression check, not an OCR benchmark or a scanning acceptance suite. It contains [20 authored synthetic fixtures and their reference transcriptions](android-ocr-probe-assets/ocr-probe/smoke/references.json): five each in English, French, Japanese and Simplified Chinese. Each language covers clean print, receipt-style print, a tinted page with faded ink, a 1.5° tilt, and mild perspective distortion. The scanned-looking images are original rasterizations of fictional text; they use installed fonts, but no font binaries, photos, customer data or model weights are part of the corpus.

## Run

- The regular provider checks, `python -B -m unittest discover -s validation/providers -p 'test_*.py'`, verify the corpus inventory and images against their references, and check result reporting. They do **not** perform OCR.
- In the existing [private, offline native test build](ocr-tesseract-qualification.md#private-android-probe), run `app.pristinepage.image.LocalTesseractProbeTest#readsTwentyCommittedSyntheticScans`. The existing scoped LDPlayer runner accepts `--smoke`: `python -B validation/providers/run_local_ocr_native_init_sinks.py <released-guest> <installed-app-sha> <previous-test-sha> <smoke-test-sha> --smoke`. The probe reuses the pinned Android Tesseract engine and packs; regular OCR-free app builds do not gain new dependencies, assets or requirements.
- To regenerate a candidate corpus with existing Pillow and fonts, use `python -B validation/providers/generate_ocr_smoke_fixtures.py <installed-font-directory> <new-output-directory>`. Compare to the committed bytes before replacing anything; different font or Pillow versions can change rendering. Running tests does not regenerate the corpus.

The native test requires a fixed single-block layout, an exact word or script phrase, the exact printed four-digit identifier, and at most 15% character edits after lowercasing, NFC normalization and whitespace removal. It completes all 20 pages and emits only case names and metrics. Report exact transcriptions separately from cases that pass the tolerance. This checks recognition by the actual native engine, not automatic scanner correction, the default layout, accessibility, Home search, representative real-world accuracy or phone performance.

## Calibration observation

The initial LDPlayer API 28 run used 3° tilt: 19/20 passed, 17/20 were exact after normalization, and all 20 identifiers were read. The Simplified Chinese tilt missed its script anchor and had 5 edits in 19 reference characters. The archived test APK is `f340751269b36ec914907a60077995fa46d78d88305d37d7061558e388248844`; evidence manifest `888e34eb1b86fb558551e6fb201f8b8cf076d7cc1d30f7f7a569488ec8cd00a6`. This is a measured weakness of that sample, not a scanner defect. Only the angle of the four tilt images was reduced for the basic smoke set; the text, checks, and 16 other images stayed unchanged.

The committed 1.5° set passed **20/20** on LDPlayer API 28 with Tesseract 5.5.1 and the pinned packs. All script anchors and identifiers were detected; 17/20 were exact after normalization. Japanese perspective, Chinese tilt, and Chinese perspective each differed by one character. The development-signed instrument APK `68322c1b0df3966038a47dca373fb5782c24e708ea2bc402a5fa6ec4633f2b8d` matched its installed bytes. Eight evidence anchors were verified against manifest `c4daea5e3a8d256fd4af628590e43218605f6043a89345ed3f12811d86f94eeb`. Both guest processes exited and the claim was released. All 40 host provider checks passed. The application APK was unchanged.
