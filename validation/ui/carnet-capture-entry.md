Attempt `CARNET-CAPTURE-ENTRY-02`, T-05, based on published source `6df7c66`. The reported scan opens with the generic selection/resource warning, no camera image and an unavailable import menu, before any photo is chosen.

Entering the scanner originally tried to create its private draft first. Two terminal drafts with retained ingest journals could exhaust its two-draft allowance even when each retained only one copy. Creation returned `draft_retention_limit`; the view model mapped it to the generic `RESOURCE_LIMIT` message, while the viewfinder and enabled source controls both required an open draft. The baseline JVM regression reproduced that refusal without invoking a camera, picker or decoder. This identifies one source of the reported symptoms, not a readout from the operator's installation.

The candidate keeps the 100 MiB maximum per encoded copy, eight attempts per private draft, and the old 1,600 MiB worst-case charged payload envelope across active and retired Atelier attempts. A single retired attempt no longer occupies half of that shared allowance; opening an empty draft reserves no payload. Saved sources, interrupted copies, existing metadata and preview/decoder limits are not cleared or altered.
