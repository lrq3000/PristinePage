# Carnet scanner usability follow-up

Scope: T-09 Correction preview magnification, T-10 title rendering, U-06 explicit OCR selection and Copy, and separate technical investigations for T-04 Ultra HDR import, the U-06 language catalog, and T-05 burst capture. This is not a replacement implementation plan or a release gate.

## Display and copy

The Correction viewport applies a display-only 1–5× transform with pinch, bounded pan, Zoom in and Fit. Result, geometry input and original use the same viewport; zoom neither renders a new scan nor mutates the recipe. Moving to a new page or closing Correction resets the viewport. Crop-control and outside-tool gallery gestures remain separate. The album title stays tappable to rename, wraps in a square-cornered control and caps the pinned header at five lines, leaving the full text in Rename and in the scrollable Home cards. OCR selection uses the platform's read-only text view with its classifier disabled and no external text-processing actions. Explicit Copy writes only the selected verbatim plain text, with no title or identifiers and Android's sensitive clipboard flag. Save as is unaffected.

## Import diagnosis

The former format preflight returned `UNSUPPORTED_FORMAT/source_color_or_frames_unsupported` for a supported class of Ultra HDR JPEGs. [Android's Ultra HDR specification](https://developer.android.com/media/platform/hdr-image-format) describes the embedded conventional SDR primary. The app uses that primary with a disclosure and keeps and hashes the whole original. Fixtures distinguish supported HDR containers from malformed offsets and arbitrary multi-image JPEGs.

## All OCR languages

The complete [official `tessdata_fast` 4.1.0 tree](https://api.github.com/repos/tesseract-ocr/tessdata_fast/git/trees/65727574dfcd264acbb0c3e07860e4e9e9b22185?recursive=1) contains 124 top-level language traineddata files excluding `osd`: 344,846,851 bytes total, 294,838,759 bytes more than the existing 20. These are raw inputs, not APK growth. In the existing signed build, the 50,008,092 raw language bytes use 26,499,158 bytes of compressed ZIP payload; new packs may compress differently. The 37 combined script models (344,943,595 bytes) and `osd` orientation/script detection model (10,562,727 bytes) are separate from selectable languages. The current recognition mode already uses the [`tessdata_fast` LSTM family](https://tesseract-ocr.github.io/tessdoc/Data-Files.html), not legacy or `tessdata_best` packs.

Publishing all 124 in Settings is not just an asset copy: the original private owner allowed 32 packs/64 MiB and authenticated the whole installed directory for every job. Keep the per-job language count bounded and English/French defaults unchanged. Tesseract can load sublanguages declared by model data, so retain complete directory authentication unless a narrower verified dependency policy is qualified. Check APK growth against 300,000,000 bytes, measure fresh private disk/startup and repeated-run costs, verify no network/permissions changes, and test labels, restart, multilingual selection and representative new-pack native recognition. Pack presence does not establish recognition accuracy.

## Burst feasibility

Recommendation: retain ordinary tap-to-capture. Prototype a long-press and accessible Burst action for a small, bounded set of full-quality stills, reviewed before committing exactly one chosen original. The existing CameraX controller uses `CAPTURE_MODE_MINIMIZE_LATENCY`, one private JPEG handoff per shutter, and separately bounded torch ownership. An initial prototype can reuse serial CameraX still requests with a three-frame cap and torch scoped to the approved burst; do not assume CameraX exposes the cadence of a lower-level Camera2 burst. Recommend the sharpest frame under adequate evidence, keep every candidate available during review, and show framing independently so the user can prefer a slightly softer full page. A burst is a pick-one feature, not optical stabilization, HDR merging, or automatic acceptance.

Start with a softly denoised luminance thumbnail, compare frames at the same document scale, and compute robust tile-level Sobel/Tenengrad energy over textured in-page regions, suppressing weak gradients from noise and limiting the influence of any one tile. Use the existing page-edge detector as an optional coverage signal, not as a prerequisite or truth; if it is unreliable, show every candidate and flag uncertain ranking. Use variance of Laplacian as a cheap control and compare both on clean, defocused, motion-blurred, noisy, clipped and intentionally cropped synthetic series. [Pertuz et al.](https://doi.org/10.1016/j.patcog.2012.11.011) compared gradient and Laplacian families under noise, contrast and window changes; their shape-from-focus results motivate the comparator, not a scanner ranking guarantee. [CameraX zero-shutter lag](https://developer.android.com/media/camera/camerax/take-photo/zsl) picks the frame nearest the tap, not the sharpest, and has device/flash constraints. [Hasinoff et al.](https://research.google/pubs/burst-photography-for-high-dynamic-range-and-low-light-imaging-on-mobile-cameras/) align and merge exposures to reduce noise; that is a different feature and more invasive than selecting an unchanged original.

The decisive first test is whether the suggested still ranks ahead of an ordinary single shutter on legibility while retaining the fuller-frame alternative and never spending unbounded staging bytes. Record capture interval, time to review, peak buffers, missed/cut pages and ranking versus blinded human or exact-text legibility on permitted inputs. Prove cancellation and app-background handling, and recheck hardware cadence on an independently authorized target before claiming low-light improvement. No burst feature or estimator has been shipped.

Host comparison: `python -B validation/ui/compare_burst_sharpness.py` evaluates 12 synthetic calibration pages and 12 separate seeded variations with different defocus, contrast, and noise. The first gradient configuration over-normalized weak contrast and missed six motion-blur pairs. With capped local contrast normalization, median denoised Sobel energy ranked the sharper frame first in **48/48** variant pairs, versus **24/48** for raw Laplacian variance, which ranked the noisier and higher-contrast blur first in the noise and shadow scenarios. A blank page had insufficient texture; a sharp cropped page retained nearly the full page's score. This is synthetic ranking on prealigned pages, not evidence of robust framing or handset capture. The combination of these effects is why burst review must show every frame and why framing is a separate signal.

## Independent boundary review

Initial review identified three input/recognition correctness risks and one packaging gate: regex-based HDR declarations could match comments or miss an HDR-base RDF property; an RGB ICC could be stripped from grayscale PNG; the bundled legacy `equ` file has no LSTM component; and archive member integrity is not a measurement of total APK growth. Review follow-up found the remaining MP Index next-directory pointer check and the need to distinguish an inventory check from an exact-baseline size check. The candidate now parses bounded namespace-aware XMP without DTD/entity resolution, verifies MP entries and terminal index, and validates matching XMP/ISO versions and SDR direction when both signals are present. The profile projection now only accepts RGB-compatible PNG color types. `equ` is retained but disabled in Settings and refused by native-session admission. APK growth uses the retained capture build's pinned digest and counts bytes, not assets alone.

Inspection of the complete publisher inventory found `equ` is the only pack without an LSTM network component. The new Azerbaijani and Uzbek Latin/Cyrillic pairs declare each other as sublanguages; no pack in the original 20 declares an active `tessedit_load_sublangs`. The unchanged Tesseract loader can use those authenticated companions when recognizing the new variants.
