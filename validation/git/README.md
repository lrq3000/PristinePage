# Public clone Git history guard

The public-development clone uses a repository-local GitHub noreply identity and `push.default=nothing`, so publication requires an explicit ref. Review and install [`public-pre-push`](public-pre-push) as `pre-push` and [`check_public_history.py`](check_public_history.py) beside it in the **shared Git hooks directory** (locate it with `git rev-parse --path-format=absolute --git-path hooks`). The hook needs LF line endings and its executable bit on Unix; the helper needs Python 3 on `PATH` (`python` on Windows, `python3` elsewhere). Inspect `core.hooksPath` first and preserve unrelated hooks. A fresh clone does not install hooks automatically.

The hook preserves the raw author/committer email check, local archive/tag/deletion refusals, and the requirement for complete Git history. Its historical identity pins are older than the content pins so that it keeps checking the same identities as before. The content pass walks every commit outside its two exact, pinned public tips, including merge-side commits. It checks commit messages, added or changed paths, and added lines for locally resolvable 7–40 digit hexadecimal commit citations, workstation home paths, unapproved email addresses, and selected private artifact paths. References to a commit already public or going out in the same branch update are allowed; unresolved hex strings can be legitimate digests and are left to review. Neither check prints suspect values. Do not treat an unverified local tracking ref as a new trusted tip or use `--no-verify` to bypass the guard.

From a reviewed checkout of the public clone, use `python -B validation/git/test_public_history.py --shell "<Git for Windows>/bin/bash.exe"` to exercise the tracked hook offline, and `python -B validation/git/verify_public_identity.py --shell "<Git for Windows>/bin/bash.exe"` to verify the installed files and check local `main` without pushing. Omit `--shell` on POSIX. Use the installed checker or a reviewed copy, not a script from the candidate branch, to inspect a proposed tip before integration.

Start future work from verified public `main`, not an earlier local draft. Keep private logs, source documents, APKs and private-ref provenance outside the publication clone. Automated matching does not detect all personal information, secrets, external private links, metadata embedded in opaque files, symbolic refs, or references absent from the local object database. It also does not authorize a push: review all outgoing commits and verify the exact destination and refspec before every push, even if the hook passes.
