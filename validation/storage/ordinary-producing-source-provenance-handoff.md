# feat(storage): bind ordinary render writes to the admitted original

**Disposition:** `U-PRODUCING-SOURCE-PROVENANCE` local candidate for `main`; no integration. Exact checkout base `a695c07541251b30bd281f5251374c73ad55be99` (tree `d245f1ed36874f32168479e1f0d0ae698a3d8f60`), in `.worktrees/pristinepage-producing-source-replay`, branch `work/pristinepage-producing-source-replay`. Independent specification and quality review and exact staged destination verification remain coordinator gates.

**Initial motivation:** A frozen ordinary consumer A may share an existing render job with a retained original B that has the same normalized pixels and conversion but different encoded bytes and dimensions. A's frozen page, recipe revision/canonical recipe, normalized identity and explicit `FAIL`/`EXPORT` output still define the job. The worker must publish B as the actual producer, not silently attribute its result to A or substitute a newly observed equivalent original.

**Final purpose achieved:** Add a data-internal typed path from guarded acquisition through intent, private staged file execution and atomic metadata completion. This is one page writer prerequisite, not export availability.

## What changed and why

- `FrozenRenderAcquisition.acquireForProducer` uses the existing guarded lease transaction. Only its successfully delivered grant creates the private-constructor capability retaining the original `Admitted` object, exact returned `JobLease` and the catalog of that acquisition. Busy, rejected, thrown or undelivered grants cannot be exchanged for a capability by looking up the latest pin. Existing acquisition callers keep their original result shape.
- `prepareForProducer(acquired)` binds v1 intent and attempt to B's Source/Blob/encoded SHA-256, while preserving A's frozen identity and the exact job key/input. `completeForProducer(acquired, intent, result, maxBytes, writer, readback)` requires the frozen request except for the proven producing SourceId B, exact ordinary OK status and raster size, and first `source_decode_v1` version 1/OK with B's encoded input size and the frozen normalized output size. The original v1 execution grammar and cache key derivation are reused.
- Carry the same capability through the existing file executor, retained `COPYING` grant and synchronous MOVED borrow. Within the phase and final metadata transactions, require a bounded exact job row, a single exact JOB pin, the same catalog instance, and the existing raw Source/Blob bounds before typed projection. Recheck all immutable admitted Source/Blob fields and independently positive live counters, allowing changes between positive counter values. Use the existing same-boot fence and short cached liveness lookup. This check runs before and after phase writes and throughout `JobLeaseTransactions.completeGuarded`, including after the SUCCEEDED CAS; a refusal throws inside the transaction. Long file and readback work remains outside Room; per-chunk checkpoints use only the captured lease row, clock, liveness and cancellation. The last observation precedes physical Room commit; SQLite and files do not become atomic together.
- An A-bound legacy journal cannot be adopted by the B producer. The exact-tuple historical writer, the `615`-byte intent, `39309`-byte maximum execution envelope, and terminal reader are unchanged in meaning and format. The reader keeps its independent proof of the historical producer, which need not equal today's JOB pin or the consumer. No job repin, retry scheduler, replacement file protocol or receipt recovery is added.
