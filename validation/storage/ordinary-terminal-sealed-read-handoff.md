## Motivation and boundary

A later assembly consumer needs to verify an already-existing ordinary render checkpoint without gaining recovery, move, or publication authority. [Capture/import/export](../../docs/specs/CAPTURE_IMPORT_EXPORT.md#export-review-and-snapshot) and [storage](../../docs/specs/DATA_MODEL_AND_STORAGE.md#freeze-committed-jobs-and-read-only-outputs) keep verified frozen inputs separate from private export readiness. The [file-execution receipt](export-render-file-execution-integration-receipt.md) and [completion receipt](export-render-completion-integration-receipt.md) describe earlier producer-side evidence, not this read. Accepted implementation plan remains unchanged (SHA-256 `791dba54b888ac430cf12c0a4d83a363a24dd570f5305e989c91815fb9be78fa`).

The only production delta is the additive internal `DerivedFiles.inspectBoundFinal(transactionId, expectedSealSha256: String, target, maxBytes, checkpoint, authenticate, readback): ObservedDerivedSeal?`, with `authenticate: (String, Long, ByteArray) -> Unit` and `readback: (File, ByteArray) -> Unit`. It requires a positive cap and reuses private `inspect(durable = false, requireFinal = true)` in this order: exact non-null seal digest and canonical envelope; exact target and byte cap; caller authentication of encoded digest, count and exact canonical domain/raster metadata via `beforePayloads`; then authenticate the extent and SHA-256 of every present copy. It invokes synchronous read-only semantic readback once on the final only. Each caller callback receives a separate bounded `copyOf()` snapshot, leaving the authenticated original metadata for the observation. The existing inspector re-resolves both payload paths and rechecks their observed presence and, where present, exact extent and digest after readback. No seal rescan, call to `recoverBound`, force, sync, move, file writes, or metadata publication. A genuinely absent seal produces no observation; missing final, failed proof, callback refusal and cancellation cannot produce one. Authentication can run before discovering a valid stage alone; semantic readback cannot. Recovery, existing public APIs and seal encoding are unchanged.

Reuse is narrower than wrapping public `inspectSeal` (which can succeed on stage-only and has no pre-payload binding or post-callback checks) or `recoverBound` (which forces/syncs and returns actionable evidence). This is a file content observation only. The trusted future caller supplies and validates the expected binding and retains cooperative stable store/target ownership across the entire operation outside Room. It must not retain or mutate the borrowed file or metadata during normal consumption; scratch isolation is defensive, not protection against adversarial concurrent file replacement. This does not prove a producer Source/Blob/byte tuple, terminal metadata state, lease/pin/ownership, codec behavior, power-loss durability, assembly readiness, or `PRIVATE_READY`. No metadata-worker files or worktrees are required by the draft.
