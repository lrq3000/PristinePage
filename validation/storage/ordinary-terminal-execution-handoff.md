## How and why these changes were made

The 42-byte tag is ASCII `pristinepage-ordinary-render-execution-v1` followed by NUL. Parse big-endian signed `Int` lengths, counts and dimensions and `Long` recipe revision; reject nonpositive numeric facts except where zero list counts are allowed. The record order is pre-execution key, page UUID, producer Source UUID, producer Blob UUID, producer byte digest, normalized pixel digest, revision, recipe digest, requested dimensions/purpose/fallback, status, actual raster dimensions, stages, result warnings and raster digest. Tokens are 1–128 ASCII bytes from `[A-Za-z0-9_.:-]`; opaque IDs are canonical lowercase UUID strings and digests are lowercase 64-character SHA-256 hex. Compare pre-execution key, page ID, normalized pixel hash, revision, recipe hash and both output sizes against the authenticated expectation; the successful ordinary values are `EXPORT`, `FAIL`, `OK`. The actual size must also match the stored raster size. Check exact EOF and compare the parsed raster digest to the stored digest, full-BLOB SHA-256 to the stored execution digest, and `render-cache-v1:` + SHA-256 of UTF-8 `pristinepage-ordinary-render-cache-v1` + NUL + pre-execution key + execution digest to the stored cache key.

Reject an empty or over-extent BLOB before hashing or parsing. The shared exact maximum is **39,309 bytes**: 2,685 for header/fixed fields, stage count and maximal result-warning list; 16 stages of at most 2,289 bytes each. Each maximum stage is a length-prefixed 128-byte ID, 4-byte version, length-prefixed 17-byte success token, four 4-byte dimensions and a count plus up to 16 warnings of 128 bytes and a 4-byte length each. The reader proves remaining bytes and policy limits before allocating any token or list; the fixed-size cursor borrows stable bytes. It rejects all non-ASCII octets rather than permitting decoding replacements, requires 3–16 stages and 0–16 warnings per list, and requires positive versions and dimensions, one of `OK`/`EXACT_IDENTITY`/`EXACT_PERMUTATION` per stage, normalized source size as first output, contiguous dimensions between stages, and exact raster size as last output. It does not impose a stage-name allowlist, assume version 1 for each stage, derive warning lists, or equate the observed encoded input dimensions with normalized dimensions. The final value contains no raster or provider object; null stage provider reflects the v1 ordinary format, which contains none.

The producing Source ID must not claim another Blob if it equals the frozen page's Source ID, and a matching Blob ID requires the same byte digest. Subject to those immutable aliases, a different Source ID with the authenticated normalized job binding is `NORMALIZED_COMPATIBLE_REUSE`; all three tuple fields matching the frozen page is `EXACT_FROZEN_TUPLE`. Both labels describe comparisons, **neither proves the producer**. The job key deliberately excludes original source row identity; the original JOB pin and the current consumer may both differ from the actual producer. Do not copy either into the parsed tuple. An unkeyed digest and a self-consistent cache key alone do not authenticate which bytes produced a file.
