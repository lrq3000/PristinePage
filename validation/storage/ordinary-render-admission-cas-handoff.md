# feat(storage): add first ordinary render-job admission CAS

**Initial motivation:** The current ordinary freeze producer persists `PENDING` page-render intents. First execution needs a single-winner metadata transition that does not recycle a previous attempt or allow a stale/changed job to advance. This is a bounded P-01/U-05 continuation, `U-RENDER-ADMISSION-CAS`, not a second implementation claim or an export acceptance decision.

**Final purpose achieved:** Added only `internal ExportSnapshotDao.admitPendingRender(jobId: String, idempotenceKey: String, canonicalInputSha256: String, input: ByteArray, updatedAt: Long): Int` to production. The unchanged drafted host SQLite suite now exercises that actual annotation against the existing exported Room v1 DDL. There is no caller, activation or coupling to the terminal export replay.

## Narrow query assumptions

The caller supplies a canonical ASCII UUID, exact v1 pre-execution key (`page-render-v1:` plus 64 lowercase hex characters), the matching 64-character canonical input digest, detached v1 input bytes of the exact nonzero extent rebuilt from one authenticated frozen page, and a typed `Long` Unix audit timestamp. Do not add a payload column, invent a grammar/cap or reuse the assembly input cap. The fixture's small opaque input and literal audit values are not caller validation. The SQL compares exact values using existing binary keys and BLOB equality, rather than normalizing, hashing or parsing stored data. Bound type/extent on the exact row before any typed read or comparison of its body; do not infer a bound from the order of SQL `AND` terms. The same-transaction scalar guard can establish that bound without a wide projection. `updatedAt` is output audit metadata, not a lease deadline or a CAS token.

On a uniquely identified `PAGE_RENDER`, require `PENDING`, matching key/digest/BLOB, raw null snapshot and ordinal, raw INTEGER zero attempt and generation, and raw null lease owner, lease deadline, checkpoint and error. The two `NOT EXISTS` probes are `RenderedPage.jobId = :jobId` and `FileTransaction.kind = 'RENDER' AND FileTransaction.ownerId = :jobId`, with no render-readiness, phase or attempt filter. These are exact canonical owner keys, not scans for malformed aliases. Under the v1 binary TEXT keys, comparison to canonical bound TEXT and the fixed ASCII kind/state literals excludes BLOB or NUL/case aliases without wrapping the indexed columns. SQLite affinity may store a convertible value as an INTEGER; the predicate observes the persisted class and value, not the type of the original insert argument. The host plan witness required a unique job-index lookup, `RenderedPage(jobId)`, and the `(kind,ownerId)` prefix of `FileTransaction(kind,ownerId,attempt)`, with no scan or temporary B-tree.

The single statement writes only `state='ADMITTED'` and `updatedAt`; it returns no row or payload. The actual Room-generated implementation binds positions 1–7 as audit `Long`, job ID `String`, key `String`, digest `String`, input `ByteArray`, job ID `String`, job ID `String`. It runs the write with `performBlocking(__db, false, true)`, steps the statement and returns `getTotalChangedRows(_connection)` as `Int`, closing the statement in `finally`. This inspection plus host SQLite establishes compilation, binding and host mutations, not Android Room execution, lock behavior or a guarantee that the caller ran its guards.

## Separate consuming obligations

- **Immutable JOB pin and same-transaction recheck:** Start with the verified assembly reference and frozen page at the exact ordinal, using `FrozenRenderJobProof` / `RoomFrozenRenderReads` and the existing `renderJobReadIsBounded` exact-length guard before the narrow `renderJobIdentity` projection. Use `boundedRenderJobPinSourceIds` (`LIMIT 2`, including malformed witnesses), require exactly one canonical JOB source ID and the existing raw Source/Blob guard before typed metadata. Prove normalized equivalence and exact immutable linkage without rebinding the JOB pin or assuming its original bytes equal the frozen page's when their identities differ. Recheck the exact admitted job identity and pin/source binding in the same short Room writer transaction as the CAS; stale, malformed or canceled inputs must not advance. Do not perform file/provider I/O or resource work while holding the transaction. If a later step uses a full lease projection, it needs the existing complementary raw lease-field guard too.
- **Resource/capability proof:** Before the CAS and outside Room, reject an incompatible frozen ordinary `FAIL`/`EXPORT` PNG request or obvious nonfit against the shared app budget. Account for retained preview charges and overlapping full-source decode/geometry/appearance ownership. During PNG, account for the retained complete render owner plus the maximum sequential codec phase, without a second full-job reservation on top of those phase permits. Preflight is not a reservation; exercise controlled `RESOURCE_LIMIT` after intervening pressure, cancellation, byte-cap and readback refusal, and verify that the budget returns to baseline and none publishes `READY`. Resource accounting, actual native behavior and exact closed bytes remain separate evidence.
- **Live lease and file authority:** `ADMITTED` is owner-free metadata, not permission to execute. Acquire through the existing lease path with a currently `ALIVE`, scoped same-boot requester and normal generation/attempt fencing before any render-journal or file work. Audit wall time cannot stand in for the monotonic lease clock, and timeout is not positive proof of old-owner termination. Retain the exact lease and stable private ownership through intent, file and completion fences. No app exposure, codec execution, `RenderedPage` publication, `PRIVATE_READY`, or device acceptance follows from this test draft.
