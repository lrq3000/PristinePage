# fix(storage): bound ordinary frozen render job reads

**Initial motivation:** `U-RENDER-READ-20261118` under approved T-04/U closes the gap between verified assembly references and the existing materialized render identity proof. The assembly guard cannot bound a different v1 BLOB, and verifying a full `JobRow` after extraction does not bound what Room has already materialized. Authority: primary `0c028637797cb953a87f1b5d78486754765316b2:docs/specs/TODO.md`. Clean base: `1bd149c673eb5faa6e837678cfbff804847aa71f`, branch `work/pristinepage-export-render-read`, worktree `X:/local-workspace/.worktrees/pristinepage-export-render-read`.

**Final purpose achieved:** Internal suspend `RoomFrozenRenderReads.verify(JobId, ExportPageSnapshot)` authenticates one ordinary frozen page and its expected JobId. The caller pairs a separately authenticated page with the reference at the same ordinal from the already verified assembly and retains the requisite owners. No collection of jobs, metadata payload, runtime handle or authority to execute is returned. The new read is not wired into an exporter.

**What changed and why:**

- Outside Room, reuse the existing ordinary constraints (FAIL, no accepted render or execution, empty masks/assets, equal EXPORT outputs, canonical recipe/hash/revision/source binding, no learned-provider recipe). Rebuild the existing `RenderJobIdentity` once and retain its exact v1 key, digest and canonical bytes. Pass that byte array's size, not a recipe maximum, a scaled estimate, stored declared length, or assembly's 4,144-byte cap. UTF-8 profile strings can change the extent.
- In one synchronous short `RoomMetadataAccess` transaction, `renderJobReadIsBounded` selects by the canonical ASCII JobId and returns nullable CASE 0/1; it imposes positive exact BLOB length, actual SQLite TEXT for all projected TEXT fields, byte and character extents of 36/11/79/64, matching `PAGE_RENDER`, `page-render-v1:` prefix, and raw SQL NULL `snapshotId` and `pageOrdinal`. Kind equality plus the byte length fixes its entire value. `renderJobIdentity` then selects only JobId, kind, key, digest and input. No materialized snapshot/ordinal, lease, state, checkpoint, timestamps, or fake full row. No other `Job` query changed.
- Read the indexed `(ownerType='JOB', ownerId=expectedId)` range with `LIMIT 2` and return only `sourceId` or an empty invalid-present sentinel if its raw class or byte/character extent fails. Never filter corruption away or use `LIMIT 1`. Zero, multiple, or invalid/noncanonical UUID pins refuse before source access. The same transaction calls existing `CatalogDao.sourceReadIsBounded` for the exact pin; it checks the raw Source and joined SourceBlob before either projection. Source ID must equal the pin, and the projected blob key must be a canonical UUID before lookup. No live page, recipe-history, source file, provider or unrelated-owner reads.
- After release, compare the exact expected JobId, kind, key, digest and bytes, then run the existing pinned-source proof: source/blob ID chain, transaction UUID, READY and positive counts, private path and byte metadata, normalized inspection and equivalence to the frozen page. Same SourceId must still reference the same blob; same blob ID must preserve byte hash. A distinct pinned source/blob with equivalent normalized hash/size/conversion remains valid, even with different verified metadata byte identity. The legacy `FrozenRenderJobProof.verify(..., JobRow, ...)` entry keeps its raw row binding, owner/list checks and exact-profile integrity semantics, and uses the same proof. No recipe or input parse is added under Room.

**Failure and historical capability contract:** Missing exact JobId is nonretryable `SOURCE_UNAVAILABLE/frozen_render_job_unavailable`. Present failed guard, missing admitted projection, malformed/multiple pin, or missing/unbounded pinned source/blob is nonretryable `INTEGRITY_FAILED/frozen_render_job_metadata_invalid`; semantic identity failures use `INTEGRITY_FAILED/frozen_render_job_invalid`. Unexpected metadata exceptions are retryable `STORAGE_FAILED/frozen_render_job_read_failed`, without private exception detail, and cancellation propagates. For the supported distinction, a different renderer version and/or provider descriptor must describe a canonical **ordinary v1** profile: it is parsed only on mismatch, its version fields pass `OrdinaryExportProfile`'s normal token checks, and its descriptor must exactly re-encode under the existing empty-provider encoder. Then rebuild against the retained profile and check the entire job/pin binding before returning nonretryable `PROVIDER_UNAVAILABLE/frozen_render_profile_unavailable`. Invalid UTF-8/JSON, noncanonical descriptors, unknown forms and unsupported nonordinary profiles are not evidence of a historical runtime; nor can a historical profile hide a corrupt or missing binding. The retained profile is identity input only; no runtime is resolved, substituted or run, no metadata is rewritten, and decoder capability/durable assets, nonordinary profiles and historical grammars outside this v1 proof remain separate gates.
