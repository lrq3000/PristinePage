## Intent and implementation

Admission and acquisition are separate transactions. Admission has already authenticated the frozen request and JOB pin and checked resources outside Room, but an old verified reference does not guarantee that this metadata is still current. Unconditionally using the shared lease DAO would first materialize `SELECT *`, including the potentially malformed input and lease/checkpoint fields. The new internal route checks the bounded immutable identity and the current JOB pin before it allows that projection, then uses the existing lease protocol instead of creating another one.

- Input to `RoomJobLeases.FrozenRenderAcquisition.acquire(proof, owner, durationMillis)` is a current-profile `RoomFrozenRenderReads.Verified` for the matching verified assembly ordinal and frozen page, plus the caller's scoped owner and the existing lease duration in elapsed milliseconds. The caller retains the original snapshot/job ownership and performs concrete resource/capability admission separately. The production constructor binds the projection, catalog, lease DAO and `RoomMetadataAccess` to the same `PristineDatabase`.
- In the shared writer transaction, call `renderJobReadIsBounded` with the exact canonical extent, then read only the narrow job identity and exactly one bounded JOB source ID. Use the existing Source/Blob scalar guard and bounded projection; check exact v1 key/digest/input bytes, live READY source binding and exact recorded pin ID and immutable Source/Blob metadata. A stable byte-distinct, normalized-equivalent original is accepted without rebinding; a replacement pin or same-ID immutable metadata drift is not. Compare the two positive counters for validity, not equality. No hashing, re-encoding, capability callback or file IO takes place in the writer.
- Require `renderJobLeaseReadIsBounded` before `JobLeaseDao.job`. Compare the full row to the same proof, including kind, exact ID and raw-guarded null snapshot/ordinal. The specialized projection never falls back to an unchecked read on refusal. Missing, malformed and canonical mismatch use the established frozen-reader diagnostics; immutable pinned-binding drift is nonretryable `INTEGRITY_FAILED/frozen_render_lease_binding_changed` scoped to the JobId. Infrastructure errors retain retryable `STORAGE_FAILED/job_lease_write_failed`.
- The shared writer still validates requesting owner and duration, requires requester `ALIVE`, admits the original scheduling states, advances generation and attempt with checked arithmetic, uses independent elapsed and Unix clocks, and relies on the existing generation CAS. Same-owner duplicate is busy; expired takeover still requires a distinct live requester and positively ended old owner. Cancellation propagates; the new route rechecks it after the last audit-clock sample before update. This is not a guarantee against cancellation racing an already-started write/commit. The public generic acquisition, ingest, checkpoint and completion constructors, callers and diagnostics stay unchanged. Only an existing `AcquireLeaseResult`/`JobLease` or normal busy/rejection is returned; the route neither admits nor repins jobs, reserves resources, opens files or marks export READY.
