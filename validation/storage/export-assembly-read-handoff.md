**How and why the changes were done this way:** Use `SELECT CASE WHEN … THEN 1 ELSE 0 END FROM Job WHERE jobId=:jobId`, not a filter on validity. PK equality to an already validated canonical ASCII UUID with binary collation binds `jobId` without making malformed job keys obtainable from the typed port. Bound `input` to actual SQLite BLOB and inclusive 184–4,144 bytes. This is the outer envelope of the unchanged 32-byte tagged header plus length-prefixed snapshot UUID and hash, 4-byte count and fixed 40-byte references: `144 + 40*n`, `1 ≤ n ≤ 100`. Other projected fields require actual SQLite TEXT and exact raw-byte lengths (`kind` 15, `idempotenceKey` 55, `canonicalInputSha256` 64, `snapshotId` 36), and matching `length(TEXT)` to reject a NUL even inside an otherwise legal byte extent. Guard raw `pageOrdinal IS NULL` and omit it from the projection; the SQL never converts a stored ordinal to an Int. Projection columns are exactly `jobId, kind, idempotenceKey, canonicalInputSha256, snapshotId, input`; no lifecycle, checkpoint, attempts, lease, error or timestamps. The guard is not a second implementation of the v1 parser: the existing verifier authenticates kind/key/IDs, digest, fixed lengths/tag/count/extent, snapshot hash and distinct ordered canonical JobIds from one bounded byte copy. This preserves healthy persisted bytes while leaving semantic binding to one implementation.

**Failure contract:** No scalar row maps to nonretryable `SOURCE_UNAVAILABLE/export_assembly_job_unavailable`; a false scalar or missing projection after admission maps to nonretryable `INTEGRITY_FAILED/export_assembly_job_metadata_invalid`; a false identity/wire binding maps to existing `INTEGRITY_FAILED/export_assembly_input_invalid`. All use the requested JobId as the affected ID. Metadata exceptions become retryable `STORAGE_FAILED/export_assembly_job_read_failed` without raw messages; `RepositoryFailure` and coroutine cancellation propagate. Cancellation checks bracket the lookup and verification, with an additional check after admission before projection. Ordinary database row absence is distinct from corruption; a guard-positive but absent projection is not silently labeled missing.
