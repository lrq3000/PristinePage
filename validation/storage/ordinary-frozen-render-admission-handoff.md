## Fixture and authority boundary

The fixture freezes one 3×2 ordinary PNG `FAIL`/`EXPORT` page via the actual `RoomExportSnapshots` over `RepositoryFixture` / `MemoryMetadata`. It pairs the `ExportAssemblyInput.verify` reference at the page's frozen ordinal with that page and uses the real persisted `PENDING` job bytes, key, digest, Source/Blob rows and `SourceReference`. This is real canonical identity generation with fake Room and source-file/preflight ports, not a real encoded file, database, codec or allocator. No hand-authored job encoding or mock of production authentication substitutes for the consumer.

The proposed data-owned consumer is internal: `suspend fun admit(jobId: JobId, page: ExportPageSnapshot): Boolean`. For the test adapter, the injected mandatory gate is a suspend function `(RoomFrozenRenderReads.Verified, ExportSourceBinding) -> OperationError?`: `null` is success from the explicitly supplied port; an error is preserved as `RepositoryFailure`, not a CAS miss. The frozen ordinal pairing and confirmation of PNG settings are caller obligations; the page alone is not an export-format assertion. Production later supplies concrete external ordinary PNG capability and resource checks, not a default success, a second scheduler/renderer/budget, or a reservation that double-charges existing phases.

Prepare `RoomFrozenRenderReads.Verified.Prepared` outside Room and use its existing `Projection` in each transaction; preserve the detached input and exact original JOB pin/source/blob proof from the first transaction. The second transaction repeats the raw extent and typed proof plus bounded pin/source recheck, compares immutable binding fields rather than mutable counters, and checks cancellation before invoking the single `admitPendingRender` with the exact canonical values. The fake counts CAS calls separately from affected rows and snapshots stored BLOB bytes and binding maps independently: a zero count cannot satisfy a no-call assertion. The update must only change state and audit time; `0` returns `false`, `1` returns `true`, and an impossible count fails inside the transaction so provisional effects roll back. No full Job projection, live page/recipe lookup, pin replacement, lease or publishing capability belongs in admission.
