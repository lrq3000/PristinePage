## Alternatives and official compatibility evidence

- **A — AGP8.10.1/KGP2.2.10/Gradle8.12.1:** [AGP8.10 notes](https://developer.android.com/build/releases/agp-8-10-0-release-notes), “Compatibility”: maximum API36; minimum Gradle8.11.1, Build Tools35.0.0, JDK17. Thus the supplied installed Gradle8.12.1 is usable at that layer. However, [JetBrains’ KGP table](https://kotlinlang.org/docs/gradle-configure-project.html) lists KGP2.2.0–2.2.10 fully supported with Gradle7.6.3–8.14 and AGP7.3.1–8.10.0: the exact 8.10.1 patch is not explicitly covered. This alone does not prove incompatibility. More materially, current KSP requires AGP8.12+, forcing older processing pins. A saves one Gradle distribution but adds compatibility maintenance.
- **B:** [AGP8.13 notes](https://developer.android.com/build/releases/agp-8-13-0-release-notes), “Android Gradle plugin 8.13.2”: “uses R8 8.13.19 which supports Kotlin 2.3.” “Compatibility” lists maximum API36.1, Gradle8.13 minimum/default, Build Tools35.0.0 and JDK17. The [JetBrains table](https://kotlinlang.org/docs/gradle-configure-project.html) lists KGP2.3.20–2.3.21 with Gradle7.6.3–9.3.0 and AGP8.2.2–9.0.0. B satisfies both documents without an R8 override.
- **JBR reuse:** [Gradle8.13 Java compatibility](https://docs.gradle.org/8.13/userguide/compatibility.html), Java21 row: toolchains since8.4, running Gradle since8.5. [Android JDK guidance](https://developer.android.com/build/jdks) says to choose a JDK “higher than or equal to” plugin requirements and distinguishes build JVM, compilation toolchain and bytecode targets. Existing Java21 therefore avoids another JDK acquisition; API26 availability of individual Java APIs still requires review/desugaring where applicable.
- **AGP9 is a credible alternative, not inherently unsuitable:** [AGP9.0 notes](https://developer.android.com/build/releases/agp-9-0-0-release-notes) document built-in Kotlin enabled by default, KGP2.2.10 runtime dependency, Gradle9.1.0 minimum and Build Tools36.0.0. [Migration guidance](https://developer.android.com/build/migrate-to-built-in-kotlin) removes `org.jetbrains.kotlin.android`, changes Kotlin DSL configuration and makes ordinary kapt incompatible. A greenfield project has no existing scripts to migrate, so this is integration complexity, not inevitable migration work. [AGP9.3 notes](https://developer.android.com/build/releases/agp-9-3-0-release-notes) support API37, require Gradle9.5.0, and document later 9.3.3 Windows/R8 fixes. Installed Gradle9.6.0 could reduce acquisition, but JetBrains’ current KGP2.4.21 table ends at AGP9.3.1, not9.3.3. Prefer B’s clearer documented intersection for API36; reconsider AGP9 if selected libraries require API37. This trades a future AGP9 transition for lower initial configuration uncertainty.

## Compose and Kotlin metadata

[Compose compiler setup](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler) explicitly says plugin version “matches your Kotlin version”; use `org.jetbrains.kotlin.plugin.compose:2.3.21`, not an independently chosen old compiler extension. The [BOM explanation](https://developer.android.com/develop/ui/compose/bom) says the compiler is not included in the BOM.

**Important current constraint:** compiler setup also states “starting with Compose 1.12.0” projects require `compileSdk 37` and AGP9. Therefore do not copy its latest BOM example into B. Coordinator must select a stable pre-1.12 BOM/library set and inspect its resolved metadata. [Compose Runtime notes](https://developer.android.com/jetpack/androidx/releases/compose-runtime) say projects released with Kotlin2.0 require KGP2.0.0 or newer. Both candidates clear that floor; it does not establish compatibility with arbitrary newer Kotlin2.4-built dependencies. Exact BOM mapping was not verified: the retrieved mapping table exposed empty version cells. Library/AAR metadata remains a bill-and-build gate.

## Room/KSP strategy

[Room release/setup guidance](https://developer.android.com/jetpack/androidx/releases/room) directs Kotlin projects to `ksp("androidx.room:room-compiler:...")`; its Kotlin2.0/KSP2 passage recommends KSP2 for Kotlin2.0+. Room2.8’s documented minSdk23 and Room-plugin minimum AGP8.4 fit the proposed baseline. Coordinator retains the Room artifact/version decision and committed schema-export configuration.

[KSP2.3.0 release](https://github.com/google/ksp/releases/tag/2.3.0): “KSP version is no longer tied to the Kotlin compiler version.” Do not invent a `2.3.21-...` matching prefix. [KSP2.3.12](https://github.com/google/ksp/releases/tag/2.3.12) raises minimum AGP to8.12.0; [2.3.14](https://github.com/google/ksp/releases/tag/2.3.14) fixes disappearing library symbols during concurrent executions. Its [tagged build](https://raw.githubusercontent.com/google/ksp/2.3.14/build.gradle.kts) sets Kotlin language/API2.3; [tagged properties](https://raw.githubusercontent.com/google/ksp/2.3.14/gradle.properties) use Kotlin base2.3.20. Recommend2.3.14 provisionally, then verify actual Room generation, schema export and incremental rebuilds. No kapt fallback is justified absent a reproduced KSP failure; do not activate both processors.

## API implications and remaining gates

[Target36 behavior changes](https://developer.android.com/about/versions/16/behavior-changes-16) remove edge-to-edge opt-out on Android16, enable predictive-back changes and relax large-screen orientation/resizability restrictions. [Android16 all-app changes](https://developer.android.com/about/versions/16/behavior-changes-all) impose job quotas affecting WorkManager independently of target. Preserve adaptive/inset handling and checkpointed export scheduling.

[16KB guidance](https://developer.android.com/guide/practices/page-sizes) requires compatible native dependencies and identifies AGP8.5.1+/NDKr28+ packaging/build defaults. AGP alone does not validate OpenCV/SQLite/runtime ELF alignment or ABI coverage. Do not acquire an NDK for a capability-free bootstrap unless native compilation actually requires it.
