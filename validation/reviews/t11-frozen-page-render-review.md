### Actual source proof, TOCTOU and runtime identity limitations

Source-supported, conditional on production wiring: the new bridge compares source ID, blob ID, byte hash, normalized size/pixel hash and conversion against the frozen values. The real RoomCommittedSources implementation performs bounded metadata reads and closed-byte/path/length/hash proof outside Room, while SourceDecoder subsequently loads the committed source and verifies complete decoded inspection and byte identity. DefaultRenderCoordinator independently compares the decoded normalized binding to the request recipe before geometry. Thus the production mechanisms do more than the new tests' value-returning source/render doubles; those doubles alone prove no actual file, pixel conversion or Room behavior.

Important limitation, not an additional defect finding under the stated contracts: the bridge's initial CommittedSources check and the renderer's later decode are separate reads. The RenderRequest contains normalized identity, not the frozen blob/byte hash, and the supplied generic RenderCoordinator is trusted to implement its contract. Exact encoded-source continuity therefore depends on immutable SourceId→blob/inspection bindings, stable cooperative private roots, the correct shared source/renderer wiring and caller-held source owners. SourceFiles explicitly excludes malicious same-UID concurrent replacement. The new API is not an atomic open-handle proof, a defense against source rebinding, or a GC lease. If a future feature permits source rebinding/compaction or changes those trust assumptions, frozen encoded identity must reach the actual decode proof before claiming the stronger guarantee; an extra metadata check alone would not close an adversarial race.

Likewise, matching the caller-supplied renderer/backend/precision/encoding strings and descriptor is a compatibility check, not measurement that a particular runtime or future encoder executed. No execution/file hash is committed by this class. Shared coordinator/classical execution and eventual codec/provider evidence remain independently required; an arbitrary injected OK port cannot establish them.

### Ownership, cancellation, errors and resource accounting

Source-supported: only an exact request and actual-sized OK raster is returned. DEGRADED, explicit failed statuses, request drift and wrong dimensions cause typed refusals. RenderResult's own constructor requires pixels only for OK/DEGRADED, and the bridge probes the raster for already-closed storage. It retains the complete result until successful dispatcher delivery; rejection/cancellation disposes the whole undelivered owner, not just the image. RenderResult closes RGB and then its accounting owner idempotently. Disposal Exceptions cannot replace an initiating safe refusal/cancellation; delivered owners retain their ordinary caller-observed close behavior. The wrapper neither resizes returned output nor automatically accepts preview/degraded pixels. Caller snapshot/job pins remain caller-owned through result close.

Source-supported: coroutine CancellationException propagates; an explicitly typed CANCELED result remains a refusal. Typed source failures are preserved, unexpected source-load Exceptions map to safe STORAGE_FAILED, allocation failure maps to RESOURCE_LIMIT, and other unexpected processing Exceptions map to a safe processing key without raw paths/messages. Existing explicit render status distinctions are preserved as far as RenderStatus permits; DEGRADED is not relabeled OK. The two retained error REDs correctly target raw cleanup masking and source IO misclassification, rather than claiming a native failure. Malformed/future canonical recipe decoding shares RecipeCodec's combined invalid/unsupported exception vocabulary; valid production snapshots have already passed the data identity loader. No mutation/repair of unsupported data was found, and no broader error-vocabulary redesign is requested here.

The helper allocates bounded metadata, not image buffers; it intentionally grants no allocation permit. The actual coordinator retains the full decoder owner through geometry/appearance and transfers the independent final raster owner. GeometryEngine's shared budget reserves output/copy/proof scratch before pixel allocation. This scoped inspection did not re-audit the numerical pipeline or certify complete peak estimates/PSS. Repeating source proof is bounded O(encoded bytes), while sizing is constant work and recipe/profile checks are bounded metadata work. Neither this review nor the 12MP size policy is evidence that a given source/output graph or whole PDF fits memory.
