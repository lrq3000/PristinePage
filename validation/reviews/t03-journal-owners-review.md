## I-1 — Important — wall-clock changes invalidate elapsed lease semantics

**Evidence status: true by static dataflow; not runtime-reproduced in this review.** `data/src/main/kotlin/app/pristinepage/data/repository/JobLeaseTransactions.kt:11-22,35-37` defaults to `System::currentTimeMillis` and uses that value both to admit/fence a deadline and to write `updatedAt`. Acquisition supplies the same wall-derived deadline at `data/src/main/kotlin/app/pristinepage/data/repository/RoomJobLeases.kt:12,24,35-39`; its delegated completion therefore retains the problem. This conflation predates this increment in RoomJobLeases, but is now also the default of the new joint-completion API. `docs/specs/DATA_MODEL_AND_STORAGE.md:25` explicitly separates Unix audit timestamps from monotonic runtime deadlines.

**Counterexamples:** acquire at wall1000 for100ms, producing leaseUntil1100. After150ms of actual elapsed time, a backward date adjustment leaves wall1050: both completion fences accept and commit domain rows plus SUCCEEDED despite the elapsed deadline having expired. Conversely, a forward adjustment to wall1200 after only10ms rejects an otherwise live, timely attempt; a jump during the callback rolls back already-written domain metadata. No owner/generation/state change is needed. This causes unexpected import/render completion failures or acceptance beyond the promised runtime deadline. It does not, by itself, defeat the separate ALIVE/UNKNOWN takeover guard; concurrent file replacement is not asserted.

**Minimal remedy:** distinguish a shared monotonic lease clock from the Unix audit clock in acquisition, checkpoint and joint/standalone completion, including native construction. Use the former consistently for same-owner runtime expiration and the latter for `updatedAt`. Merely injecting a monotonic replacement into the current single-clock API also makes audit timestamps non-Unix. Keep restart/boot ownership interpretation conservative and separate; do not turn a monotonic value or wall timeout into process-death proof, or add OS inspection under the metadata lock. Add independent-clock regressions for forward/backward wall jumps, real elapsed expiry and Unix audit values before claiming this corrected.
